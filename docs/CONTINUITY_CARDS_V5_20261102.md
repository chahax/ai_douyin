## 实际实现

入口 `scripts/run_continuity_cards_v5.py`，复用现有 v3 完整剧本生成、DeepSeek 独立审查、MiniMax 核验及最多两次局部补丁。没有修改网页默认入口或发起媒体生成。

每章流程：完整原文前缀 → MiniMax 提议共享卡增量 → 独立请求核验（必要时仅一次修订）→ 完整剧本 Agent → 从最终修订稿抽取结束状态 → 独立请求核验 → 绑定候选校验值后交接下一章。

共享资料分两类稳定卡及一份动态交接：

- fact：有原文段号的身份、关系、年龄等；未知年龄不指定数字，原文外观估计不升级成确定年龄。
- design：普通场景布局、造型等制作选择，明确不等于小说事实。同一语义键持续继承；改值必须有原文依据，不能把 design 原地提升为 fact。
- previous_handoff：上一章最终候选的时间、地点、在场人物、持物、未完动作，附候选原句与完整稿校验值。后续修改候选会使旧交接失效。

作者、DeepSeek 整稿审、核验、补丁和补丁复核都获得相同冻结版本。DeepSeek 不接收先前审查意见，接收共享设定用于跨章核对。语义合理性仍依赖模型与助手审查，引用存在不代表语义一定正确。

第一章新建卡；后续只提交增量，完整旧卡不由模型重写。所有卡版本及结束状态独立保存，不改历史记录。整章仍有备注时，可以单独核验结尾状态用于本次连续性评估，但不冒充整章自动验收通过。

## 范围与限制

本轮只跑第1—3章，保留完整1..当前章原文。没有实施69章人物事实预扫描或更长篇章的自动截窗；全书反向纠错传播未实现。已使用过的旧交接失效后会停止，不自动重写所有后续章节。

人物/房间同义键是否重复、时间是否语义倒退，仍由核验处理；程序保护校验值、分类、来源、版本与有限修订，不声称用规则完全理解小说。
