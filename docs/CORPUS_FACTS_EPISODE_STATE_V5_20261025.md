# 章节事实与本集状态快照 v5

## 本次实现范围

用户同意先优化“章节事实与变化”和“本集状态快照”。新增独立 v5 模块与任务路线，既有 v3/v4 冻结任务仍沿自己的版本执行。此次不改变账号浏览器、后台服务或媒体生成流程。

完整作者章节仍是阅读单元，完整相邻章只供上下文。原文逐字保留，自然段只是证据地址。章节候选不再只有四类标签，而是包含实体称呼、事实、事件时间、叙事位置和明确状态变化。

## 数据和模型职责

1. Qwen 从完整原章提取事实候选，绑定原段原句；程序计算位置和 SHA。
2. MiniMax 逐章核对事实及每段覆盖，同时检查缺漏、实体类型、时态及状态变化。来源绑定通过不等于语义正确。
3. MiniMax 建立全书框架与本集选择，前序来源审核保留。
4. 本集快照声明跨章实体对应、开场与结束状态、场景、在场人物、进入/离开/移动/转交/获知等动作，以及每场信息目的和对白目标。
5. MiniMax 设计、编剧读取本集快照、实际使用的事实、完整本集及必要的较早证据章。未来章节和全书主线不继续传入编剧上下文。
6. 程序检查来源绑定、显式状态链和时长格式；Qwen 核对前序语义，DeepSeek 仍只负责最终内容和表演计时审核。

`actual / memory / plan / belief / hypothetical / quoted_story / uncertain` 与 `chapter_present / earlier / later / timeless / unspecified` 分开记录。原文“想起去年”不能因叙述发生在本章而成为当前动作；计划和猜测也不能直接应用为当前状态。

美术补充单独标注。布光、陈设、站位和表演可以有明确创作补充；人物关系、知情和道具归属不能靠补充说明编造。程序仍无法仅凭引文存在证明其含义，跨章人物合并、过去状态是否持续、最终表演是否实现状态都需要语义审核。

## 接线与返修

- `scripts/run_corpus_production.py` 新 prepare 使用 v5，已有 PLAN 按版本派发。
- `scripts/run_fanqie_corpus_workflow.py` 新 JOB 固定 v5；已有 v3/v4 JOB 未生成文本计划时也保持原准备路线，无路线字段的旧 JOB 保留旧流程。
- 责任阶段新增 snapshot，材料、框架或快照变化后使相应下游失效；完整稿更新后重做最终双审。
- 剧本中的场景及状态引用与快照绑定，字段绑定不冒充自然文本已正确表现动作。
- 保留原文、原生输出、失败和请求账本；未知调用不会因新版本而重新派发。

本轮尚未实现跨任务共享资产缓存或按单个事实精细失效；现阶段仍按责任阶段重建。也没有以增加状态检查宣称调用数已经减少。

## 执行范围保护

新任务在 prepare 时固定本机提取实现摘要，执行时核对，避免部分章节使用不同版本。云阶段要求独立、绑定本次来源/章节/提供方的明确授权记录，不从开发任务的普通说明推断外发批准；旧拒绝记录沿已有历史链保留并检查。该保护不读取或输出密钥，不触发模型或账号业务。

`corpus_scope_v5.record_cloud_authorization` 供已有调用方在收到明确用户批准后登记；本轮没有为真实试跑登记云授权。
