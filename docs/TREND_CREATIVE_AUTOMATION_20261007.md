# 热度标签驱动原创作品与运营流程

本轮需求：继续使用获取的视频热度标签选择方向，再由新创作流程形成完整作品，并与用户沟通核对内容。适合本项目的方式是**人工把关的运营自动化**：系统准备、执行和追踪重复步骤，用户确认内容取舍和实际视频。

热度提供选题依据，参考片与表达标准指导叙事，完整作品的表现再回到运营评估。标签只决定值得讨论的受众问题；人物关系、阻力、选择与结尾应由完整简报明确，不能用几个热词替代剧本。

## 流程与分工

| 阶段 | 主要输入与产物 | 执行/核对 |
| --- | --- | --- |
| 1. 获取与分析 | 原采集批次、去重视频、明确指标、原话题、采集关键词及账号策略 | 沿用既有采集授权和样本门槛；单批样本不声称全站排名或增长 |
| 2. 形成选题 | 既有 ContentOpportunity、标签来源、账号定位、时效与风险 | 保留来源和相关度证据，过期/错账号停在阅读核对 |
| 3. 提出故事简报 | 主题、受众、人物关系、观众感受、画风、转折、结尾，以及压力、选择、后果和释放 | MiniMax 提案；说明标签如何兑现及账号格式匹配，由用户确认完整方向 |
| 4. 创作完整剧本 | 已确认完整简报、人物、R01参考全文、适用表达标准 | MiniMax 提交完整新稿；DeepSeek 少量必要全文复审。用户确认正文变化；不手填补丁、不拼接旧稿 |
| 5. 整片导演 | 本次确认的完整正文、参考、表达标准 | 安排信息揭示、观察对象、切镜理由和情绪重心，不在编剧阶段塞坐标与道具微操作 |
| 6. 局部表演与编译 | 导演意图、源对白、刺激反应、资产起态 | 局部表演安排实际窗口；确定性编译查跨拍状态与排时，不代写剧情 |
| 7. 制作交接 | 完整剧本、导演、实际表演、编译、资产与服务请求 | 用户核对制作安排与图片；关键互动保持在合适生成段内。时长随必要表演浮动 |
| 8. 视频与人审 | 明确授权的当前段请求与参考 | 成功保存后 awaiting_human_review；用户批准服务原始尾帧才按原规则续段。助手不抽帧、听看或ASR |
| 9. 发布及反馈 | 用户认可的完整片、绑定账号、符合正文的发布标签 | 独立核对发布授权、主动AI声明和虚构声明；浏览器发布及核验。实际作品指标回接选题与版本 |

内容核对集中在选题/简报、完整正文及制作交接、实际视频。正文返修后按源哈希让受影响的导演、表演与交接失效；保留历史与实际消耗。已授权工作继续，不因内容核对重复申请权限。实际工作期间每30分钟报告内容取舍、产物、下一步和未解决问题。

## 三类标签与两个判断

- **视频原话题**：来自采集记录 hashtags，有对应样本。也不能自动证明这个话题本身导致视频热门。
- **采集关键词**：搜索输入或主要分类，说明采样范围；不冒充视频原话题。
- **推断主题**：既有机会服务提出的 topic_labels，说明潜在故事方向；保留“提案”身份。

先判断选题是否与账号定位、受众和可用格式相符，再判断故事中是否真正兑现所选主题。发布标签在完整作品后按实际内容整理，不能直接复制全部采集热词。账号相关度和关键词匹配只作为筛选证据，最终内容匹配仍须核对。

**范围已确认（2026-10-07）**：用户明确“直接就法律，这个是核心”，采用法律定位内的核心标签与多个关联议题。该直接回复取代此前范围选择的待答状态；不采用全站任意热词。当前接线和实际采集结果见[法律核心获取与分析](LEGAL_CORE_TAG_COLLECTION_20261007.md)。以下旧来源包中的pending及过期诊断保留为当时记录，不回填历史批准。

## 本轮实际开发

新增独立离线版本，不迁移旧 v17/v23 或现有返修任务：

- [creative_trend_bridge.py](../src/content_factory/creative_trend_bridge.py)：账号/版本/批次绑定、既有样本门槛、时效、来源分类、账号匹配线索与格式校验；完整方向Schema；确认绑定；通用完整编剧工具Schema及请求预览。
- [prepare_trend_creative_workflow.py](../scripts/prepare_trend_creative_workflow.py)：SQLite `mode=ro` 导出已有机会、原批次和冻结账号策略；准备选题阅读稿；经实际用户确认后导出兼容 `creative_brief/v1` 的完整简报与编剧请求预览。
- [test_creative_trend_bridge.py](../tests/test_creative_trend_bridge.py)：来源、过期、错账号/版本、混批次/指标、去重、篡改、确认失效、题材变化与旧流程兼容等离线验证。

预览携带R01全文与6项编剧适用标准（V3/A1/A2/A4/E1/R1），本地测试核对它们确实位于 messages 的用户上下文中。20项标准的完整来源仍保存在档案；导演与表演标准的生产接线尚未完成。本轮未实际请求模型，不能写“参考已进入本轮生产请求”。

通用编剧请求从本次简报读取人物、关系和结尾，不继承电影/同事情境，不沿用旧固定15秒A/B脚本。动作/对白 speaker 的约束同时出现在工具Schema和本地验收中；Schema有效仍不保证模型遵守，更不保证故事好看。

**已完成的是离线桥接合同和入口。**现有仪表盘 A/B 按钮、付费派发器及治理注册没有切换到该入口。新合同无网络调用、无自动重试、无预算读写；所有请求 `submitted=false`、`dispatch_allowed=false`。真实执行必须另行绑定已有派发/在途结果/累计账本控制，不能将预览直接当HTTP参数提交。

## 离线命令

所有输出写入新目录；相同证据可重放，已有目录的内容不同则拒绝覆盖。以下参数应替换成确切的账号机会和原批次；不能用最新批次拼接旧机会。

```powershell
.venv/Scripts/python.exe scripts/prepare_trend_creative_workflow.py export-source --opportunity-id OPPORTUNITY_ID --run-id RUN_ID --output NEW_SOURCE_DIR
.venv/Scripts/python.exe scripts/prepare_trend_creative_workflow.py prepare --source NEW_SOURCE_DIR/TREND_SOURCE.json --reference-fulltext data/reference_reviews/reusable_expression_20261001/EXPRESSION_REFERENCE.md --standards data/qa/loneliness_vs_current_story_20261007/round_03_knowledge_standards/EXPRESSION_STANDARDS_v1.json --output NEW_PREPARED_DIR
.venv/Scripts/python.exe scripts/prepare_trend_creative_workflow.py writer-preview --packet NEW_PREPARED_DIR/SOURCE_PACKET.json --direction ACTUAL_DIRECTION.json --confirmation ACTUAL_USER_CONFIRMATION.json --output NEW_WRITER_DIR
```

确认记录必须来自实际用户消息，保留 `source=user_message`、`message_id`、原话、`confirmed_at`，绑定 `packet_sha256` 与 `direction_sha256`。文件结构校验不验证消息真实性；操作人不得从模型审查、缺省值或模拟夹具制造批准。改简报或来源后原确认失效。当前待答范围用 `pending`，范围确认后以新来源包保存，不改旧包。

## 后续接线与运营验收

在方向核对后依次接通通用文本派发、完整复审、导演表达审阅与既有表演/编译，再接媒体和页面；每段保存不可变来源和真实回执。运营回流应贯穿账号/策略版本、采集批次、机会、方向哈希、剧本版本、制作交接和实际发布作品ID，不能只记录热词或重新生成时换身份。

当前发布反馈模块已有账号、机会、版本和作品指标，尚未实际消费本轮新packet。后续应评估有效播放、观看留存/完播、互动与账号目标（按实际可获得的指标），比较同类作品并承认样本限制；不能把最高播放样本或模型审查无问题当成运营收益已验证。

本轮确认的是可复用流程的开发方向。离线合同通过、接口成功、有效完整文本、用户创作质量认可及运营效果分别记录，实际端到端运营尚未验收。
