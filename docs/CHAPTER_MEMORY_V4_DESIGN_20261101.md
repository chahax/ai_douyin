# 逐章累积前情分析 v4

用户要求：越往后，应利用越多的前段分析；修改后从第一章开始测试。

实现入口：`scripts/run_chapter_memory_v4.py`。这是显式文本测试入口，未替换网页默认流程。

## 每章怎么处理

1. 取当前完整章节，以及从第一章到上一章的完整原文。当前测试范围为第1—3章，不包含后文。
2. MiniMax读取此前全部已接纳的逐章分析，产出当前章增量：身份、关系、环境、事件状态、计划、未完事项；另列开头承接与结尾状态。
3. 引用地址由当前原文生成Schema枚举，禁止引用后文。certainty与temporal分开，猜测、计划、原书未来不能混成当下事实。
4. MiniMax独立检查分析，有必要错误最多修一次，再复核。仍有意见时最多一次核验其是否真正阻断承接，不反复投票到通过；存在有效阻断项仍停止。
5. 获准的当章分析追加进资料，不重写旧章。每份记录绑定原文、分析、审核、上一份完整资料的摘要校验值；保留原生失败与争议裁决依据。引用合法和模型通过均不等于语义保证。
6. MiniMax完整生成本章剧本，接收：全部截至本章的原文、此前逐章分析、当章分析、上一章最后8个原段。原文优先，分析不是不可改的“事实”。
7. 沿用v3整稿流程：DeepSeek独立审核→MiniMax核验→唯一范围补丁→复核，最多两次补丁。DeepSeek不接收分析资料或旧审查作为标准答案。

## 累积的边界

- 第1章：没有前情，建立第一份记录；第2章：读第1章记录；第3章：读第1、2章记录。每章还有自己的本章分析。
- 每章记录保留其时点，不是全书“当前状态”。旧计划不能自动算已完成；上一章末状态不能覆盖当章开场之前的事实。
- 开头承接检查上一句是谁说/做、当前代词回指谁、地点/动作是否继续，避免只按最近姓名重新指定主体。
- 来源资料只从原文分析累积，失败剧本不写回资料。测试中某章剧本未通过时，可以继续检验下一章的原文分析链；这不代表失败剧本被允许连载或生成媒体。
- 分析不是对白/表情/动作的逐项副本；普通呈现差异、原文已足以让作者生成的当前场细节，不作为分析必填覆盖要求。人物关系、事件主体、重要变化、未来/计划区分和必要承接仍须核对。
- 本轮前三章采用完整历史原文与完整分析，未声称已实现长篇自动压缩或语义检索优化。过长请求沿用容量检查，不能静默删章。本试验CLI限定2—3章。

## 可追溯与失败处理

- 全试验共用一次工程窗口，分析和剧本子任务不各自重置调用上限。
- 确认完整返回的分类合同失败可按新Schema复核原值并继续审核；不替模型修改分析，不伪造通过。
- 未知调用原样留存，停止后继章。已结束目录不可重启；有据接续新目录继承累计用量、源文与剩余上限。
- 根STATE的`current_run`指向当前子任务，运行中的调用状态以该子任务STATE为准；根累计值在子阶段结束后更新。
- 未通过结果显式保留，不转给人工待确认作为成功出口。

## 本轮检验重点

- 第1章“哥哥发传单”是老二自称，不能新增哥哥身份；原书报复/失明未来与当前眼睛完好须区分。
- 第1章末叶北持土豆袋→第2章叶嫣儿接袋，发言人和物品来源承接。
- 第2章末苏墨反对辍学→第3章孩子误解“不肯放过小六”，不能把误解写成苏墨真实意图。
- 前文分析确实逐章发送、旧分析未被覆盖、剧本和审核结果不冒充来源事实。

上述检验重点由主助手独立使用，没有作为预设答案发送给模型。真实结果另见本次生产证据与验收报告。
