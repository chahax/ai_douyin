# 声音整理 → 画面组织 → 审核：真实一轮测试

用户“行跑一遍试试”。当前小说完整19章前情、20—21章目标与上一试验一致。新增独立 audio_first 模块与 run_audio_first_trial 入口，不迁移默认生产。

## 职责划分

声音节点只确定原文内容、声音类型、说话人及证据。心理主体不明确不等于待核对白；明确出声但身份未知才保留空署名。程序分配声音ID，绑定原文片段。

画面节点使用完整原文与声音表，只输出画面和声音ID。程序原样展开声音；重复、缺失、换序或直接新增音轨拒收。这个约束防止下游改坏上游，不能证明上游判断正确，也不能证明画面没有偷偷指定说话人。

审核区分声音判断与画面组织责任。候选未自动放行。

## 开发与运行经过

初次28项回归通过；真实316生成完整67条声音后，被本助手新增的“证据段须逐字含姓名”硬门误拦。提示允许上下文归属，程序却把字面匹配当语义判断，属于设计不一致。修改为10条待审证据提示；原生声音不改，保留旧失败，核对原生工具参数与保存结果完全一致后接续。此处不是放宽到语义通过。

317画面完整返回11场。67个声音ID各引用一次、顺序正确。但49处画面采用紧凑原段范围，当前合同只支持单段，格式失败未合成有效剧本。保存原始失败，318仅审查声音表与原始画面，未重生成。音轨也没有明确绑定到同场具体画面。

最终30项程序回归通过，包括原文完整性、声音类型与身份分离、篡改/漏引用/重复引用拒绝、同源已知回执接续、失败画面只审查不伪造渲染。

真实MiniMax-M3.1-Flash 316/317/318三次：19171、18110、25410 tokens，共62691。累计318次、5984476已知tokens，pending=null；315→318工程窗口已结束，不重跑。前两次失败都为已知完整响应，无新增unknown。

## 主助手复核

声音的两个具体问题改善：海鲜感叹A017为旁白；“姐姐最好看了”A038保留未知署名，不猜哥哥。共38对白、28旁白、1系统提示。未知应答尚未解决，且声音选取不是全文覆盖证明。

主要新错误在画面节点：

- 到站下车后又写孩子贴车窗观察，并混入以前路过的见闻。
- 学校裙子见闻被写成商场橱窗里的内容。
- 六个孩子变成七个孩子。
- 便利店又附加“商场附近”归属。
- 新增孩子手捧新衣，原文当前只交代穿新衣及此前安排送货。

模型审核抓到部分问题，仍漏人数与便利店归属；还误称唯一女孩不存在姐姐对象、把呼吸平稳认定睡着、把49个画面范围格式错误说成声音也失败。未采纳这些错误理由。

## 结论与下一修改边界

这次拆分确实保护了声音内容，也让错误责任可区分；整条生产流程未通过。失败不是“所有原文理解都错”，也不能把声音两个点改善说成通用分析完成。

下一步优先完善现有画面节点的输入输出合同：画面条目与所涉及原文事件、声音ID对应；允许明确合法的原段范围；核对人物数量、实际所在与新增道具。无需再增加一批自由分析节点。普通过渡仍允许省略，微动作不因未逐字出现在原文就判错。

没有手改模型稿、媒体生成、发布、服务重启或默认迁移。
