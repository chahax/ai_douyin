# 小说全流程开发与端到端测试

日期：2026-10-17。用户本轮明确要求“直接全流程开发测试”。本轮继续实现 P2—P4 的实际接线，不停在领域模块或模拟接口。

## 交付范围

正文采集/本地导入 → 冻结来源与创作目标 → MiniMax 原生完整创作 → DeepSeek 同源同稿场记、九维全文审查与逐项核实 → 程序决定 → 有界整稿返修/同稿全文复审 → MiniMax 导演分段 → DeepSeek 对完整导演包审核 → 文本制作交接。

实际网页与 CLI 都进入新独立 v5。文本交接可以列出已有资产检索候选，不能把候选写成已批准绑定。视频、声音、用户人工审核及发布继续沿既有独立规则；本轮不自动派媒体或发布。

## 模块边界

- runtime 子 agent：`novel_agent_pipeline_v5.py`，统一来源注册、阶段路由、实际客户端调用、唯一 claim、原生请求/响应、用量、容量及可恢复检查点。
- director 子 agent：`novel_director_handoff_v5.py`，导演整包、事件覆盖、表演与连续性、素材需求、同稿导演复审和制作交接合同。
- entry 子 agent：新 CLI、新网页及主导航接线，旧冻结任务按旧入口只读，不迁移。
- 主 agent：`novel_agent_roles_v5.py`，同源完整输入、合并审查/核实原生合同与程序派生；环境核实、框架适配、跨模块主审、故障测试及真实测试结果。

## 执行不变量

1. 旧 v1/v2/v3、P0/P1 v4 接口冻结及原生文件不改写。已有小说累计 20 次 / 310301 reported tokens、剩余调用 0 继续保持，不能换版本或目录领新额度。
2. 新运行与故事在 canonical 来源注册内唯一；同源命名或分组变化不能绕过旧登记。
3. MiniMax 创作仍直接交完整原生文本，无逐句引文、排版或工具交稿硬门。DeepSeek 与导演辅助结构出错是技术停点，不要求编剧重写格式。
4. 场记/审核/核实可合并一次真实请求，但分派生产物；候选需要核实时，同一完整源稿、场记、原审查、候选一次带回全文复审。最终仍需 DeepSeek 原生 pass。
5. 默认完整稿最多两轮内容返修，同稿核实每稿一次、运行合计两次。导演层另有最多一轮完整导演修订；全部真实请求共用原生总账，范围及容量在新运行冻结。
6. 每次请求锁内领取唯一身份和预留；结果未知、用量未知、截断或缺证据保存并停止。完整回执已保存但检查点未提交时，只解析原回执，不重复请求。
7. 已完整机器合格结果可在余量 0 本地保存；任何建议、图节点或框架重入无权另发请求或重领阶段容量。
8. 框架仅管理显式状态图，不成为第二个调用账本；运输自动重试和节点自动重派关闭。网页后台执行及 CLI 使用相同运行和同一派发门。

## 测试次序与真实范围

先完成功能、故障与旧入口回归，跨模块模拟服务覆盖整稿返修、同稿核实、导演修复、断点恢复和未知停止；实际网页/CLI验收使用同一入口。

真实模型测试在代码/协议/来源与新容量冻结后进行，沿用户已授权 MiniMax 创作、DeepSeek 必要审查。旧书没有剩余容量，不擅自增额；可采用另一个没有同故事停止的新来源或独立原创小说测试源，明确标注来源性质及实际采集范围，绝不把构造源冒充番茄书籍。新来源默认总容量不超过既有新任务 20 次 / 500000 reported tokens，停止、失败和用量完整保存；不自动运输重试，不靠换源改名继续同一失败故事。

生产成功以实际完整稿、同稿复审、导演包、导演复审和机器交接原始证据为准；如服务或容量导致停止，如实交付已完成开发、证据与准确停点。离线通过、真实文本通过、导演文本通过、用户视频通过分别记录。
