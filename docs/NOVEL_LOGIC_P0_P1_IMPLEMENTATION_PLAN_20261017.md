# 小说逻辑流程 P0/P1 开发与验证

日期：2026-10-17。依据：架构方案 v1.1、Claude Code 交叉审查及用户“你验证开发”。

本轮实施独立 v4 领域模块，先冻结接口和样本，再由子 agent 开发，主 agent 审查实际接线、反例及历史完整性。不修改已冻结的 v1/v2/v3，不启动新的小说、导演、媒体或发布请求。本书原 20 次 / 310301 reported tokens、三稿三审和调用容量 0 保持原停点。

## 范围与分工

| 模块 | 本轮交付 | 负责人 |
|---|---|---|
| 字段合同 | 同源同稿产物头、场记、九维审查、问题核实、分集及导演消费最小字段 | contracts 子 agent |
| 场记规则 | 基于明示结构化状态的保守检查，区分同事件展开、独立动作、叙述层和时间线 | state_logic 子 agent |
| 问题与程序决定 | 根因去重、逐项处置、重大未决、DeepSeek 原生 pass、分离的容量及下一步 | adjudication 子 agent |
| 接线与验收 | 独立离线入口、冻结案例、跨模块及故障测试、主审和交接 | 主 agent |

公开接口先由子 agent 协商，最终以代码和接口快照冻结。领域模块不导入或派发模型客户端，不以图框架维护第二套预算。LangGraph、网页替换、真实模型及导演制作接线属于后续 P2—P5。

## 必须成立的不变量

1. MiniMax 原生文本为权威；辅助场记错误不能让编剧为 JSON 或排版整稿重写。
2. 原生 revise 即使所有意见被驳回，仍需 DeepSeek 对同源同稿重新全文审核并原生 pass，不能由核实模块直接放行。
3. 同源同稿、九维完整、场记完整、问题逐项处置及文件/响应证据不完整均不放行。严重程度未知不能当作 minor。
4. 原生 pass 后发现新重大问题须处理；可能重大的未决不能放行。已确认重大问题走有界整稿返修。
5. 全文审核、独立核实请求、完整稿返修分别计数，每个实际请求受同一权威总账约束；本模块只计算建议，不领取生产 claim。
6. 已取得完整合格结果时，零剩余调用容量仍可本地登记；需要新增请求时按实际阶段容量停止。
7. 重复报告不会自动加重严重度；歧义、回忆、电话、共享持有、同事件摘要展开不能仅按字面拒稿。
8. 结果/用量未知、截断、身份错绑保存为技术停点，不自动重派。v4 不接管旧生产任务。

## 样本及验证

- 研究材料只引用现有 v3 三稿三审及冻结正文身份，不新派三稿三审，不改其结论。
- 构造明确状态真值的成对案例：独立动作冲突与同事件重述、瞬移与转场、道具断裂与共享、缺席接话与电话/回忆等。标签在运行前保存，保留故事级留出。
- 结构化规则案例验证领域逻辑和保护门，不冒充“自然语言小说自动理解”的质量证明。真实语义检出、误报及留出质量需后续模型验收。
- 跨模块故障包括：原生 revise 全驳回、pass 后新重大问题、严重程度未知、旧稿混入、缺场记、零容量 pass、容量耗尽、未决/截断。
- 相关旧入口和原生文本回归；比对原保护基线 185 文件及原生产状态。无调用客户端的离线验证不改生产账本。

本轮完成条件是可调用、可测试的独立领域核心与明确的接线边界，不以测试数量宣称真实文本或视频质量通过。最终交接另存实施报告及本地证据目录。
