# 来源视频的情绪分析

用户于2026-09-11要求把其他视频的情绪纳入来源分析。明确结局不等于平静收场，也不必规定每片愤怒收尾。

分析分开处理：

- **表达形式**：实物示范、单人讲解、角色表演、真实对话等，以已有独立来源审查为依据。不能仅因语气激烈就声称画面中两人在对抗。
- **语言立场**：目标、阻力、追问、拒绝、让步、台词结论；引用原始ASR证据。转写不能证明语气。
- **原声与表演**：连续片段中的相对语速、语气、重音、停顿、表情与动作。区分听到的表达和推断的内心状态，不能确定时保留未知。
- **情绪过程**：开场、触发、变化、结束时各角色的状态。抽样时不能填未观察到的全片峰值或情绪占比。
- **剪辑与音乐**：与人声情绪分开。没有分离与确认，就不判断音乐贡献或精确人声响度。
- **账号适配**：参考的是表达方法，结局可继续施压、反讽、不甘、委屈、释然等，须符合本片人物目标和已完成的事件。

## 本地流程

1. `scripts/prepare_source_emotion_analysis.py` 输入完整来源证据、原媒体manifest及新输出目录。原视频SHA必须一致。≤36秒素材覆盖全片，长素材取首、中、尾各8秒，保存原片窗口范围；这些是初筛，不等于长片分析完成。
2. `scripts/review_video_omni_local.py --batch-json <输出目录>/jobs.json` 只加载一次本地音画模型，逐个连续窗口分析。不可让模型对首中尾拼接样本虚构连续转折。原媒体不上传外部服务。
3. 检查输出，发现错误保留原始结果并退回；不得用标签完整代替真实内容。需要全片情绪曲线或准确峰值时，补齐连续窗口后再判断。
4. `scripts/publish_source_emotion_analysis.py <输出目录>/manifest.json` 验证每个窗口样本、模型观察及原ASR绑定，保存`emotion_analysis.json`与本地索引。状态保持`model_observed_unverified`，此命令不签发独立通过。
5. 新建来源工作流请求会附带这些带SHA和范围说明的情绪观察；历史请求不偷偷改写。编剧与审稿提示词要求把模型观察、已确认事实和原创表演分开；涉及矛盾或未看范围不采信。

ASR字数/全片秒数只叫“转写信息密度”，包含停顿与转写误差，不能充当精确发音速度。点赞值保留原指标名，不当作播放量或创作贡献率；这批素材不足以证明某种情绪导致高点赞。

## 本次发现的分析器缺陷

第一轮对拼接样本要求复杂分项回答时，出现24秒样本被标注到30秒、单人表达被写为双方对抗的错误。该轮`omni_observation.json`保留为失败诊断，不作为本次正式情绪索引的输入。改用每个连续窗口独立的短问题；表达形式继续使用已独立审核的来源分析。仍须保留模型观察的不确定性。
