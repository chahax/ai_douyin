# 参考片驱动的导演稿流程

## 当前目标与参考证据

参考片分析与原始抽帧材料位于 `data/reference_reviews/loneliness_20260919/ANALYSIS.md`。参考片的有效手法是：明确刺激引发反应、有目的的动作、观众能看懂的信息、主次画面和反应近景；不是堆叠悲伤形容词。原片声音没有完成直接听看核验，分析里的声画限制仍保留。

## 文字生成与审核

1. `scripts/run_reference_director.py` 分别生成 story、emotion、visual，每层保存真实请求、返回、候选及审核，不用下游偷偷修上游。
2. 表演使用 `scripts/run_reference_performance_beat.py`，按B01到B04逐段生成。前一段未真实审核通过，下一段不能启动；下一段请求绑定前段末态及源文件哈希。每段只能输出当前id和原对白。
3. 通过后使用同一入口 `--assemble` 机械合并。`assembly.json`保存四个模型输出及审核来源；还需全稿跨段审核，合成成功本身不是通过。
4. `scripts/export_reference_director.py`导出可读导演稿。文字通过不能替代视频质量审核，也不能把四层或四段通过算成四次完整流程通过。

示例（RUN为新目录，UPSTREAM为已审故事/情绪/镜头目录）：

```powershell
.venv/Scripts/python.exe scripts/run_reference_performance_beat.py --run-dir RUN --adopt-run UPSTREAM --beat B01
# 实际审阅并记录B01后，再调用B02；依次到B04
.venv/Scripts/python.exe scripts/run_reference_performance_beat.py --run-dir RUN --beat B02
.venv/Scripts/python.exe scripts/run_reference_performance_beat.py --run-dir RUN --assemble
```

审核重点：观众是否知道旧话所指；先刺激后反应；收口不得早于说完；抬脚/侧步按自然速度；反打背景与朝向相容；近景不声称能看见脚；脚部关键动作在全景内真实发生；身体、目光和脚位跨段接续。

## 格式恢复的边界

`src/content_factory/director_json.py`只允许对finish_reason=stop的完整响应修复一个末尾容器括号。原文不变，`syntax_repair.json`明确记录位置、旧字符、新字符与哈希，并在使用时重新推导。不能修字符串、数字、正文标点或中间括号，不能修length截断，不能产生语义批准。试验中修复trial023末尾括号后，原来的镜头时间/动作问题仍被结构及实际审核否决。

## 首段与续段

静态首图是可选的制作控制方式。默认旧稿沿用已审首图；新稿可在delivery/generation_options.json显式声明 `reference_generation_options/v1`、`opening_mode=text_only` 和理由。执行计划、最终提示词、源bundle及实际请求必须一致，不能只改production.json放行。

纯文本首段会写明唯一门洞、门轴开向、人物门内外位置、侧步空间及每镜景别；不带任何图片参考。后续仍严格承接紧邻审核通过原片的原始尾帧，不能借图、跳段或把未检声音当作通过。无需把企业素材权益当成情绪表现升级条件。
