# 可复用创作简报示例（提案，尚未接入生产）

用户每次修改下面的创作要求。程序应据此派生角色、场景、镜头、资产引用和执行计划；不得要求用户手改Python或某个故事的镜号映射。本文件不是新的生成授权。

## 每次更换的内容

```yaml
标题: 待定
故事来源: 原创 # 或已提供正文的改编
主题: 一句话说明这次想讲什么
目标观众: 谁会关心这个故事
希望观众的感受: 开头感到什么，结尾留下什么
人物关系: 谁想得到什么，谁或什么阻止了他
核心事件: 哪件具体事情迫使人物作出选择
关键转折: 什么新证据或行动改变人物判断
结尾: 用哪个可见决定或反应结束
时长范围秒: [60, 100] # 示例，可改；先评估是否可拍

参考表达:
  - 参考片及时间段
  - 这段值得借鉴的镜头或表演机制
  - 不借用的剧情元素

避免的观感: []
```

## 固定流程应承担的工作

1. 对比故事候选，判断因果是否成立、结尾是否真的兑现、动作与对白是否容纳得下。
2. 用少量探索图确定审美，再生成角色与场景资产；查看实际图后再修订调度。
3. 每镜写明观众新增的信息、注意对象、刺激和反应、切镜理由及必须可见的动作。
4. 从角色／场景／道具ID生成素材引用，不按S01–S08等故事专用区间写代码。
5. 保存画内／画外对白、状态和反应窗口，编译成执行器支持的请求。
6. 能力未知时先做有界验证；正式制作遵守已有逐段审核、原始尾帧接续与声音规则。
7. 全片实际复核，保存失败、待检和成本。复用不等于跳过判断，也不保证首发全对。

## 原创例一：职场

主题：一个总替同事收尾的人，第一次明确拒绝。
人物关系：同事以为帮助理所当然，主角害怕拒绝会伤害关系。
核心事件：下班前再次收到临时任务，同时看见自己已错过的约定。
关键转折：主角不再默默接下，说明边界；对方必须自行承担后果。
结尾：对方开始处理自己的任务，主角离开；不靠口号总结成长。
参考表达：学习目标样片“信息插入→人的反应”，不使用诈骗剧情和人物。

## 原创例二：陌生人

主题：一个习惯不被注意的人，发现自己的日常习惯被记住。
人物关系：常客与早餐店店主，彼此不熟悉。
核心事件：常客没有开口，店主先按他平常的习惯做好一份早餐。
关键转折：常客原本只打算匆忙拿走，意识到对方记得自己，停下并作出回应。
结尾：回应和短暂对视，不解释孤独，不追加事故或悲惨身世。
参考表达：学习目标样片末尾“接收刺激前后面部变化”，不复制电话和对白。

上述两例只说明输入如何变化，未生成剧本、未做质量验收。角色形象、动作、时长和镜头仍需通过正式上游创作确定。
