# 浏览器执行器退出恢复与原任务接续

用户授权“开发测试然后应用到这次吧”。修复对象是 account01 的本地执行链路，不新增发布、评论、点赞或模型调用。

## 故障证据

12:49 浏览器启动在 importing_playwright 阶段超时，worker 被回收。空闲120秒后，旧 host 仍执行 list_tabs RPC；此时 _proc 已为空，RPC 抛错。原 finally 只停止心跳、移除线程登记，没有交还 owner。最后 owner 心跳为12:51:11，generation46。13:19 的原同步命令 d8b6ffd9d8d5465db32e3b89da48f7ee 保持 queued，owner/generation 为空，未产生执行阶段。业务租约一小时后先报 outcome_unknown（异常32），等待器三小时后报 command_wait_timeout（异常33）。后台进程活着不代表账号执行器可用。

## 修改

- 空闲清理遇到从未就绪且已确认清理完成的 worker，不再向不存在的进程发标签页 RPC。
- host 退出先核对原命令是否全部已知结束，以及人工/官方标签页是否受保护；确认资源退出后才以原 owner/generation 原子交还，保存原 owner 和清理证据。无法确认退出、仍有 running/paused/waiting_human/unknown 时保留控制权。
- 启动失败清理记录实际进程退出证据，捕获并只处理该未就绪 worker 自己的子进程；不按进程名称清理用户浏览器。
- 异常退出恢复按账号持久退避5分钟，24小时内达到2次异常退休则不再自动启动；正常空闲退出不计入故障预算。此预算限制执行器再启动，不重放已执行失败的业务请求。
- 作品同步调度增加原浏览器命令绑定。尚未领取的队列等待不会直接被写成执行结果未知；超过等待窗口转为 waiting_original，阻挡重复计划。扫描只消费原命令回执，记录后推进下次计划。
- 本次历史失败已结束，采用独立接续记录保留其原失败快照；原请求继续使用相同ID/请求SHA。接续结束只保存独立回执和安排下次计划，不把历史失败改成成功。旧版本未绑定的任务不靠时间猜测批量接续。本次明确授权的单条任务单独校验接入。

当前调度绑定改动针对作品同步 post-publish；智能运营和观看原有未知任务保护保持。缺少退出证据的进程崩溃、真正未知的外部结果、验证码不纳入无条件自动修复。
