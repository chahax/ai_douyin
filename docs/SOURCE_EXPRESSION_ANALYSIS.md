# 原片音画表达 → 高表现对照 → 账号原创剧本

2026-09-09 起，标题和标签仅用于采集、筛选与选题。新剧本必须建立在至少20条同批、不同主要标签且总点赞或总播放达标的原视频分析之上。来源文件缺失时停止，不用标题摘要替代看片结果。

## 输入原片

研究页面和 `scripts/run_account_video_research.py` 支持 `research_local_media/v1` 清单，绑定账号、采集批次及每条视频的真实 item_id/video_id。每批研究会导出待填写模板；当前合同片的20条模板在 `data/trend_research_runs/local_media_contract_sources_20260909.template.json`。其中 `video` 为空是明确的缺失，不能填本项目生成片段充当原始参考。

```json
{
  "schema": "research_local_media/v1",
  "collection_run_id": "实际采集批次ID",
  "account_uuid": "实际账号UUID",
  "items": [
    {
      "item_id": "douyin:实际视频ID",
      "video_id": "实际视频ID",
      "url": "采集时保存的原链接",
      "video": "D:/IT/ai_douyin/data/source_media/实际原视频.mp4"
    }
  ]
}
```

可选 `qwen`、`transcript`、`scenes` 字段接受现有分析产物；旧无来源哈希的产物不能直接通过新门槛。

原片获取已新增独立入口，复用账号登录会话，在同一页面依次读取来源。它核对实际播放器或页面JSON的视频ID；遇到 `blob:` 时，仅使用浏览器已发出、且 `aweme_id` 匹配当前来源的详情请求，响应的视频ID还要再次一致。不会猜测媒体地址、生成签名或处理验证码。

下载使用浏览器认证请求上下文保存原始二进制，核对HTTP成功、文件大小、视频轨道及来源时长，保存SHA和获取回执。若已观察到详情请求，会先读取真实规格，避免直接请求过大的默认版本；正常保留合适的主版本，长片优先选择保持宽高比的完整480—720p MP4，不选DASH独立轨，不截短片段，存在音频的来源须有覆盖完整时长的音频轨。所选规格和依据写入回执。

接入分析前再次检查回执的账号、采集批次、视频ID、原片SHA及文件路径。清单只在 `items` 写入实际获取的原片，待获取来源列入 `pending_items`，`selection` 固定本次选择的全部来源。后续研究按这份选集分析，不能把选中的20条扩大成默认50条；20视频、主要标签和总指标门槛仍需通过。下载完成不等于音画分析通过。

仅获取指定批次的原片，默认单条验证，不调用模型：

```powershell
.venv\Scripts\python.exe scripts/acquire_source_media.py --account-id account01 --resume-collection-run <已有批次ID> --max-items 1
```

继续同一批次可增加 `--max-items`。已获取文件验证哈希后复用，不重复下载。遇登录或验证时保留同一会话，完成后按CLI提示续跑；明确停止或输入结束才关闭。来源身份无法确认时停止，不拿推荐视频替代。完整签名地址仅保存在本地来源回执，命令输出不含签名参数。

主研究入口使用 `--acquire-source-media` 获取原片并生成清单，`--run-local-toolchain` 才执行本地图像和语音模型，`--generate-script-pair` 才调用编剧。也可继续手工提供原视频清单。

离线续跑已有批次、分析原片并请求双剧本：

```powershell
.venv\Scripts\python.exe scripts/run_account_video_research.py --account-id account01 --keywords 合同纠纷,劳动争议,婚姻家事 --resume-collection-run <已有批次ID> --content-analysis-implementation local_qwen_paraformer --local-media-manifest <填写完成的本地清单.json> --run-local-toolchain --authorization-reference "本项目原片音画分析" --generate-script-pair --short-seconds 45 --long-seconds 180
```

只检查所选来源是否已具备编剧条件，不调用模型：

```powershell
.venv\Scripts\python.exe scripts/pre_video_script.py --account-key account01 --collection-run-id <已有批次ID> --recent-video-types mixed,talking_head,text_cards,interview,unknown --check-sources-only
```

退出码0表示证据门槛通过，2表示有缺失；生成入口也会执行相同门槛，并将缺失原因逐条保存为 `source_media_gate_*.json`。时间使用记录中的采集、分析与完成时间，页面统一北京时间，不由文件修改时间推断任务完成。

## 实际分析与证据

本机已有 Qwen3-VL-4B-Instruct 图像理解、Paraformer 语音识别、FSMN VAD 和标点模型。工具链先探测原片实际时长，抽取带解码时间戳的全片分布帧并提取完整音轨；图像模型按小批次遍历全部抽样帧，再结合本地转写文本提取核心与表达方式。缓存绑定原片SHA、采样及模型/提示词参数，不能用路径和文件大小作为同一内容的证明。

长片的全部画面观察和ASR先按时间切成有界证据段，再逐层合并。每段都保留原证据引用；全量原始证据仍写在最终分析工件中，不把分段候选归纳冒充新的原始证据。超过输入预算时停止，不能静默截掉后半段。分层合并可能遗漏细节，核心诉求、开场与实际结局仍须独立核对。

视觉小批和归纳阶段都保存按输入身份校验的检查点。图片复制到新的分析目录，在原片、帧字节、ID、时间、采样参数、模型及提示词一致时可以续用；来源或参数改变时不复用。实时日志与每次分析的 `stage_progress.json` 记录阶段、真实时间和已观察帧数。处理完成、文件校验完成与语义审核通过是三件事。

实际原片复核发现过两类错误，均已拦截并加入提示词：画中画的手部操作不能归到背景出镜人；上门催款等存在明确诉求和阻碍的反问台词不能仅因包含问题就归为知识问答。夸张反问不能变成死亡责任等新主题，操作建议中的动作对象不能被改写。

每条 `VideoContentAnalysis` 新增：

- `expression_analysis`：核心表达、实物演示/人物冲突等表达方式、视觉与语言结构、角色目标与阻碍、转折和结局、逐条证据ID/通道/起止时间及未知项。
- `media_evidence`：原视频、抽帧清单、视觉分析、音轨和转写的路径与SHA，实际采样时间、已分析帧数和全片音轨覆盖。

原片、工件或单张帧图发生变化，帧只分析一部分，原片首尾未覆盖，ASR失败，证据无时间或引用不存在，均不能计入已完成媒体分析。视觉证据须对应解码帧的ID、时刻及原始观察文字；语音证据须与转写的ID、原句和时间一致。视觉表达不能只引用ASR，语言表达不能只引用画面。确认无语音须有无音轨或全轨静音依据，不能把ASR返回空串直接当成无语音。相同原片SHA不能借多个来源ID重复凑20条。

这里的音频分析是语音转写及语言结构分析；音色、语气、音乐、音效和口型没有被完整验证。抽样画面也不能证明帧间未观察到的连续动作。所有这些限制要保留，不能让图像模型根据ASR臆测已听过原片。当前流程不向外部音频理解接口上传音轨。

### 低内存与中断续跑

用户于 2026-09-09 要求优先减少内存占用，允许慢跑。本项目 `.env` 中 `SOURCE_ANALYSIS_LOW_MEMORY=1` 启用低内存模式：来源流水线使用跨进程锁串行，Qwen 每批最多 2 帧、NF4 双重量化，计算线程 2、解码线程 1；Paraformer 的 `batch_size_s` 降为 15。抽样间隔、首尾和场景变化采样、图像像素上限及完整音轨覆盖不变。模型加载前需有至少 6 GiB 可用系统内存；批次之间可用内存低于 2 GiB 时卸载模型，等待内存恢复后继续。此阈值用于缓解压力，并非整个系统的硬内存配额。

可选依赖列在 `requirements-video-analysis.txt`。NF4 加载使用 Transformers 的 `BitsAndBytesConfig`，依据 [官方量化说明](https://huggingface.co/docs/transformers/quantization/bitsandbytes) 和 [Windows/CUDA 安装支持](https://huggingface.co/docs/bitsandbytes/installation)。量化配置进入检查点身份及原始响应；低内存模型的候选结论同样需要语义复核，不能自动视为与原精度结果等价。

`SOURCE_EXPRESSION_SYNTHESIS_PROVIDER=configured_llm` 仅把带时间的本地观察和 ASR **文本**交给已配置的编剧模型归纳；输入检查拒绝图片、音频和文件块。图像观察和 ASR 仍在本地完成，图像模型在文本归纳前卸载。纯文本修订路径延迟加载 CUDA，因此不会为重做归纳而加载图像模型。

来源归纳可以用 `SOURCE_EXPRESSION_LLM_MODEL` 单独配置模型，本次设为 `Minimax-M2.7`，双剧本的编剧模型设置独立保留。外部纯文本阶段最多 64,000 字符，本地 Qwen 文本阶段仍为 11,000 字符；较长来源继续分段合并，全部原始证据保留。纯文本预算不会增加本地图像批次或加载另一个本地模型。归纳的 JSON 若仅在明确相邻的 `text/evidence_ids` 字段内漏转义中文引述的英文引号，可做保守的转义修复并记录原文/修复 SHA 和插入位置；原始回答不覆盖，歧义、截断和其他格式错误仍拒绝，语义及证据校验保持必需。

已观察但尚未完成归纳的任务，可向 `analyze_video_frames_qwen.py` 提供 `--visual-responses-from <原尝试目录> --visual-responses-batch-size 6`，核验原片、帧字节、解码时间、提示词、模型与原始推理配置后复用原 6 帧批次的文字观察；只为缺失帧执行新的 2 帧推理。旧观察记录真实来源和旧配置，不写入标为新 NF4 配置的缓存。`--synthesis-from <原qwen.json>` 则用于完整视觉观察的纯文本重新归纳，两种复用方式不能同时使用。

一次来源同时包含旧标准和新 NF4 观察时，可用 `--visual-responses-plan <JSON文件>` 显式列出每个原始响应目录、真实批次大小及推理配置。工具逐项校验，拒绝重叠帧，不把标准结果改标为量化结果，也不重复处理已经完整保存的图像。某一来源文本失败时仍可先推进其他独立来源；不完整或被语义拒绝的来源不能通过双剧本的全选集门槛。

实际抽帧复核发现的错误，可用 `--observation-review` 提供绑定原工件和帧 SHA 的逐帧纠正，并用 `--synthesis-feedback-file` 指导重新归纳。原始模型响应保留不变；纠正文件一旦用于生成，后续修改应创建新版本，避免使已有工件的哈希绑定失效。审核材料由 `scripts/export_source_expression_review.py <清单>` 导出，导出完成不代表审核通过。

## 高表现与创作使用关系

`build_expression_patterns` 在同一批次筛选出的来源集合内，对同指标的上四分位（保留并列）与其余样本，统计表达方式支持视频数、实际来源ID和中位点赞/播放；指标分别核算，缺少对照时标明无法比较。这是所选样本中的关联，不代表整个采集批次，也不证明因果，不能据点赞推断完播或转化。

编剧接收每条完整表达证据、这些对照以及账号定位，选择可执行的呈现方式。模型输出 `expression_plan` 和 `reference_usage`，把借鉴的抽象方法、原创改编和对应镜头记录清楚。程序检查真实ID及时间范围，独立审稿检查借鉴方法是否由证据支持、镜头动作是否真正推动情境、转折结局是否落地。

文件证据齐全不等于模型归纳正确。小模型提炼的核心与表达方式仍是候选解释，编剧和审稿必须回看ASR原句与画面观察，保留担忧、假设、否定和条件，不能拼接原片没有表达的因果。`source_semantic_fidelity` 不通过时停止，保留对应来源与证据问题，修复来源分析后再继续。已发现的语义错误按工件SHA记录拒绝，不能把失败结果当合格来源使用。

不计算模型实际创作贡献百分比。采样得分不是贡献率，点赞份额也不是；过去三个来源各约6%的数字仅来自采样分数归一化，不能解释剧本如何形成。已有历史稿保留，其新生成/修订须重新满足证据门槛，不能补填虚假来源。

双剧本完成后仍停在视频生成前。后续视频继续遵循逐段生成、抽帧与声音审核、上段通过后取原始尾帧衔接下一段的既有流程。

2026-09-10 新增显式 CLI 分阶段入口：项目模型先逐版写含实际动作、对白和完整物态的故事，独立审核绑定故事/工作流/来源 SHA 并逐镜引用真实动作；审核通过后冻结故事，只生成摄影 v2，再通过 bundle 进入正式双稿结构与内容审核。计划、节拍和转场从已审原文机械投影，摄影模型不再重写动作主体或结局。它尚未成为网页默认的全自动阶段链。准确命令、审核协议、失败退回与最终入口见 [分阶段故事与摄影流程](SCRIPT_PAIR_WORKFLOW.md)。

### 实际试写后的退稿规则

2026-09-10补充：结局按实际镜内行动倒查。`resolution`、节拍、表达计划和末句声称已完成的事实必须由本镜或此前的`action`支持，并在依赖该事实的后续动作之前发生；重印承诺不能变成已经出现的新合同，计划或尾帧文字不能跳过产生文件、核对或交接的过程。逐镜跟踪材料身份、数量、签署状态和归属以及笔和手机；言行相反若没有人物动机、反应及后果，应认定为生成矛盾。

“结局完整”不要求每次完成整笔交易。如果本片开场处理是否签当前争议文本，真实停止签署、完成眼前材料处置并明确未签状态，可以结束这一次决定；不能因此宣称金额已核实、后续交易或整个合同关系已解决。若标题或开场承诺完成签约，就仍须真正完成对应过程。此规则同时加入作者、审稿与事件提纲提示词，完整双稿提示版本为`2026-09-10-action-outcome-v8`。

已有完整双稿中只有短稿需要当前返修时，可运行 `scripts/revise_script_candidate.py --workflow-request <原_runs/request.json> --baseline-draft <同目录草稿.json> --editor-feedback-file <本轮反馈.md> --reference-source-id <实际参考来源ID> --output-dir <data下新目录>`。该入口仍先验证原20条来源身份，复用项目编剧和字段补丁协议，只调用一次文本模型，禁止修改长稿或增删镜头。允许共同核心修改时单独记录其影响；旧长稿原文冻结，原失败或待审状态不会被改变。

产物只标记`candidate_pending_independent_review`，保存原补丁、合并候选、新旧SHA、全量来源及实际请求/结束时间，不经过正式双稿发布入口。该状态仅说明模型补丁范围合法，不代表内容、制作结构或法律审核通过。还须对目标短稿运行制作预检、引用核对并实际读镜头，再决定是否展示为供用户审核的修订稿；不自动生成视频。

实际返修若出现“action已停签，但blocking/audio/transition和结局计划仍签字”等关联字段残留，可在同一命令加`--rewrite-short`。模型必须返回完整`core_message`与`short`，先写人物和六镜动作，再由实际镜头填写结局及其他元数据；工具检查全部字段和原镜号后整块替换短稿，不从旧稿继承遗漏字段。长稿不发送给此次编剧，保存的长稿原文不变，共同核心变化单独记录。完整重写候选同样须独立审查，不能自动通过或触发视频。

完整候选只剩局部问题时，继续使用原`--workflow-request`和`--baseline-draft`绑定，新增`--previous-candidate <本工具之前输出的candidate.json>`及本轮具体反馈，即在该候选上继续默认补丁。工具验证候选SHA、同目录run记录、原请求/基线绑定、长稿未变及短稿原镜号范围；保存前候选与其run的原文副本和SHA，旧文件不修改。允许继续修改的pending状态不表示内容已经通过，实际审核须另存记录。

若完整重写仍照抄旧稿中已被否定的动作，可使用`--rewrite-short --omit-rejected-short`。实际模型请求省略旧短稿、旧共同核心及长稿正文，只保留原角色姓名和身份、六镜编号、45秒时长、来源证据和本轮编辑要求；原始稿仍在本地按SHA保留。输出须保留既有角色姓名和身份，同样只保存为待独立审核候选。

本轮首次试写仍出现“双方已完全同意、依次写字签名归档”的平铺流程，以及把封空白误写成口头变更效力条件的问题。作者提示词现在先约束实际目标受阻、人物选择改变和已完成结局，再展开分镜；审稿先检查实际 shots，再核对计划字段，不能凭“冲突/转折”标签放行。删除了长版默认十二段十五秒的建议，要求新增有因果作用的事件，避免用重复书写和收纳填时长。

结构检查与内容审稿各自保留：title 属于各版，reference_usage 与 expression_plan 同级，protagonist 必须与角色姓名一致。固定机位短版的景别、机位与灯光作为 S01 定义的共享制作设置展开，原模型草稿和每项归一化记录保留；共享设置不修改动作、道具、对白和声音，也不代表首尾连续性已通过内容审核。非固定短版不使用此绑定。已有被退稿文件保留，改稿继续由项目编剧模型完成。

早期构思仍可运行 `scripts/plan_script_expression.py --workflow-request <本项目_runs中的request.json> --editor-feedback-file <编辑方向.md> --output-dir <新目录>`。事件提纲阶段沿用项目编剧模型、同一批20条已复核来源和真实高值对照，仅生成两个人物的目的/阻碍、短长事件链和引用，不填完整摄影字段，不调用视频接口。提纲按真实来源ID、事件时长和字段结构检查，产物始终是 `candidate_pending_independent_review`；外部编辑实际审查动机、因果、可见结果后，可作为后续编剧的编辑输入。提纲没有完整实际对白，不能当作新分阶段流程的已审故事或替代逐镜审核记录。不能由提纲模型自行宣布通过，也不能用编辑手写剧本替代项目作者。

提纲可重复传入 `--reference-source-id <source_id>` 聚焦实际参考：先验证全20条的独立审核与媒体身份，再保留20条核心/表达/指标/审核概览和完整高值对照，只将选定来源的完整既有证据传给构思模型。概览不能替代原句引用；所选源不删证据，未知/重复ID拒绝。原20条完整工作流请求仍按SHA追溯。`--previous-outline`用于把模型上一版提纲及新的编辑意见送回项目作者；失败稿保留，新稿仍待独立审核。

本轮模型参数对照中，M3关闭推理的整稿多次出现剧情与状态跳步；开启adaptive后的全量提纲请求曾600秒超时，聚焦参考后一次请求151秒返回，但内容仍被退回。这些是本次实际结果，不代表模型质量保证。临时模型/推理覆盖只作用于运行进程，未据一次候选返回自动更改项目默认配置。M3推理模式说明参考[MiniMax官方模型说明](https://github.com/MiniMax-AI/MiniMax-M3/blob/main/README.md)。


## 独立复核与有界修订（2026-09-09）

逐条核对实际抽帧和完整ASR后，将语义审核绑定到当前分析SHA和原视频SHA。失败版本进入永久拒绝记录，不能把旧review改成通过来解锁。抽帧理解和ASR不等于听看原片，声线、语速、口型没有核验时保留未知。

`scripts/repair_source_expression.py`接受原分析、帧清单、转写、绑定审核和反馈，只允许修改显式`--allow-path`字段；重复`--context-evidence-id`可明确选择完整证据行，旧主张所引证据必须全部包含。原始音画证据与未授权字段不可改，保存请求、响应、补丁和新旧SHA。类型或路径错误拒绝落新候选；新产物始终待独立复核。原视觉观察错误通过另存、逐帧SHA绑定的observation_review修正后仅重做文字综合，已验证图片推理无需重复。

本轮v5提示词明确区分：错误/正确实物步骤，普通字幕/信息卡片，静态背景屏/软件操作，口述案件/真实角色表演，以及提问人、签约金额、请求和结果。每批视觉frame_id沿用真实输入，不重置编号。原文法律主张保留来源归属，不能因字幕有民法典标题就认定已给法律依据。

编剧证据投影保留全部20条核心、实际所引原证据及紧邻ASR，完整原始证据另存审计工件。单源预算384条/48000字符，全批260000字符；仍超预算则停止，不裁剪前提或后半段。该预算为本项目已配置M3编剧、M2.7审稿的保守文本大小限制，不是其他模型上下文容量保证；变更模型时应重新评估。M2.7官方上下文204800 tokens，字符数与tokens不同：https://platform.minimax.io/docs/guides/text-generation 。

`scripts/export_source_expression_review.py`导出逐条核心、画面、转写语言结构、秒数和独立审核。仅当所选全部来源都具备匹配SHA的通过审核、明确同批点赞数据且再验证覆盖完整时，报告上四分位（含并列）与其余样本的表达支持数和真实来源ID；不把采样分数或点赞份额写成创作贡献。
