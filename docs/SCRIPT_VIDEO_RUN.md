## 2026-10-01 完整接通叙事交接（v2）

新原创任务绑定 `narrative_expression_v2`，将阶段职责表与完整提示词保存在任务状态中。旧v1绑定保持原阶段分配；没有绑定的历史任务不补写新规则。新职责表把全片动作规划也纳入导演表达职责，不增加单独审核阶段。

既有联合文本审核输入新增 `final_video_prompts`，由视频请求的同一编译器生成；普通审核与聚焦审核都收到它，交接核验重建同一输入。聚焦审核requirements、timing、first_frame对照包含最终请求；不把“新增信息”或情绪标签当作实际表演。新增文本会增加输入量，但不增加模型调用轮次，不宣称节省费用。

正常及助手返修交接分别生成 `NARRATIVE_TRANSFER.json`、`ASSISTANT_REVISED_NARRATIVE_TRANSFER.json`：
- 简报要求及源稿哈希；
- 各拍实际播放的动作和对白顺序（背景摘要不当作演出）；
- 每镜构图、表演、切走理由、作者提示词及实际编译请求；
- 请求是否可编译及对应版本。

对照文件的哈希进入媒体交接与输出清单；最终请求与对照不一致会停止导出。文件只证明来源和请求可对照，`semantic_approval=false`；叙事是否成立仍由现有文本审查判断，实际视频由用户人工审查。生成前不伪写内容通过，不把用户反馈替换成自动视频审核。

视频适配器v3明确映射全片计划的“画内对白/画外对白/混合对白”为请求的“画内/画外/画内与画外”语义（混合文本使用画内/画外）；保持说话人、台词与次序，不猜测新模式。v1/v2请求按原版本重建，旧模式失败不被悄悄改成通过。

本次新治理运行时登记目录为 `data/creative_governance/20261001_v7_narrative_transfer`；之前冻结目录不修改。本轮只修改代码、示例和文档，未调用文本、图片或视频付费接口。手工自由写视频提示词不属于新原创交接流程；新制作应沿用锁定剧本、分镜与编译请求，不再为每段单独改写剧情。


## 2026-10-01 叙事表达优先与真人风格

《今晚不算你的》用户反馈“习惯替同事加班”没有被看懂，成片情绪不足；这是用户反馈，不是助手播放后得出的媒体结论。文本核对发现：B01在请求前就重新打开本子，没有明确外部触发；B05才用“上次熬到两点”回述历史；正式稿B05的反应近景在最终提示词中变为固定中近景。不能把单次开本子/伸手自动解释成长期牺牲，也不能把文字里的情绪标签当作表演。

新原创任务自动绑定 `narrative_expression_v1`（`state.narrative_focus_binding`），直接进入现有编剧、导演、普通文本审核和聚焦文本审核请求，不新增模型调用或输出字段。检查分工：
- 编剧用实际动作/对白建立核心关系、当前欲望、选择代价和改变判断的依据；背景说明和摘要不算演出。
- 导演在最终prompt中落实新增信息、关键反应构图与时间窗口；连续尾帧不支持的换机位须明确适配需求，不能静默删除叙事。
- 审核在现有requirements项核对核心前提及剧本到最终prompt的信息保留。违反明确简报的表达缺失归writer/director；强度、美感与感动程度等主观建议不扩大为机械禁令。
- 动作、道具、布局、计时仍负责可执行性；这些检查通过不证明内容有感染力。

叙事判断不由关键词或程序伪造；当前改动仅完成离线验证，须新稿真实文本生产及用户观感验证才可宣称创作改善。旧run缺此绑定时沿用旧提示词；已有绑定保存完整文本，恢复不读取新规则覆盖历史。既有源稿、审核和付费回执不改。

真人版可使用 `config/creative_brief.live_action.example.json`：每次可替换主题、关系、感受、转折和结尾，示例不代表已批准重制。真人指AI写实实拍质感；人物、背景与首帧必须采用同一媒介并重建或选择兼容资产，不将动画尾帧用于真人续段。

**当前视频审核政策：**依据AGENTS.md中2026-09-30更新，视频由用户人工审查；助手仅核对任务成功及文件保存，记录 `awaiting_human_review`。下方旧版“助手抽帧/听看”默认已被替代。逐段续生一般等待用户反馈；明确授权完整审片版可延后人工审查，均不得自动写内容passed。

### 人物离屏后重新入画的身份检查

人物一致性必须以该角色首次通过的清晰画面为基准，不能只与紧邻尾帧比较。角色在上一段尾帧中不可见、被遮挡或只有局部身体时，下一段重新入画必须额外对照其历史基准，逐项检查发色与白发分布、发型、脸型与五官、明显年龄感、肤色、体型和服装。服装相同不能证明是同一人物。

整片审核必须列出每个角色的所有“重新入画”切点并逐一对照；任一角色出现明显发色、年龄或面貌变化时，`identity=false`且`cut_continuity=false`，整片视觉失败。该段不能为下段提供合格尾帧，所有从其尾帧续生的后段一并失效并需重做。若上一尾帧没有目标角色，提示词中的文字身份锁只能作为生成约束，不能作为审核通过证据。

只提供单一首帧连续控制的制作链，在分镜阶段就要检查“下一镜重新成为主体的角色是否出现在当前镜原始尾帧”。若不出现，下一镜不得直接提交；先改当前镜构图，让该角色在尾帧中保持清晰可辨。双人对话需要在每个段间尾帧保留两人的脸或足够身份特征；可以用双人中景或带清楚侧脸的过肩构图。不能等生成后再用文字声称是同一人。

文字独审逐段记录刺激、选择、变化前态/后态、可见手段、对应时窗与摄影。若反应早于刺激、重心句被切走、时长不足、末态与下一段冲突，修对应上游并使后层重新审核。短句不得靠拖长字音填满时间；克制表演不等于全程冻结，也不以微动作数量作为合格标准。

视频审核在原八项之外，明确在实际审核记录中写出“情绪触发与节奏”判断：对白前/中/后及对方反应各列实际秒数、画面证据、听看观察、通过/失败/待检查。父亲向墙认错、女儿全程同一表情、问完即抢切或结尾动作抢走重心，均不能以技术连续为由放行。未听看的声音项仍为待检查。先修当前不合格段，通过后以其原始尾帧重新推进后段。

整片复核必须判断全片最有分量的句子是否得到足够停留、对方改变是否有刺激、结尾是否及时结束；各段通过不等于整片情绪通过。局部节奏修订不自动登记新稿或清零失败预算。本次助手修订稿单独标注来源，不伪装为自动作者模型结果，不触发付费生成。

已生成视频的主要问题是视线或末态时，可显式增加 `--focus terminal-attention`。此分支核对上一失败原片实际提交的完整请求、执行计划、文字独审和模型原始输出，原样保留其中的人物及纸张对应，只让模型澄清源稿各角色已有的视线目标及接触约束。不能把两人都改成全程看纸，不能增加抬头、转头或回看步骤来掩盖偏差；实际尾帧仍须重新查看。此分支独立记录指导版本，默认旧请求保持原样，累计停止规则不变。

本模式让模型保留合同已有印刷文字，但不烧录字幕、水印或额外标题。冻结字幕源另存，实际生成原片审核无原生字幕、下方字幕区域可用后，可本地叠透明白字细描边：

```powershell
.venv\Scripts\python.exe scripts/render_clean_script_captions.py --run-dir <本批> --shot S01 --transcript <本批实际本地ASR.json> --caption-review <实际无字幕与字幕区域检查.json>
```

此入口不加黑底、不用静图遮盖旧字；发现原生字幕时应先修生成请求。检查 JSON 绑定原片 SHA、`native_caption_free=true`、`caption_area_clear=true` 与具体 notes/evidence。本地识别字词必须与冻结对白相符，数字的小数点或负号差异也拒绝；时间只来自原片实际音频。输出是另存的字幕待审预览，检验原生音频与逐帧时间不变，并生成新抽帧材料，不修改原视频、raw tail、campaign 审核或自动选为交付。后续衔接始终使用已通过原片的平台原始尾帧。

## 用户长期要求：生成后必须抽帧检查

已按精简执行生成首镜的同一固定机位批次，S02–S06 在已通过原始尾帧门禁后沿用 `compact_continuation/v1`：机械保留本镜动作、表演、声音、唯一对白和尾态，制作道具编号转换为原有自然名称，字幕留给本地后期。旧请求不改，预览和真实请求分别留档。该模式不代替逐段画面与声音审核。

用户确认采用此前因微动作被判失败的片段时，可以通过 `video_campaign.reopen_after_human_reassessment` 绑定实际复审和用户声音确认，重新进入普通审核门禁。旧失败审核按原字节归档，历史失败次数仍累计；另登记一次继续授权。所有检查通过后才可用该片原尾继续，未决任务、修改过的原片或缺少声音确认不能通过。审核登记必须保留输入 JSON 原字节，不能序列化后仍使用旧 SHA。

2026-09-08 用户明确要求“之后生成视频你抽帧检查”。此要求适用于后续每次视频生成和重生成，助手负责完成检查，不能只把成片交给用户找问题。

1. 每镜下载后自动提取真实首帧、末帧和每 0.5 秒画面，图片标注解码帧号与视频时间。检查人物身份、座位/视线、手和道具、动作速度及口型。快速或可疑动作应额外加密抽帧，不能只看一张代表图。
2. 合并及字幕处理后重新提取成片画面，每个切点检查前后 0.5 秒；核对前镜末状态与后镜开场状态。换机位不要求像素相同，但人物位置、视线、道具状态和动作必须连续。
3. 抽帧无法判断声线和语速。必须同步听看原视频，逐镜确认谁在说话、声线是否属于该角色、嘴是否对应对白、语速是否合适；ASR 文字正确不等于声画正确。
4. 保存每项观察的秒数和证据。发现错配或衔接错误就标为未通过；检查未完成应明确记录待检查，禁止自动填写全部通过。交付时说明已检查的范围和未解决问题。检查不自动触发付费重生成。

情绪审核遇到小型音画模型反复混淆声线或给出泛化情绪标签时，不宜仅凭一个标签持续付费重试。可用 `scripts/review_speech_emotion_local.py --run-dir <已下载片段目录>` 运行本地 emotion2vec+ large，保存全段与3秒窗口的声学分类分数、原视频/音频/模型SHA。模型用法来自[官方模型卡](https://huggingface.co/emotion2vec/emotion2vec_plus_large)，不上传原声音频。分类分数并非校准概率，也不能证明演技、身份或口型；须结合原声音画辅助检查、实际抽帧与发音时间，由助手记录具体判断和相互矛盾的证据。工具不登记通过、不提交视频。

已审短稿的 `screenplay_continuation/v3` 是可选精简执行投影：保持输入尾帧，角色外观用于辨认，当前唯一声线和真实模型表演优先，原对白、动作、摄影及末态各保留；不重述名义初态，不为无对白角色再配置声线。旧v2输出不改，所有新提示仍须绑定独立文字审核。跨目录合片使用 `scripts/assemble_screenplay_segments.py --campaign <campaign.json> --output-dir <新目录>`，核对当前series每段最新通过记录和原尾链，保存实际concat切点；`--captions` 只选原声及帧时间未改变的本地字幕候选，合片仍待实际审核，不自动成为合格交付。

原片若仅有已检查正确的少量原生字幕，可在字幕审核中逐条登记 `native_caption_spans`（原文字、时间范围、观察说明），本地渲染只略过对应完整对白字幕，不叠双层、不遮盖或删除原字。原生字与其他对白时间重叠、文字不匹配或未逐段查看时拒绝此模式。原片无字幕仍采用原 `native_caption_free=true` 检查。保留原生字会有位置样式差异，交付审核中如实记录。

审核按剧情功能和连续性区分硬错误与自然表演差异。人物换位或换脸、碰错/拿错道具、关键动作缺失或反向、错误末态导致下一镜无法衔接、错人发声、声线口型错配属于硬错误。短暂看向正在说话的人后回到正确目标、在同一张纸上抬指再接触、轻微头部或坐姿变化，只要没有改变人物关系、道具归属、关键动作或冻结末态，应在观察中记录为可接受差异，不因剧本没有逐字列出就自动判失败。低分辨率下无法确认是否残余接触、是否正好指到细小文字等细节记为未确认，不能把推测登记为失败。用户明确表示某版整体可用时，优先复核最接近版本并保存新口径的独立补充报告；旧审核和失败次数仍保留，不能倒改历史。

`query` 下载成功、`merge` 合并和字幕版渲染都会自动生成 `review_packets/<视频名>/<内容标识>/packet.json`，包含时间标注抽帧、首尾对照、切点对照、切点带声音片段、音轨和待填写审核模板。旧视频可以只做本地抽帧：

```powershell

.venv\Scripts\python.exe scripts/run_script_video.py review-packet --run-dir <批次>
```

抽帧产物按原视频、剧本和切点记录绑定哈希，重复运行不覆盖原有审核。检查图片是派生材料，不能当作方舟可接受的原始肖像参考上传。`review.template.json` 初始检查项均为未填写；工具没有自动视觉、声线或质量判定能力。

审核 JSON 沿用检查模板中的视频和剧本哈希，`decision` 为 `passed`、`failed` 或 `pending`。八项 checks 使用 true（已检查通过）、false（已发现问题）、null（尚未检查）。只要已有确定缺陷即可记录失败并回到上游修订，无须先完成其他检查；无缺陷但仍有未检查项则为 pending，不能生成下一段；全部检查通过才能放行。`observations` 覆盖已有结论的检查项，每条包含 `check`、本镜 `time_seconds`、具体 `notes`、`evidence`（制作批次内证据文件的相对路径数组）。例如一个声线问题应记录原视频或本地音频检查依据、实际秒数和画面中发声者，不能只填“通过”。每次检查保存在 `quality_review_history` 中，补查不会抹去先前记录。

规则：上一段审核完成前禁止提交下一段；仅允许生成下一个未通过镜头；下一段首帧必须是紧邻已通过片段的原始尾帧。失败后先经项目编剧模型定点修订，再准备新批次并保留旧产物。已有任务结果不明时先查清，不重复提交。已确认在创建前被拒绝的请求不算“生成了一个不合格视频”。累计第 10 个生成输出失败时保存 `HUMAN_REVIEW_REQUIRED.json` 并停止后续提交，重试、换镜头和换修订目录均不重置计数。所有片段通过后才能合并，合并成片仍需重新检查每个衔接与声音。

编剧入口新增 `--baseline-draft <项目 _runs 中的完整双剧本>` 和 `--revision-feedback-file <具体问题>`，用于在新输入下定点修改已有稿。它与要求输入完全一致的 `--resume-draft` 分开记录；保存原稿与原始请求哈希、新证据请求、模型字段补丁和完整审稿结果，不覆盖旧请求伪装成同一次生成。不得混用这两种模式。

本次连续短片同时使用 `--continuous-short`：程序将下一镜 `start_frame` 绑定为前镜模型所写的 `end_frame`，保留原模型描述与逐项绑定记录，动作和对白不自动改写。随后检查短版每镜都有两个既有角色、固定同一景别/机位/光源、4—15整数秒及绑定后的连续状态。审稿和实际读稿须确认 action 能从继承状态执行，不能因绑定成功就放行跳过拿放的动作。此检查不代表模型实际生成画面已经连续，仍需检查原视频。

`SCRIPT_REVIEW_LLM_MODEL` 可以为只读审稿指定独立模型，审计分别记录编剧与审稿型号。当前项目编剧使用 MiniMax-M3，独立复核使用已有的 MiniMax-M2.7。`--review-only --resume-draft <同输入原稿>` 只做结构与编辑复核；失败保存审稿结果并返回，不调用编剧改写。审稿必须引用当前稿件的真实原句，引用不匹配就拒绝该审稿结果，不能拿它来修改正确稿件。

`scripts/run_script_video.py` 使用项目现有 `DreaminaCLIClient`，将用户指定的 v4 短版分镜保存为不可变快照。该入口只生成待审核候选，不启用已退役的旧视频管线，不发布。

步骤为准备执行分镜 → prepare → 按镜 submit → query 下载 → 逐镜检查 → review-reference → 后续镜头 → merge → 成片审核。submit 在调用服务前持久化回执；网络错误或结果不明也保留回执，重复执行会拒绝再次消费，应根据已保存任务 ID 查询。参考视频限制为本批实际文件，逐项记录哈希；台词来自锁定剧本，双人对话的画面提示由执行计划重新编译。
