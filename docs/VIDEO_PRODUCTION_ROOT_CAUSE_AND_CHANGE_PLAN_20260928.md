# 视频生产流程问题归因与修改规划

日期：2026-09-28
状态：分析与待实施规划；本次未修改生产代码，未新增付费调用。下文方案、接口名称和验收门槛均为拟议内容，不能当作已实现或已通过。

## 1. 目标与范围

最终目标是：替换创作简报后，能够生成符合主题、人物关系、情绪转折和结尾要求的完整剧本，继续形成可执行分镜、可复用资产和首帧方案，最终生成画面、表演及声音均合格的视频。JSON正确、测试通过、审核引用完整均不能替代这个目标。

本阶段先修文本生产与审核的可靠性。保留MiniMax创作、DeepSeek审核的分工作为对照基线；没有证据证明换成同一个模型就能解决当前问题。是否更换模型，要在输入和任务设计固定后比较。

沿用[动作与时序规范](CREATIVE_ACTION_TIMING_CONTRACT.md)、[可复用流程](REUSABLE_VIDEO_WORKFLOW.md)和[实际视频制作要求](SCRIPT_VIDEO_RUN.md)。本文件负责问题、修改顺序和验收规划，不作为每次全量发送给模型的提示词，也不覆盖这些规范。

## 2. 事实基线与证据边界

最新样本：已审核剧本《这次先回去》，四拍约40秒。此次是已批准剧本的下游测试，不是新简报从零创作的完整测试。

- [本轮结果](../data/production_trials/say_no_action_one_production_cycle_20260928/RESULTS.md)：4次真实文本调用，共101,586 reported tokens；未通过，无合格交接，没有图片或视频调用。
- [独立内容审核](../data/production_trials/say_no_action_one_production_cycle_20260928/round_01/INDEPENDENT_CONTENT_REVIEW.md)：三处实质内容问题被DeepSeek漏报；实际停在审核补证。
- [问题源路径](../data/production_trials/say_no_action_one_production_cycle_20260928/round_01/LOCAL_REVISION_TARGETS.json)：人工修订目标，未应用到原模型稿。
- [前两轮结果](../data/production_trials/say_no_v3_two_production_cycles_20260928/RESULTS.md)：用于回归历史结构、初态与保持时长问题。

已有改善应保留：动作计划首轮结构通过；本轮文件夹拿放链正确；程序排时完成；B3抬眼结束后有完整两秒保持。对白预算合规只代表文本估算，不证明实际声音自然。

| 本轮请求 | 输入tokens | 输出tokens | 合计 |
|---|---:|---:|---:|
| 静态清单 | 2,175 | 1,041 | 3,216 |
| 动作计划 | 4,417 | 14,970 | 19,387 |
| DeepSeek审核 | 33,463 | 3,159 | 36,622 |

审核与补证占本轮77.75%的tokens。原审和补证解析后的JSON对象相同，只有排版变化。该比例不是费用比例，不同供应商和缓存计价需要另算。

审核原始输入同时包含动作计划、派生排时计划、分镜、生成提示词、静态清单和证据目录。系统消息24,827字符、用户消息77,001字符；其中shots序列化约47,156字符。字符数不是tokens，不能混用。此次结束标记为stop/tool_calls，无上下文超限或输出截断证据。因此“重复输入已确认”；“注意力负担导致漏审”是待对照验证的解释，不能断言已经达到模型上下文上限。

## 3. 问题应采用两个分类维度

内容类别回答“哪里出了问题”：叙事、动作、交互、空间道具、镜头、资产首帧、声音。
根因类别回答“为什么失败、该修哪里”：事实来源冲突、契约缺口、确定性计算、语义漏审、审核接口、请求与输出、流程路由。

一项问题只建立一条主记录，允许关联多个内容类别；不要重复登记成几条修复任务。

| 编号 | 已知问题与内容类别 | 根因判断 | 修改责任 |
|---|---|---|---|
| R01 | B2说话时已抬眼，B3再次抬眼；交互/动作 | 表演自由文与结构化操作各自描述状态变化；已有规则未被完整执行 | 动作契约、编译器、文字与操作的一致性审核 |
| R02 | B3镜头文字要求落夹即切，落夹后却还有接受对白；镜头/叙事 | camera与cut_reason都能定义切点，缺少唯一执行依据 | 切点契约与下游编译 |
| R03 | B4椅背后直接坐下，未表达可坐侧位移；动作/空间 | 站坐状态检查不足以证明空间可达；关键空间前提缺失 | 空间表示及语义检查，后续图像验证 |
| R04 | DeepSeek全pass，漏掉R01—R03；审核 | 已确认漏审；输入重复、任务混杂可能加重问题，模型能力贡献待测 | 审核任务拆分与基准评测 |
| R05 | 17处必要证据覆盖未满足，补证原样返回；接口 | 内容判断与复杂引用覆盖耦合，补证不允许改变结论 | 审核证据接口和错误路由 |
| R06 | 早期保持窗口错误、初态与拿取矛盾；交互/道具 | 时间语义和状态前提曾不明确；本轮已改善 | 保留现有程序排时与状态回归，不重复返工 |
| R07 | 历史结构缺失、截断；接口/输出 | 分别核对Schema、输出预算、finish_reason；不能全部归为剧本质量 | 传输及结构校验；有证据才重试 |
| R08 | 长期围绕同一批准剧本修补；验证范围 | 缺少新需求、正确反例与保留样本，可能过拟合 | 可复用性验收设计 |

R03目前是文本空间安排存在风险和表达缺口，不是已经观察到视频穿模。资产复用、首帧动作、实际声音等本轮未运行，不应登记成“本轮已失败”或“已解决”。

## 4. 规则组织方式

采用一份简短总览、分类规则注册表、阶段提示模块和回归案例库。运行时由程序挑选适用规则，不把所有规范和历史失败全文发给每个模型。

| 层级 | 内容 | 使用方式 |
|---|---|---|
| 核心原则 | 忠于简报、因果明确、情绪可读、每镜提供信息、事实一致 | 少量原则贯穿创作与审核 |
| 创作简报 | 主题、人物关系、时长、观众感受、风格、转折、结尾 | 每次创作确定，可替换；不能混入全局接口定义 |
| 分类模块 | 动作、交互、空间、镜头、声音、资产 | 根据阶段和出现的实体/动作加载 |
| 程序约束 | 字段类型、ID、状态前提、时长、版本、引用和来源绑定 | 代码执行，模型仅接收必要输入与错误 |
| 案例库 | 错误样本、正确样本、含糊边界样本 | 主要用于评测，仅选少量相关示例进入提示词 |

拟议规则字段：rule_id、内容类别、根因类别、适用阶段、触发条件、严重性、事实来源、检查器、修复责任、正反例、版本、替代的旧规则。

例如“目标状态的保持窗口从进入该状态后起算”是一条通用交互规则；“本片抬眼后保持两秒”属于本次简报/剧本实例。不要把两秒固定成所有故事的要求。

规则变更必须同时说明保留、合并、移至代码、移至案例、废弃中的哪一种。旧任务仍绑定原版本；不能直接删掉兼容规则或改写历史失败记录。

## 5. 目标流程和字段责任

创作简报 → MiniMax剧本 → 剧本内容审核 → 静态资产清单 → 全片动作计划 → 程序排时和派生状态 → 聚焦语义审核 → 有界局部修复及受影响范围复核 → 合格文本交接 → 审美样板/实际资产 → 依据图片校准镜头 → 逐段视频及声画审核。

保留全片规划，按阶段减少重复输入；不能靠逐镜孤立生成丢掉跨镜关系。

### 5.1 统一事实来源

- 剧本负责剧情、说话人、对白及关键事件顺序；改剧情需要回到剧本审核。
- 静态清单负责身份、外观、场景与资产身份；资产owner和实时holder分开。
- 初态与动作操作负责位置、视线、姿态、持物等状态变化。
- 表演文字补充表情、力度、呼吸和节奏；任何新增状态变化必须在操作层表达。不能仅靠关键词过滤证明一致性。
- 切点绑定明确事件及其完成条件，camera只决定如何拍摄；编译出的切点、末态和最终提示词必须一致。
- 程序计算时间、首尾状态和派生分镜。保留源稿到派生字段的映射，供审核与下游核验。
- 源剧本要求同时说话和关键动作而当前契约不支持时，返回明确的表达不兼容，不能默默改剧情迁就Schema。

空间模型先覆盖实际高风险关系，如座椅可坐侧、桌面可达区域、通道、身体朝向和物品持有人。无需立即建设复杂三维引擎；无法判定时明确unknown，进入语义或实际图片审核。

### 5.2 精简审核输入与输出

由程序构建版本化审核材料：整片简报和情绪脉络 + 当前镜头事实 + 相邻边界 + 必须比较的原文片段 + 确定性检查结果。保留所有承载动作/切点语义的自由文字，不能为了省tokens删掉R01、R02所在字段。

优先构建三类对照：操作—表演文字；本镜末态—下镜首态；切点—本镜尚未完成的对白/叙事任务。共享静态清单只提供一次；动作计划、排时计划、分镜和生产prompt不再无差别全文重复传入。最终视频prompt的生成也必须做一致性检查，不能只验证其上游就默认编译无误。

审核输出拟简化为规则检查状态、发现的问题、具体证据位置、理由和修复责任。证据包由程序预先绑定真实来源，引用有效性由程序校验；有效引用不代表判断正确。重要检查必须明确passed/failed/unknown，不把空issues等同完整通过。

先尝试单次聚焦内容审核。仅在不确定或高风险变更时增加针对性复核，不默认增加多次模型或多agent调用。

### 5.3 按原因修复

| 失败类型 | 处理路径 |
|---|---|
| 结构/输出截断 | 保留原响应，识别原因后做有界重试或结构修复；记录预算 |
| 引用格式错误 | 修引用映射，不重写剧本；无法支持原结论时转语义复核 |
| 内容矛盾 | 回到事实所属层做局部补丁，重编译并复核依赖项 |
| 审美偏好 | 作为建议或简报调整，不自动升级为硬失败 |
| 修复无变化 | 记录对象/内容hash相同，不重复同一个无效请求 |

局部修复不等于只检查一个字段：状态变化影响后续镜头，时间变化影响对白和切点。通过依赖关系确定复核范围；根本剧情改变则重新审核全片。沿用来源hash、有界补丁、完整校验和下游绑定能力。

## 6. 实施顺序与交付物

以下新增修改均未执行；表内Python模块已存在，拟议的是本轮新增能力，不是模块本身。各阶段还必须提交第10节规定的可检查工件。

| 阶段 | 工作与涉及模块 | 验收条件 |
|---|---|---|
| P0 规则盘点与基线 | 对现有prompt、Schema、校验器做规则映射；冻结真实失败样本与输入统计 | 每条规则有唯一责任与来源；区分已实现和文档承诺 |
| P1 事实与字段归属 | creative_action_plan_v1及版本路由：切点绑定、自由文与操作关系、最小空间前提 | R01—R03有真实错误样本和对应正确样本；不能只写匹配原句的检测器 |
| P2 审核材料与接口 | creative_review_v6、creative_review_evidence_ids：去重、证据对照、明确unknown | 必要语义保留；引用可追溯；格式错误与内容失败分别路由 |
| P3 修复和交接 | creative_plan_patch、creative_segmented_director、creative_state_plan_binding及workflow | 修复后新版本重编译；受影响范围复核；已知失败及未解除的复核/阻断级unknown不生成合格handoff |
| P4 分层评测 | 现有测试与生产runner增加相应评测入口，不覆盖旧series | 按下节输出结果，并保存真实调用、费用及原始证据 |
| P5 规范收敛 | 同步更新现有动作规范和实现说明，标明旧规则替代关系 | 文档、运行时协议、测试版本一致；本规划更新实际完成状态 |

先完成P0—P2再做付费对照；不同时升级模型、改剧情、改审核并调整预算，否则难以归因。生产失败发生后先分析本轮，再修复，再启动下一轮；多次接口调用不等于多轮生产。

## 7. 验收与生产测试计划

### 7.1 离线层：先确认流程没有制造矛盾

固定本轮三个漏报样本、历史保持时长/拿放初态/结构失败、正确对照、含糊边界以及合法同时说话动作场景。离线测试只能验证程序行为，不能证明DeepSeek能够发现语义问题。

检查派生一致性、源hash、版本恢复、局部修改的依赖传播、无变化修复停止，以及必需证据缺失和未解除的复核/阻断级unknown不能放行。选择有实际风险的测试，避免只复述实现的断言。

### 7.2 审核对照层：测漏审与误报

冻结一组人工标注的错误与正确样本，按内容类别覆盖动作、交互、空间、镜头；保留未用于提示词调优的样本。对同一批材料比较旧审核和精简审核，固定模型及相关采样参数；报告样本数及重复次数，不能从一次结果宣称稳定错误率。

指标：重大问题召回、正确样本误报、unknown比例、引用合法率、局部修复成功及引入新问题数量、输入/输出tokens、实际费用、耗时。初始准入要求：固定的已知重大问题不得漏报，正确对照不得因重复规则被误拦；小样本全通过只算进入下一阶段资格。

输入tokens相对同样本旧方案下降30%可作为待验证优化目标，不是已取得结果；不得通过删掉关键证据实现该目标。可靠性优先于缩短文本。

### 7.3 新简报文本生产层：验证用户真正需要的交付

拟选至少三种不同需求：双人关系转折、单人情绪变化、涉及道具/空间互动的故事，均从新简报开始，而非继续替换同一剧本细节。另加入第10.5节的五类边界需求。具体运行数量和预算在调用前绑定，本文不自动新增授权。

每次交付必须包含可读完整剧本、全片分镜与时间安排、资产复用/新建清单、首帧和关键表演要求、明确的交接状态及未解决问题。人工内容审核应评价：符合简报、动机与转折可信、对白自然、反应有时间、镜头有叙事作用、结尾兑现情绪；技术检查不能代替这些标准。

分别报告首稿可用率、修复后可用率、重大漏报和每个合格交接的成本。任何未通过样本如实记失败，不重命名任务掩盖失败，不把同一轮内调用次数计为多轮。

### 7.4 媒体层：验证实际成片

只有合格文本交接后，在对应付费范围内进入少量审美样板、资产与关键片段验证。历史人物和场景资产按身份、风格、布局和实际图片检查后复用，不能仅因ID存在就复用。

执行“本段生成并审核→通过后原始尾帧作为下一段首帧”。检查首尾、镜内动作和所有切点；同步听看原视频验证声音归属、声线、语速和口型，记录秒数和证据。未检查项保持待检查。既有《玄关一步》视觉先行授权仅限其绑定序列，不推广为新项目默认放行。

文本通过不等于视频通过。只有实际声画与情绪观感检查完成，才计作最终流程通过。发布要求仍按AGENTS及现有制作规范执行。

## 8. 调用预算、版本与回滚

每个试验绑定简报/剧本版本、规则版本、模型、预算、允许修复次数和停止条件。遇到预算耗尽、未决调用、同样错误无进展或已知重大问题时保留失败状态，不无限自动补证或重跑。

新增规则采用明确新版本，不改变旧任务请求与历史回执。先用于测试series；验证后再决定默认入口升级。回滚切回原版本，不抹除新版本失败证据。新剧本通过项目登记入口独立计数，同稿继续累计；本文不调整既有10次失败上限及付费授权。

## 9. 研究依据及其适用边界

- [Anthropic：Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：支持精简高价值上下文、按需提供资料和避免脆弱特殊规则累积。本项目采用这一设计方向，但实际收益必须测量。
- [Lost in the Middle](https://arxiv.org/abs/2307.03172)：在检索与问答任务中观察到长上下文的信息位置影响表现。不能据此直接归因本项目的模型漏审，也不能代替当前模型的对照测试。
- [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)：格式输出能力不等于语义和创作质量审核能力；还需区分输出预算和截断。

当前结论：优先修复事实归属、审核负担及修复路由，再用同条件评测判断是否换模型。下一项可执行工作是P0规则映射和冻结评测样本，而不是继续向总提示词追加本片专用禁令。


## 10. 评审修订：可检查工件与量化准入

### 10.2 控制规则增长与解决冲突

规则优先级与严重性分开。P0为来源完整性、不能伪造通过、预算及交接边界；P1为本片明确硬要求、关键剧情和物理/时序一致性；P2为创作质量建议。优先级不是模型自由忽略要求的授权。

同级硬约束相互矛盾时返回REQUIREMENT_CONFLICT并列出冲突来源，停止依赖步骤，不自动选一条。Schema无法表达合法剧情时返回EXPRESSION_UNSUPPORTED，不得用Schema优先级篡改剧情。当前用户明确变更应形成新简报版本和重新审核；历史特例不能跨series继承。P2不能覆盖P0/P1。

最小规则集按责任定义：来源与版本、简报/剧情保持、状态一致、时序与切点、交接和未知项处理。阶段按触发条件加载其中适用部分；动作/空间/镜头等扩展按内容加载。每次请求保存激活规则清单、排除理由及规则tokens预算。首版每阶段建议不超过12条语义规则，超过时必须解释合并/分工方案，不能静默截断硬规则；此数是设计上限目标，不是删掉必要约束的理由。

新增规则必须证明现有规则无法覆盖，提交至少一个错误例、正确例和对已有规则的冲突检查。相同根因优先合并。状态流转为proposed→active→deprecated→retired；deprecated必须指定替代者与版本，retired只从新任务集合移除，旧版本仍可回放。每次发布报告净增规则、替代规则、激活规则数及上下文变化，避免注册表只增不减。

| 问题 | 权威字段及对照字段 | 拟议检查器/失败码 | 单一修复责任与复核 |
|---|---|---|---|
| R01 | groups[*].operations中kind=gaze及其actor/target/value；对照dialogue_performance、groups[*].performance和编译首末态 | proposed:check_gaze_text_consistency → PLAN_GAZE_TEXT_CONFLICT；proposed:check_adjacent_state_transition → PLAN_BOUNDARY_STATE_CONFLICT | action_plan负责改源计划；重编译当前及后续受影响镜头。程序核对操作与边界，语义审核检查文字隐藏动作；不宣称程序已能理解所有文字 |

unknown必须带reason_code、缺失证据、责任阶段、处理动作、是否影响交接；不能只返回一个unknown。

| 等级 | 适用范围 | 行为 |
|---|---|---|
| 可继续 advisory_pending | 只涉及非必需审美建议，或明确属于后续媒体阶段的实际声音/口型检查 | 带标记进入适用的下一阶段；不计该项passed。文本交接可标注媒体待验，最终成片仍不能通过 |

### 10.4 审核评测的样本量与门槛

第一阶段离线整理80个独立样本：动作、交互、空间、镜头每类10个错误样本和10个正确对照。每个类别各5错+5对用于开发，另外5错+5对冻结为保留集，共40个保留样本；同一错误的表面换词不算独立案例，来源故事不得跨开发/保留集泄漏。标签包含严重性、事实证据和预期处置，标注争议先裁定，不能以某个被测模型的结论充当金标准。

拟对40个保留样本分别运行旧/新方案，每样本独立重复3次，即每方案120次评测执行、总计240次；一次执行按一个样本一次审核定义，重试和复核单独计入调用数及成本。先用12个开发样本做一次筛查，新方案若仍漏掉已知重大问题，就停止扩测。实际付费评测必须先落实额度；额度不够只能报告筛查结果，不降低样本量后宣称稳定。

准入门槛（每次重复分别计算，同时报告汇总）：

- 已冻结的R01—R03及其他重大错误不得判passed；错误样本重大问题召回100%。unknown不计为发现错误，只计安全阻断，因此不能靠全部unknown达标。
- 全部标注问题召回至少95%；每类别至少90%，同时列出整数分子/分母，小分母按向上取整要求执行。
- 正确对照误报率不高于5%；known-correct上的review_required/blocked单列，不隐藏为非误报。
- 可判定保留集的review_required/blocked unknown比例不高于5%；含糊/不可满足专门测试不混入这个分母。
- 引用合法率、必需证据存在率100%；来源不存在、漏执行或已知失败均不得进入合格交接。
- 三次重复全部达标、无重大结论翻转，才称“本保留集重复验证通过”。报告比例的95%置信区间，并说明同一样本重复结果相关，不把120次运行当120个独立案例；不宣称总体生产稳定。

保留集被用于调提示词后即失去保留资格，须补充新保留样本再测。修复评测另冻结至少12个可修复问题，每类3个；重大问题修复至少11/12成功且不得引入新重大问题，失败如实保留。所有预算包括这部分，不能藏在“审核调用”之外。

### 10.5 新简报与边界测试矩阵

正常创作拟覆盖三类各2份独立新简报，共6份；每份一次完整文本生产，最多一次内容修复。至少5/6在该预算内形成合格交接；首稿可用率另外报告，不以修复成功掩盖。每份交接均人工核对第7.3节六项内容要求，必须无未解决重大问题；失败样本不能交媒体生成。这里只定义进入小范围媒体验证的门槛，不代表普遍可靠。

另外五类每类至少2份，共10份边界输入，作为独立路由验证：

| 类型 | 预期结果 |
|---|---|
| 不可满足需求 | 返回明确冲突及需调整的条件，不编造可用剧本或静默删需求 |
| 表达不兼容 | 明确EXPRESSION_UNSUPPORTED；区分现实可行和当前协议不能表达 |
| 合法同时说话动作 | 支持时正确表达并通过；协议暂不支持时走上行兼容性问题，不误报物理不可能 |
| 含糊边界 | 关键歧义进入复核/澄清，非关键偏好可明确假设后继续；不自行改变关系、关键转折 |
| 正确反例 | 无额外硬失败，不因碰到关键词就增加无意义动作或返修 |

边界路由10/10符合人工预定处置、零静默改剧情才通过；这10份不计入正常创作成功率分母。修复后仍失败要分析后再改流程，不靠反复重跑消耗预算得到幸运样本。

### 10.6 成本、缓存、延迟与人工复核

每次调用保存provider、requested/response_model、价格版本和币种、输入/输出tokens、缓存命中/未命中tokens、推理tokens（如供应商提供）、请求/完成时间、重试与补证关联、供应商用量回执、实际账单金额或估算标记。字段缺失记null，不能按0计算；不能重复计算已经包含在输出内的推理tokens。

成本优先取供应商实际用量/账单；按价格表换算的记estimated。跨供应商分项列出，不把77.75%的tokens说成77.75%的费用。对照分别报告自然缓存状态与可比的缓存情景；不能强制关闭供应商不支持控制的缓存，也不能把热缓存收益全部归因于提示词修改。

人工记录主动复核分钟数、角色、计价假设；等待时长单列。总成本=模型调用费用+人工主动复核成本，币种不同时注明采用汇率及日期；另报告不含人工的费用。每个合格交接成本使用全部尝试成本除以合格交接数，失败成本不能丢弃；没有合格交接则该指标不可计算。

对同样本配对比较单调用及整轮墙钟耗时的中位数/P95、重试次数、复核次数、人工分钟数。初始优化目标：输入tokens至少降30%，实际可比模型费用至少降20%，端到端中位耗时至少降20%，P95不劣于基线10%以上，人工主动复核分钟数不增加；质量门槛先满足。费用、延迟、人工任何数据不全时标记未验证，不能宣称优化完成；小样本P95仅作描述，不能外推服务承诺。
