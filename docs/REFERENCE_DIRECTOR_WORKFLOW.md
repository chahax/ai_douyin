# 参考片驱动的分层导演流程

当前为开发与实测阶段，尚未达到完整流程连续三次通过，也未接入新稿视频执行。

## 为什么重构

旧导演流程要求全场同侧固定全身双人镜头。它能降低连续性变量，却让表情太小、动作容易退化为站定说话。参考片的价值是刺激、反应与选择能被镜头看见。新流程把事件、情绪、摄影、表演分层审核，保留旧回执与旧协议。

## 四层输入输出

1. story：四段事件与短对白，责任归属、选择和结尾必须成立。
2. emotion：同一角色的前态、刺激、后态、选择与可见结果；保留已审时长和对白。强度0–5只表示当下激活程度，不是质量评分。
3. visual：明确门内外、门轴参照方向、人物轴线；镜头必须真的能看见其宣称的证据。面部近景与空间全景有不同职责。
4. performance：动作和对白排入镜头时窗，起止状态连续，反应在触发后发生，单演员动作不可冲突。

每层需要 review.json 绑定 candidate.json 哈希、实际证据与结论后才允许后层。validation.json 的结构通过不等于语义通过。raw.txt 为现有 provider 处理后的模型文本，response.json 记录处理信息，不宣称是原始 HTTP 字节。禁止人工改写模型候选再冒充原回包。

## 命令

```powershell
.venv/Scripts/python.exe -X utf8 scripts/run_reference_director.py --run-dir data/director_workbench/<新批次> --stage story
```

实际审核通过后，以同一 run-dir 依次调用 emotion、visual、performance。每次运行前检查已存在的 attempt 状态。--attempt second 保留失败尝试并选择新尝试；--revision 指定旧候选，--feedback 传具体缺陷；这属于真实模型定向修订。

模型调用参数属于协议：当前独立测试采用 `--thinking adaptive --temperature 1.0 --max-tokens 32768`；旧稿默认关闭思考的调用记录保留。8192输出上限曾造成自适应模式截断，不能把截断内容当候选。`enabled`在当前服务端被拒绝，应使用实际支持的adaptive。每次只向模型发送当前阶段输出格式及所需参考机制，完整参考分析以文件哈希绑定。

协议变更需要新 run-dir。--adopt-story 可复制以前实际审过的 story 文件夹，重新做结构校验并绑定来源；不增加独立成功次数。

## 参考片对齐标准

- 情绪：像参考片约94–103秒老人由愤怒转为接电话后微笑那样，触发和前后差别在画面里成立。不是简单加大哭喊。
- 情感：人物为什么在意、为什么迟疑、改变决定的代价能理解，不能无条件立即和解。
- 画面：像参考片手机细节、人物反应与空间镜头各司其职；不能全靠台词解释或靠换景装饰。
- 动作：像约50–58秒叫醒、递物、催拍的因果顺序，动作推进下一事件；静止要有未完成的决定。
- 证据：正常播放尺寸能辨认情绪。构图声称的手、脚、脸确实在画内。文本意图与真实生成表现分别验收。

## 媒体衔接待完成

完成文本审核后还需明确叙事镜头与API生成段的映射，不能把每个剪辑点自动变成独立付费片段。仍遵守“当前段生成并真实审核通过 → 原始尾帧作为下一段首帧”。新首图必须先检查唯一门口的空间与初态。音色、说话人、口型必须同步听看确认；ASR和抽帧不能替代这项。
