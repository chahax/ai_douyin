# 后台运行—异常人工处理—完成后继续（2026-10-18）

用户明确要求按已确认的交互开发：正常按设置后台运行；发生异常在浏览器管理前端显示；人工处理后点击完成继续，系统核验原会话，通过后继续原流程，不依赖聊天指令。

## 本轮接线

- 保持现有账号定时、后台线程与异常暂停。前端全局异常卡提供“前往处理此账号”和“处理完成，继续运行”，原日志/账号登录页统一该完成按钮语义。前往处理必须选中异常所属账号，不能沿用其他账号的页面选择。
- “处理完成”只登记一次持久恢复请求，显示等待核验/核验中并禁重复；原身份探测通过后才放行，失败显示原因仍暂停。查看者只读，未登录不读状态或登记。
- 新后端 API `complete_account_handling(account_uuid, account_key, *, handled_by, path=DB)` 返回 `accepted/state/message`。事务内核验绑定、暂停、未决恢复及三计划原运行；未知或未结束的运行明确拒绝，保留原ID/锁。重复点击不新增请求。
- 持久记录本次人工完成操作者、请求ID、原控制版本及可继续的原计划/已知终态运行。只针对该账号最近明确失败/受阻且已结束的运营计划登记续行；已完成计划和未来正常周期不强制重跑，原结果不改写。
- 原身份核验成功且原控制版本未被另一次暂停/设置变更打断后，将上述已知停止计划放到下次扫描继续。保留原失败ID，新一次业务仍走原配额/互斥/有效授权；未知、媒体、发布和付费创作不在此续行范围。
- “仅关闭提示”继续独立操作，不确认登录有效、不恢复或重派。关闭当前记录后，账号页仍能处理并继续；新异常继续展示。
- 人工处理入口复用原账号环境；已有暂停原因不被打开窗口动作覆盖。根据同账号原维护回执给出安全的相关搜索/视频/创作者页面，避免搜索验证却只打开个人首页；无可靠上下文仍用原登录入口。只返回固定官方目标，不接受任意回执URL或路径。已绑定账号窗口关闭后等待点击完成，不再要求确认一次绑定；未绑定的新账号保持原绑定流程。

## 实施与验证

先保存本方案，后台子agent实现完成/续行合同与SQLite回归，前端子agent实现三入口与AppTest；主agent审查原身份、未知门、重复点击及失败回执，组合验证、空闲重启并读回当前真实异常。不会替用户点击真实“处理完成”，也不自动解决验证码。

后台恢复应在原计划扫描内执行，长播放线程和独立扫描保持。核验成功仅说明原身份会话可用；业务继续若再次遇到验证或其他异常，应生成当前待办并暂停，不能把核验通过伪写成一轮播放完成。
