# 创作目标、阶段上下文与接口合同修复计划

用户本轮要求继续修改流程，重点是合适的规则、阶段上下文空间和实际接口数据。先保存计划，子 agent 分模块实施，主 agent 审查接线与失败用例。旧 M3/v23、525 规划、529 正文、530 审查及对应冻结、消费不变。

## 已验证问题与修改边界

1. 529 的冻结 brief 把“只核对工资、索取明细”和“老韩停滞留白”写成事实来源；法律结果不确定被错误等同于场内不能产生结果。新独立合同区分用户目标、平台元数据、核实法律、创作选择和待确认推断；不手改旧 brief。
2. 530 出站 Schema 允许空对白检查，本地却要求全部 21 句。这是实际合同不一致。新出站与入站使用同一覆盖规范，逐句、逐动作、起态和结尾的证据可追踪；覆盖合格不冒充审美可靠。
3. 529/530 分别用了 28772/33022 输入 tokens。需要按阶段明确保留与省略的字段，完整当前正文和 R01 不能遗漏；旧全文、历史回执、整图谱和重复诊断不应无差别进入每阶段。离线测量字节、字符和字段归属，不把估算说成服务端真实 tokens。
4. 请求仍使用已真实验收的 M3.1 Flash Preview 客户端和 DeepSeek 少量审查，SDK 重试关闭；服务约束不能代替本地验证。未知结果、未知用量、截断不派发返修；完整已知内容失败才进入有界完整新稿。

## 本轮实施

- A：新目标/来源合同与前置验收。故事必须有具体诉求、阻力与策略改变、可观察的场内后果，并允许法律争议开放；规则约束功能，不指定一句台词、某种情绪或唯一结尾。
- B：新阶段上下文构建器。主题/规划/完整正文/全文审查分开投影，有来源清单、内容 SHA、字段省略说明、全文同源和参考实际出现证据；复用精确模型的实际 wire 规则。
- C：新全文审查合同。请求 Schema 与本地覆盖同源；检查最早起态、动作前提、对白话轮作用、有效阻力、情绪改变、结尾局部后果。避免禁词表、强制爽点、硬填动作或以全 pass 数量代替质量。
- 主 agent：集成为独立离线入口与阶段状态门，使用真实 529/530 保存回执做失败复演，使用明确标注的合成样例做上下游接线验证，保存请求预览、审查记录和可恢复开发副本。

## 分工与验收

整片规划负责情绪和事件因果；完整正文负责人物有目的的话轮与关键行为；局部表演才细化动作、反应窗口和共享状态；确定性编译负责引用、状态前提、时间及下游失效范围。不得把所有位置、朝向和逐秒表演重新塞给剧本模型。

本轮无新增付费请求或媒体、无发布。旧一稿一审已完成的 RUN_CLAIM 不重新执行。离线入口必须可运行、无客户端构造/网络派发/消费 claim，故障分类与返修额度承接不能清零。完成后报告实际接入范围、请求上下文差异、真实旧回执的拒绝原因与仍需生产验证的部分。

恢复使用既存 v8 开发副本或本轮独立副本，不覆盖冻结、账本、凭据与原生媒体，也不恢复生产次数。
