# 连载生产独立入口 v1：开发与离线验收

本轮依据 `SERIAL_NOVEL_PRODUCTION_SPEC_20261026.md` 开发。新增 `serial_story_contract_v1.py`、`serial_story_production_v1.py` 和 `scripts/run_serial_story.py`。这是独立CLI，不替换旧冻结流程，不重启账号服务。

## 已实现

- 本地prepare读取完整可读目录，核验每章原文SHA；冻结来源、章节范围、实现、模型路线、调用上界和旧拒绝证据。prepare不调用模型，不等于外发授权。
- 执行路径为完整章节分类及逐章审核 → 分层归并及审核 → 连载总纲/分集规划及审核 → 单集完整剧情对白 → 逐场调度 → MiniMax交叉审核 → DeepSeek内容和时长双终审。
- 分层归并每组最多4个子节点，并按实际序列化体积收缩分组；单节点过大或无法继续归并时停止，不能截断章节。归并审核读取子材料及精确来源引文，不冒称每次都读完全部69章原文。全部原文与逐章材料留存。
- 全局归并固定人物与地点标识。材料覆盖精确到原段；分集允许跨章，未改编章节需要明确说明。来源未确认全书完整时不能声明原作已完结。
- 单集目标独立设置10—3600秒。场次不再沿用旧15秒限制，剧情和音轨固定后逐场补动作、神情、摄影与状态。单次输入仍受实际容量门约束；3600秒是配置上界，不保证如此长的剧集一定能在模型上下文中生成/全文审核。
- 每集将审核通过候选的结束状态传给下一集；旧状态禁止重新引入覆盖，位置、持物、知情变化绑定动作。不同timeline分开记录；结构隔离不保证模型的历史语义一定正确。
- 视频片段长度独立于剧集与场次。拆分不能切断已排定对白或连续动作，无法拆分时保存待修记录。片段导出前后状态、音轨及动作ID，不生成资产、首尾帧或视频。
- 前序固定MiniMax-M3.1-Flash；DeepSeek只用于分集双终审，输入为本集及必要完整上下文章节、筛选后的设定、候选与承接状态，不将整本原文混入终审。Qwen不参与。
- 原生请求、响应、用量和未知结果沿用严格账本。已结束/未知任务拒绝重派；独立执行的START记录阻止重复启动。候选、审核与来源按SHA绑定。

## 测试结论

`data/qa/serial_story_v1_20261026/final.xml`：150项通过，其中新增连载测试33项，旧story_first v1—v5回归117项。

新增测试包含：69章完整模拟调度；两集不同长度的完整模拟链；240秒剧集及15秒片段；固定对白不得被调度改写；跨集状态重置、人物突然换位、跨时间线状态覆盖、对白超时、章节遗漏、未读结尾、错误审核地址、来源篡改及授权范围变化拒绝；未知请求不重试；片段不截断音轨与动作。

这里的模型回执全部由Fake客户端生成，明确记为 `simulation_passed`，不是69章真实模型分析。第一次测试因测试临时目录父目录尚未创建而在fixture初始化时报错，未执行用例；first.xml保留，随后在已存在的项目测试目录执行并通过。

真实小说本地准备记录：`data/corpus_production_trials/20261026_serial_novel_v1_prepared/`。已核验69章、150,503字；STATE为prepared，calls_started=0、pending=null，无AUTHORIZATION，无START。没有新完整剧本、真实模型调用、视频或发布。

本地计划默认先生成并审核前两集，以便验收相邻集连续性；总纲规划仍覆盖全部已获取章节，其他剧集不会被标记为已生成。400次是本计划的技术停止边界，不是已经批准或消耗的调用预算。

## 尚未完成，不能作为全功能验收

- 语义审核返回revise/uncertain时保存责任阶段、字段、证据和候选，停止为needs_attention。格式错误可自动完整返修一次，但独立语义裁决及按责任阶段自动重建尚未接入。现有descendants只计算受影响后集，不等于实际执行了后集返修。
- 归并的语义遗漏、关系错误、开场信息效率仍需真实模型及独立复核，程序覆盖检查不能保证材料充分性。
- 跨进程续写、继续未生成剧集及资产版本库接入尚未实现。当前execute为独立有界的一次执行，不能重跑已结束run假装续行。
- 当前仅输出JSON长剧本与镜头拆分计划；网页入口、实际资产生成、媒体合成、分集发布未接入。
- 本轮没有真实外发授权。旧拒绝原样保留，authorize要求具体来源、目的地、计划SHA及调用边界匹配；方向确认和开发测试指令没有被写成云端授权。

## CLI

本地准备：

```powershell
.venv/Scripts/python.exe -X utf8 scripts/run_serial_story.py prepare --manifest <MANIFEST.json> --run <新目录> --statement <当前用户指令> --episode-limit 2 --max-calls 400
```

查询：

```powershell
.venv/Scripts/python.exe -X utf8 scripts/run_serial_story.py status --run <目录>
```

真实执行另需明确授权文件，经authorize绑定同一计划后才可execute。不要重跑上面已prepared的目录，不要把它的旧拒绝文件改成通过。
