# 抖音标签族与页面样本流量关系

## 目标

采集流程分成两层，且只扩展一层：

1. 对每个根关键词采集“综合排序、最多点赞、最新发布”。
2. 从完整视频卡片文本提取 `#标签`，按唯一视频支持度、排序覆盖和名次选择相关标签。
3. 对选中的相关标签再次采集同样三种排序。
4. 标签结果中出现的新标签只记录共现关系，不继续递归搜索。

默认每个关键词最多扩展 2 个标签、单批全局最多 6 个标签、单批最多 30 个搜索页。页面预算在打开浏览器前按最坏情况核验；同一标签由多个根关键词发现时只访问一次，但保留每个根关键词的关系。

## 数据口径

页面卡片中的第一个可见数字统一保存为 `displayed_metric`，语义标记为 `displayed_unknown`。除非页面明确说明字段含义，否则不能称为播放量或点赞量。

标签排行生成的分数叫 `sample_traffic_proxy`（页面可见样本流量分），不是抖音官方标签总流量。每个标签、根关键词、排序分别生成一个快照，包含：

- 唯一视频数；
- 最佳名次；
- 倒数排名和 `sum(1 / log2(rank + 1))`；
- 页面展示指标峰值和中位数；
- 前 5 个证据视频 ID；
- 0–100 的页面样本流量分。

样本流量分由样本覆盖 30%、倒数排名质量 30%、页面展示指标 30%、最佳名次 10% 组成。计算时先按视频 ID 去重，同一视频出现在三个排序中不会被当成三条独立流量。

## 关系图

```text
根关键词
  └─ keyword_hashtag ─> 标签
                           ├─ 排行快照（综合） ─> 视频 ID / 名次 / 页面指标
                           ├─ 排行快照（最多点赞） ─> 视频 ID / 名次 / 页面指标
                           ├─ 排行快照（最新发布） ─> 视频 ID / 名次 / 页面指标
                           └─ video_cooccurrence ─> 同卡片出现的其他标签
```

关键词到标签的支持度、标签到标签的共现度都按唯一视频数计算。每条边保留支持视频 ID、来源视频数、作者数、排序覆盖、关系权重和关系分，因此派生分数可以复核。

## SQLite 保存方式

所有事实和派生快照都带 `run_id`。新批次只追加，不覆盖旧批次：

- `trend_observations`：查询类型、查询值、深度、根关键词、排序、名次、视频和结构化标签；
- `trend_tags`：归一化标签实体及首次/最后出现时间；
- `trend_observation_tags`：某批次、某查询、某排序中的视频包含哪些标签；
- `trend_tag_relations`：关键词到标签、标签到共现标签的批次关系边；
- `trend_tag_traffic_snapshots`：标签 × 根关键词 × 排序的页面样本流量快照。

旧数据库启动时会自动补充新观察字段并将 `PRAGMA user_version` 升到版本 2。观察写入使用冲突更新，不使用会删除并重建行的 `INSERT OR REPLACE`，以便关系证据保持稳定。

## 登录态和原始数据

标签族采集复用趋势采集器配置的独立浏览器用户目录，因此可以复用已经验证过的登录态。数据库不会保存用户目录路径、Cookie 或令牌。

授权策略的 `raw_retention_days=0` 时，完整卡片文本只在内存中用于标签提取，不写入 `raw_text`；结构化视频 ID、标题、排序、标签和关系证据仍按批次保存。

## 后续演进

当前 `run_id + root_keyword` 就是一版不可变标签族快照。如果以后需要人工维护长期标签族，可以在现有事实层上增加稳定的 `family_id` 和版本表；不要把当前趋势聚类 `TrendCluster` 直接当作标签族，因为聚类 ID 会随视频集合变化。
