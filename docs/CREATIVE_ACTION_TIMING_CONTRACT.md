# 动作、交互与镜头的文本计划规范

更新：2026-09-28。适用协议：`whole_film_state_plan_v3`，用于显式选择新版 v6 文本流程的任务。本文解释已实现的协议及审核边界，不代表该版本已经通过真实生产验收，也不自动升级旧任务。

## 1. 规范如何执行

采用“规范文档 + 结构化契约 + 程序校验 + 实际内容审核”。文档供开发与创作人员理解；发送给模型的是当前版本的精简规则和动态 JSON Schema；确定性的状态与时间关系由代码检查；叙事、表演及空间合理性由审核模型和助手阅读实际内容判断。不能只给模型追加一大段规范并假定它会遵守。

本文不直接在运行时注入模型请求。修改协议时，必须同步修改提示规则、Schema、校验器和相关正反例，并绑定新版本；若文档与实现不一致，先登记差异并修正，不以文档描述宣称功能已经实现。创作简报只替换本片内容，不重复定义接口。

## 2. 问题归类与修复责任

| 类别 | 检查对象 | 典型问题 | 首先修什么 |
|---|---|---|---|
| 流程／接口 | 字段含义、输出结构、版本和上下游输入 | during 两种解释、截断、设计使用另一份分镜 | 契约或程序；保留原响应 |
| 动作 | 初态、动作前提、身体与道具状态 | 已坐又坐、桌面物品标为手持、从椅背后直接坐下 | 全片动作计划及空间安排 |
| 交互 | 说话人、信息获得、视线、对白时长与反应 | 先放松后听到接受、重复抬眼、8字只给1秒 | 对白窗口及刺激—反应顺序 |
| 画面／镜头 | 构图、机位、动作可见性与切点 | 同时固定机位和拉宽取景、构图看不到关键动作 | 摄影安排，保持已审动作与交互 |

同一问题可影响多类，但按根因只登记一次，附受影响项。初态自然放松、结尾释然对比弱属于观感风险，不能未经证据升级成硬性时序矛盾。修复顺序为接口明确、动作成立、交互成立，再落实镜头表达；上游改变后，下游需要重新核对。

## 3. 一份计划负责动作状态

- `script`：已审核的剧情、对白和动作顺序依据。
- `static_visual_manifest`：人物身份、外观、固定场景及道具资产依据。资产所有者不等于当前持有人。
- `initial_state`：第一项动作发生前的状态；先读全片后续动作，避免错误初态迫使增加无意义动作。
- `events.operations`：位移、视线、拿放、站坐及可见情绪的状态操作；程序推导变化和镜头首尾。
- `performance`：补充表情、呼吸、节奏等表现，不另藏与操作相矛盾的关键动作。
- `composition`、`camera`：说明如何拍清楚这些动作，不另写第二套剧情。

`take` 要求当前无人持有；`place` 要求由行动者持有并在放下后清空持有人；`sit` 要求此前站立。满足这些检查仍不能证明真实空间可达：椅背后的站位、身体转向、可用通道等仍须内容审核，后续还须看实际图像。

审核后的 `STATE_PLAN.json` 沿用到资产设计、联合审核与交接，核验来源、审核记录及编译分镜一致性。不得通过后续自由改分镜绕过这份计划。

## 4. 动作来源与时间阶段分开

事件中的三个字段回答不同问题：

| 字段 | 回答的问题 | 约定 |
|---|---|---|
| `script_slot` | 该事件对应剧本哪部分？ | `before`、`during`、`after` 或补充说话表演 `dialogue_performance` |
| `phase` | 事件相对对白何时发生？ | 使用下表明确枚举，不使用旧的 during 缩写 |
| `dialogue_index` | 是第几句对白的说话表演？ | 从0开始；其他事件填-1 |

**历史剧本字段 `script.during` 的含义是第一句对白之后的剧情动作，不是“说话期间”。** 保留该字段是为了兼容源剧本，不能按日常英语推断其时间。

| 原文来源／情况 | phase | 时间要求 |
|---|---|---|
| `before`，本拍有对白 | `before_first_line` | 在第一句开始前完成 |
| 第一句的说话表演 | `first_line_delivery` | 完整位于第0句对白窗口内 |
| 后续句的说话表演 | `later_line_delivery` | 完整位于对应索引的对白窗口内 |
| `during`，本拍至少两句对白 | `between_lines` | 第一句结束后、第二句开始前 |
| `during`，本拍只有一句对白 | `after_last_line` | 该句结束后 |
| `after`，本拍有对白 | `after_last_line` | 最后一句结束后 |
| 本拍无对白 | `no_dialogue` | 保留原文 before→during→after 顺序，索引为-1 |

所有时间均为本拍局部秒数，`0 <= start < end <= duration_seconds`。事件按开始时间排序。互不冲突的动作可以并行，同一状态字段有依赖的重叠操作不允许。对白窗口逐句对应源台词，不复制或改写说话人和对白。

v3 的 `dialogue_performance` 只允许空操作或 `affect` 操作，不能借此提前执行原文的离开、拿放、坐下或视线改变。这是当前协议的表达边界，不是“人不能边说边走”的创作规则。源剧本明确要求边说边执行关键动作时，应报告表达不兼容、修订协议并重审，不能偷偷移动动作时间或改源稿。

## 5. 正确和错误示例

假设本拍只有一句对白，窗口为2–5秒，剧本要求说完后才离开。以下是事件片段示意，不是完整可提交计划。

正确的说话表演：

```json
{
  "start": 2, "end": 5,
  "phase": "first_line_delivery",
  "script_slot": "dialogue_performance", "dialogue_index": 0,
  "performance": "自然说出对白，呼吸平稳",
  "operations": []
}
```

正确的说完离开（假设C01是本拍行动者）：

```json
{
  "start": 5, "end": 7,
  "phase": "after_last_line",
  "script_slot": "after", "dialogue_index": -1,
  "performance": "说完后转身，平稳走出两步",
  "operations": [{"kind": "move", "actor": "C01", "target": "", "value": "沿过道向门口前进两步后的位置"}]
}
```

错误及处理：

- 把上述离开安排为3–5秒：仍在对白中，应拒绝；不能仅改标签骗过检查。
- 把离开标成 `dialogue_performance`：位移动作不属于当前协议支持的说话表演，应拒绝。
- 8个汉字只分配1秒：超过当前每秒5计时单位的文本上限，应重新排时。文本上限通过也不证明实际语速自然。
- 已站立的初态又写“从坐姿站起或已经站着”：执行选择不唯一且与初态冲突，应明确一种动作。
- 固定机位同时要求拉宽取景：明确是否确实需要改变取景；若需要，统一摄影描述并重新核对连续性。

## 6. 验收分工和当前边界

| 层次 | 能确认什么 | 不能据此确认什么 |
|---|---|---|
| Schema／程序 | 字段、时窗、对白预算、状态前提、同字段冲突、来源绑定 | 模型没有在自由文本中藏矛盾、真实空间可执行 |
| 模型＋助手文本审核 | 动作覆盖、刺激反应、空间逻辑、摄影一致性、情绪表达计划 | 实际画面、声音、口型或观感已经合格 |
| 实际素材／视频审核 | 对真实图片和原视频抽帧、听看后的具体结论 | 未看的镜头或未听的声音自动通过 |

已知内容问题不得因格式正确而放行；可选审美建议不应自动触发返修。失败记录应包含问题类别、具体字段或秒数、规则来源、证据及修复责任。接口错误先修接口，内容错误回到对应计划；不以重复全文修复掩盖原因。

v3 已有离线正反例，尚未完成新的付费生产验收。当前每拍一个连续镜头；复杂同说同动、身体朝向等不能宣称已被程序完整覆盖。旧v1/v2请求及审核记录按原版本保留，不转换失败稿后冒称原轮通过。

## 8. 2026-09-28 两轮实测补充

本次两轮真实文本生产仍未取得合格交接。首轮进入DeepSeek，但出现字符串状态被当作对象下钻的证据错误，并漏报动作完成后的保持时长；次轮已明确排出抬眼后两秒保持，但出现初态持物与拿取矛盾，修复返回截断，未再次到达审核。

新任务可绑定 `completed_action_hold_v1` 指导，从进入目标状态的动作结束起计算明确要求的保持时长；目录证据接口 `leaf_catalog_v1` 列出可引用叶子路径并一次汇总无效引用。`shots`里的首尾状态即使看起来像JSON仍是字符串，只能引用该叶子及原文片段，不能自行拼接子路径。证据目录不证明内容结论正确。

保持时长指导在第二轮原稿中有改善证据；证据目录的新接口尚未得到这两轮的完整生产验证。详细记录见[两轮结果](../data/production_trials/say_no_v3_two_production_cycles_20260928/RESULTS.md)。不把本地修复或协议文档当成生产通过。

两轮结束后新增 `completed_action_hold_v2`：保留v1保持时长指导，并在语义检查前一次报告全部Schema结构错误。该修复只有离线验证，旧任务的v1绑定不变。

## 9. 动作分组、程序排时与证据编号

新建的显式v6任务可绑定 `whole_film_action_plan_v1`。旧v1/v2/v3任务仍按原绑定执行。动作计划模型不写事件start/end、dialogue_windows或reaction_window，而写全片initial_state、每拍groups、dialogue_performance、reaction锚点及摄影描述。groups按原before/during/after顺序，包含action或hold、所需时长、操作及表演。当前初态仍由模型给出，程序只核验类型化前提，不能宣称程序已决定空间和表演。

程序根据锁定剧本插入原对白，优选每秒3.5计时单位加0.3秒余量，单句至少1秒；需要时只缩短对白至最多5单位/秒。动作和明确hold不被压缩；仍超时则报告缺额。保持窗从进入该状态的动作结束后开始，余下片尾时间不能抵扣较早的保持要求。程序只生成执行时间轴，不修改原稿；剩余镜头时间延续末态是否自然仍须内容审查。

原计划、派生的v3时间轴与排时报告分别保存。审核时同时核对模型自由描述和程序时间轴：dialogue_performance不能藏未登记的视线/位移，camera不能在对白前擅自切走，文字描述的坐下路径仍须空间检查。新计划结构通过不等于这些语义检查通过。

局部修复使用 `source_sha256` 和 `patches[{path,value}]`。只替换原稿现存可编辑字段，拒绝整稿/整拍、保护字段、重复或祖孙重叠修改。保留模型补丁原响应与程序合并回执，合并后全片重新验证；局部修复不等于局部放行。原稿骨架无法定位时，才在既有预算内考虑完整重建。

审核接口 `evidence_ids_v1` 将当前上下文映射到真实叶子的证据ID。模型选择ID并给判断，程序验证ID并展开原文路径；原ID稿与展开稿分别保存。ID有效只证明寻址正确，不证明覆盖充分或审核结论正确。当前编译字段与源计划的必要对照仍须满足，不能机械补引用后宣称内容通过。
