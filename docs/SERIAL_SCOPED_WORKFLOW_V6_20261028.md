# 按本集、逐场依赖的连载流程 v6

用户确认需求后要求修改流程。本版修改正式业务模块并接入现有连载CLI的显式选择，不是一次性模型实验脚本。旧v1—v5源码、冻结任务、原生回执及2条历史未知调用不改。

## 本轮改动

1. 完整阅读：保留完整章节，按容量分组，先输出自然语言analysis和open_questions。为复用既有回执系统，目前用简洁JSON外壳封装自然语言，不要求逐段覆盖表或影视状态数组。阅读结果标为暂定理解，不自称事实验收。
2. 先规划连载：基于阅读报告和章节/原段索引规划本集事件范围，不先要求每章材料与全局资料库全部审过。完整原文保留，后续逐集再次读取。
3. 本集设定：从选中完整章节提取必要世界、人物关系、环境及事件，视觉补足独立记录。未明问题保存在questions；已知人物名称、别名、ID不能随意迁移。
4. 场次依赖：每场明确required_claim_ids与required_question_ids。未依赖的疑问不会送入调度，也不阻塞本场；使用的事实与完整原文进行本场核对，检查模型是否漏报关键因果依赖。
5. 定向回查：必要疑问触发LOOKUP原文回查，必须返回原文引证；unknown不得夹带事实。已回答的事实还需经过本场核对，不能只凭answered标签放行。
6. 局部阻塞：必要疑问仍不明、或本场审核uncertain，保留阻塞原因，后续同时间线场次保守暂缓；其他时间线可继续生成。整集有任何未解决阻塞不得记为完整通过。
7. 局部返修：本集基础事实问题返修本集FOUNDATION；回查事实问题返修对应LOOKUP；剧情问题返修本集STORY；调度问题按明确场次地址返修。复用原生请求缓存，只有输入或前态变化才重算依赖阶段。不是每个问题都重做逐章分析。
8. 复用原状态引擎：身份、时间线、人物位置、持物、知情变化、音轨和动作时长、跨集承接继续校验；新增位置值必须是已登记地点ID。
9. 最终审查只带实际用到的事实和完整相关原文，不把无关questions又带回来造成整集阻塞。保留MiniMax交叉审、DeepSeek内容/时长终审及主助手独立验收状态。

## 入口与部署范围

新增准备任务可使用：

```powershell
.venv/Scripts/python.exe scripts/run_serial_story.py prepare --workflow scoped-v6 --manifest <已获取章节清单> --run <全新目录> --statement <任务范围>
```

prepare仅本地保存计划，不调用模型。authorize/execute仍按保存的版本与授权范围执行。默认CLI仍v2；网页、账号后台、服务未迁移或重启。此次没有生产模型调用、视频生成或发布。

## 测试与限制

测试覆盖无关疑问放行两集、本场必要问题阻塞、定向回查后继续、未知答案不得伪造事实、稳定身份、位置ID、未知事实依赖、全章不截断、冻结版本分发、返修不重复阅读、独立时间线保留，以及旧连载/状态用例。最终102项相关回归通过（含13项v6），见data/qa/serial_story_v6_20261028_verified.xml。全部是离线或模拟响应，不是新小说生产质量验收。

本轮仍未解决模型语义不可靠的问题：引用真实不保证结论真实；场次依赖由模型提出，仍可能漏提。状态表合法也不保证动作文字没有隐含矛盾。不能宣称无人验收或无bug。

其他边界：剧情层返修仍以本集完整剧情为单位；同时间线阻塞采取保守传播，尚未实现任意场次因果图；超大阅读报告/单集完整原文超过容量会明确停下，不截断原文；未接新媒体生成或资产网页。沿用旧NativeClient的思考/输出设置，本版不偷偷切max，也未声称已移植实验脚本的流式/父进程时限。
