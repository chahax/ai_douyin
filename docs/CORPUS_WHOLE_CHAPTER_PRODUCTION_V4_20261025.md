# 完整章节分类、交叉校验与责任返修 v4

## 用户要求与实施范围

用户要求沿作者章节直接分类，避免按长度组成新的阅读单元；分类材料交给另一模型核验；错误按世界观、人物、环境、事件、场景调度和时长追溯责任；前序优先 Qwen / MiniMax，DeepSeek 用于最终内容及计时审核。

本次新增独立 v4 合同和执行器，不修改旧 v3 冻结任务的来源、原生输出、审核结果及用量。`scripts/run_corpus_production.py` 的新 prepare 默认 v4；已有 run 按冻结版本选择执行器。`scripts/run_fanqie_corpus_workflow.py` 的新采集任务登记 v4 文本路线，历史 JOB / 文本 PLAN 保持旧路线。没有重启账号后台、调度新采集、生成媒体或发布。

## 输入与模型分工

1. 保留每个作者原章全文，每章独立分类。默认补充完整前后邻章，明确仅本章计入分类覆盖。
2. 自然段提供 ID / 字符位置索引；长自然段不硬切、正文不重写。模型输入只保留必要索引，原文 SHA 留在本地来源目录。
3. Qwen 按 world / character / location / event 多选分类，每个自然段恰好一次；重要度只表示阅读优先级，不删原文、不强制每章精选数量。
4. MiniMax 独立逐章核验分类。已完成的语义退回可指向对应章，交 Qwen 修一次后重新由 MiniMax 审核；来源及旧标签保留。
5. MiniMax 建立世界、人物、地点、逐章主线及本集选择；Qwen 对完整原章逐项核对相关断言，并检查跨章框架自身一致性。
6. MiniMax 写视觉设计、本集事实表、完整剧本；Qwen 审核设计的来源和状态。设计说明包含统一画风、大环境到小环境、实际人物、道具、动作神情、视线和开场可见信息。
7. 程序先检查连续秒段和对白下限，再由 DeepSeek 分别做最终全文内容审核、动作计时审核。DeepSeek 路由仅允许 `FINAL_CONTENT_*` / `FINAL_TIMING_*` 请求。

这里的“独立”指不同调用、不同提供方的职责分离，不表示模型结论必然正确。用户描述的 MiniMax 现有权益不等于本次核实了供应商账单；记录中不把费用写成已确认 0 元。

## 责任返修

问题类别为 world / character / location / event / staging / dialogue_timing，负责阶段为 materials / framework / design / facts / screenplay。不能只凭“人物错误”四个字固定重跑人物阶段：原关系正确而编剧写错，应定位编剧；原关系表已错，应先修关系表。

根因报告必须覆盖每个问题，绑定原审核问题摘要、实际产物 SHA、字段路径与原样证据。来源类错误还需完整原章中的可定位引文。程序检查证据真实存在；语义归因仍记录为模型意见。

| 责任阶段 | 需要更新并重新核验的下游 |
|---|---|
| 本章分类 | 该章交叉核验、全局框架、设计、事实表、完整稿、双终审 |
| 世界 / 人物 / 地点 / 主线框架 | 框架核验、设计、事实表、完整稿、双终审 |
| 视觉设计 / 场景调度 | 设计核验、事实表、完整稿、双终审 |
| 本集事实表 | 事实表、完整稿、双终审 |
| 编剧 / 对白时长 | 完整稿、双终审 |

每次返修保存失效清单和旧产物 SHA；新的完整稿不能复用旧稿的终审。最多两次跨阶段责任返修，已完成返回的格式错误允许一次协议修正；网络未知、输出截断、用量未知仍停止，不自动重派。
