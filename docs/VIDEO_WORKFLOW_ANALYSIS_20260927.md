用户需要的是换主题、人物和创作要求后，同一流程仍能做出高质量完整作品。项目已有编剧／导演、资产生成、版本绑定和逐段审核能力，主要缺口在于审美意图没有稳定贯穿到实际镜头，媒体执行还混有单片定制代码。继续追加禁令或“电影感”形容词不能证明解决问题。

关键不是表情数量或单张画面的精细度，而是观众的信息、人物的选择和摄影观察对象一起变化。末尾来电者身份不能只凭这些帧确定。目标样片和项目最新片同为720×1280；提高输出分辨率不能单独解决目前的内容差距。

## 四、项目与样片的差距

### 1. 操作过程挤占了信息与情绪

项目抽帧中，0–55秒多次回到桌边三人／合同；60–75秒持续看手机；80–120秒多次回到前台三人；125秒后集中在窗口递交材料。动作在发生，但观察对象和信息层次变化较少。

S15提示要求拿收据、入袋、折信纸、装信封、信封入袋、拉链、拿袋、转身离开；S16又要求放袋、拉链、取多份材料、递交、接稳、拉链、拿袋。多步精细操作既增加生成风险，也容易成为办事过程展示。应在上游决定哪些动作真正改变观众判断，保留关键签字、交付等因果证据；不能生成失败后裁掉关键过程冒充完成。

### 2. 为证明全部事实，镜头常停留在多人中景

实际提示反复要求三张脸、双手、合同和道具都可辨。它有助于核对状态，却可能压缩主角面部可读面积。应分工：一镜证明动作，一镜表现人接收信息后的变化。不是机械增加特写，而是将观察权交给情绪重心。

### 3. 好的理念已经在提示里，落实仍有损耗

通用合同已要求因果、情绪、视觉递进和对白前中后反应。因此不能把“补上这些要求”当作新改造。

具体风险：creative_seedance_segments._shot_prompt把dialogue_lock统一编译成“画内对白”，没有按分镜dialogue_mode保留画内／画外差别。它可能限制说话者继续发声时观察听者反应，但尚不能断言是某个声音问题的唯一原因。要检查意图经过分镜、资产、编译、生成和剪辑后的保真。

### 4. 换故事仍需改脚本

prepare_creative_seedance_reference_segment.py写死合同片目录、导演版本，按镜号区间选陈默、林屿、方澄和具体背景，另有S11/S16特殊判断。旧参考链也锁定《玄关一步》。这些应成为历史案例／测试样本，通用入口应读取角色、场景、镜头清单。

### 5. 失败教训常驻提示，形成高负荷规则堆叠

当前writer_script约6753字符、writer_check约8757字符；许多内容是历史具体反例。视频主提示约473–670字符，另有资产引用说明。长度本身不证明错误，但混合不同题材的规则可能增加冲突和注意负荷。

建议保留少量稳定原则，将故事事实放进简报，将历史失败放入回归集，只给当前任务注入相关错误。必须真实对照验证，不能凭精简文本就宣布改善。

### 6. 审核方法仍有漏检

最新用户反馈包括：约16秒手指与拉链声、30秒后语言和内容重复、50秒及70秒场景／站位／首尾状态、95秒声音、130秒穿玻璃。原先通过描述与后续退回意见都保留在审核文件中。

静帧适合身份、构图；接触、穿越、拉链、道具交接要连续看完整动作及接触前后。声音要实际听看。ASR和不可靠本地模型不能直接写口型、声线通过。改造重点是让实际观察可靠，不是再增加几个勾选框。

## 五、建议的新流程

创作简报 → 参考表达拆解 → 故事与审美方向 → 角色／场景资产 → 根据实际资产修订调度 → 分镜与节奏预演 → 有限能力验证 → 正式逐段生成与审核 → 整片观感、切点、声音复核。

### 用户只改一份简报

主题、人物关系、来源、时长范围、画风、观众感受、核心转折、结尾余味、限制。角色路径和镜号逻辑由清单派生；用户不改Python。不同题材采用相关约束，不默认父女、玄关、四段或固定27秒。

### 审美先由画面确定

在批量资产制作前，用少量风格探索图确定肤质、光线、色彩、空间层次、镜头距离和表演程度。保留现有Seedream资产能力，角色身份参考尽量减少干扰；场景能容纳已定动作。实际选定图片交给可读图的导演阶段核对，避免继续为不存在的空间设计调度。

### 每镜以观众收到什么为核心

明确注意对象、新信息、刺激、反应前后差别、切镜理由、必须可见的证据。每段只传当前相关人物和状态。让对白方式、反应窗口、资产引用和状态由同一权威中间表示编译到最终请求，避免多层重复改写。

### 区分故事镜头、API片段和剪辑片段

先做带时长的分镜预演，再由已验证适配器处理时长与参考方式。不能把两秒插入镜仅因API限制拉成四秒，也不能为省一次请求把七八个动作塞入一镜。计划内省略与事后掩盖失败必须分开。

关于独立参考生成换镜、原始尾帧接续等方式，目前用户已有明确约束；本提案不直接改变门槛。将来如调整，应显式约定适用范围并实测，不能用教程意见自行覆盖。

### 先验证最难的能力

正式制作前，在有限预算下单独验证关键反应、同角色换景别、道具交互和带对白片段。试验不冒充生产序列通过、不直接释放尾帧给后段。确定合适的模型／参考方式／画风后，再按既有授权从首段顺序制作。

### 无错误与好看分别验收

技术门槛继续保留。观感记录另回答：开场为什么值得看；每段增加什么；情绪是否在正常播放尺寸可读；重复操作是否拖慢；结尾是否由人物反应兑现。每项都要秒数和实际证据，不只写“电影感”“情绪饱满”。未检为待检，视觉先行授权不自动扩展。

## 六、可复用成功的验证方式

建议：同一流程版本、三个不同创作简报，实际完成三部通过声画与观感审核的短片。可覆盖亲情、职场、陌生人关系；记录全部尝试、首稿／首段成功率、返修次数、生成素材时长、费用证据和人工介入时间。

只改简报和由它派生的资产，不手改执行器的角色名、目录和镜号条件。若每个故事都要写专用代码，复用不通过；仅文本或静态图通过，视频不通过；从大量失败里挑三个好结果而隐去尝试，不能称稳定成功。

这是建议的新验收范围，尚未执行。先用代表性短片验证，再扩展到目标样片约104秒的规模；短片通过不能自动外推到长片。复用意味着判断有稳定的位置和输入，不意味着任意一句话都保证佳作。

## 七、实施优先级

1. 统一当前状态索引，区分历史链、通用链、单片实验及实际退回状态。
2. 建立创作简报与角色／场景／镜头清单，移除专用目录和镜号区间判断。
3. 修复分镜到请求的语义传递；历史案例迁到回归集，按任务注入约束。
4. 增加画面审美定向与节奏预演，在上游减少无叙事作用的操作步骤。
5. 有限媒体验证后，按现有规则逐段生成、真实听看。
6. 同版本跨简报验证完整成片，之后再扩大范围。

本轮没有重生成旧片、变更生产代码或将提案标为已验收。
