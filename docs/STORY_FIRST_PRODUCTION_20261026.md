# 剧情先行、调度后补的独立生产路线

2026-10-26，用户要求修改流程、测试后直接生产测试。

## 路线

完整原章 → 基础人物关系/地点/约束 → 剧情和带音轨类型的对白 → 独立站位、进出场、动作、持物和知情变化 → MiniMax 全量交叉审核 → DeepSeek 全文内容/时长双审。

前序使用 MiniMax-M3.1-Flash，adaptive/medium，输出上限 16384；不调用 Qwen。使用官方 function tools 的 submit_result 接收文本结果，本机 jsonschema 与业务约束再验证，不声称工具调用能保证语义正确。DeepSeek 只在最后两审调用。完整源章节和原始响应保存，未知调用不重放。

审核引用程序生成的字段证据编号，绑定候选 SHA。空值不等于否定。审核失败定位 foundation/story/staging，作废责任阶段及下游；单次协议修复、最多两轮责任返修，所有旧稿和意见保留。最终稿由结构化产物确定性渲染，避免额外整合模型改写已审对白。

## 入口和边界

`scripts/run_story_first_production.py` 新 prepare 默认 v2；execute 按已冻结 PLAN 选择 v1/v2。旧 corpus/Fanqie 任务和网页没有自动迁移，账号服务未重启。这是独立完整源文本路线，尚未接入真实长篇全章材料归并链，不能把三章小样结果外推为 69 章验收。

来源仅合成《两把钥匙》三章 399 字符，沿原已授权来源创建独立任务。没有发送此前拒绝的真实小说 69 章，没有生成媒体或发布。

## 已验证的工程行为

77 项新旧回归通过，见 `data/qa/story_first_20261026/all.xml`。覆盖原场景人物遗漏、场景地点、出入场/状态动作绑定、对白类型和时段、空值证据、审核候选绑定、责任返修、未知请求保护、篡改拒绝等。模拟回执测试不等同真实模型成功。首次 pytest 临时目录父目录不存在，失败记录保留；创建父目录后测试通过。

v1 真实调用 4 次 MiniMax、49,326 reported tokens，调度漏人物先被程序拒绝，协议修复后通过。随后完整稿、重复渲染和重复字段值使审核请求超过容量门，在 HTTP 前停止，DeepSeek 0 次，pending=null。原任务保留在 `data/corpus_production_trials/20261026_story_first/run`。

v2 保留完整 artifacts，证据表改为列定义和紧凑地址行，移除重复字段值及重复渲染文本。相同 v1 候选的保守请求界从超过 131072 降为 89168；没有截断正文或抬高容量门。v1/v2 实现分别快照留存。

v2 真实执行与最终主助手复核结果见 `data/corpus_production_trials/20261026_story_first_v2/run/RESULT.json` 及该试验目录的 `PRIMARY_REVIEW.json`；文件未产生时不代表通过。

## 限制

程序校验明确字段和引用，不能自动证明模型写全了所有人物、道具状态和物理动作时长。关系与状态的语义、动作能否在指定时间完成仍须独立审核与主助手复核。没有“无任何 bug”的保证，文本通过也不是视频验收。

## 最终真实结果

v2 实际 MiniMax 8 次、157005 reported tokens，7 次 tool_calls、最后调度返修 1 次 length，pending=null；不是未知调用。完整候选60秒生成并进入MiniMax审核，但调度返修被截断，DeepSeek实际0次。主助手审查仍为 needs_revision：空间措辞、钥匙去向、状态保持/变化等问题未通过；审核对继母称妈和整句音轨起点的部分判断依据不足。没有完整通过稿。

本轮v1+v2共12次、206331 reported tokens（含失败），Qwen0、媒体0、发布0。原Tool Use试验22份文件SHA保持，两个失败任务不得重跑。建议下一轮按固定场次拆分调度输出和责任返修，同时校验跨场状态；不以提高上限或手改稿冒充验收。新增紧凑索引逐字段可逆性测试通过，累计78个不同相关用例通过。
