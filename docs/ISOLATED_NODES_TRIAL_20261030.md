# 独立提示、独立请求与返回合同：一轮测试

用户要求按一个节点一个会话尝试，并关注 token 成本。本轮仍为声音、画面、审核各一次，没有新增反思或重生成调用。

## 实际改变

底层原来就每次构造独立的 system/user 消息，没有传递前一节点聊天历史；本轮没有把“原来共享聊天”当既成事实。实际变化是 isolated_nodes 为三个节点各自定义精简提示，取消提示拼接，精简节点间传递资料。

- 声音输入仅原文，输出 items。
- 画面输入原文与声音必要字段，不再传证据原文副本、上游检查备注或审核提示，输出 text/gaps。
- 审核输入原文、待审内容、声音出处索引、缺口和程序问题，只返回审查 text。

声音提示明确保留间接叙述中的必要告知，允许原句作旁白。画面缺口报告不自动触发新调用，当前仍由审核核对，不是自动返修闭环。

## 结果与缺陷

声音节点保留了去融创乐园的间接告知A070，旧因果缺口本次改善；但A001“嗯嗯”又署给刚发表意见的叶东，归属缺乏上下文支持。

画面15场，仍把学校同学裙子的见闻写成商场当下衣橱内容，仍补“商场外便利店”。系统提示触发苏墨看向叶寻，被改成察觉视线；关注孩子的动向又被具体化为护住跑散孩子。

4条gaps主要是点头、回头、点单/椰汁和摇头。可见动作不因缺配音就成为声音缺口，部分还已经画出来。当前提示“需要表达而声音表未提供”边界不够清楚，是明确的节点内需求歧义，不是前一节点聊天混入的证据。

原生画面用波浪号范围、同一行多个声音ID及额外“地点补充”。当前行协议不支持，格式检查失败，未渲染有效剧本。只读检查94个声音ID实际按顺序各出现一次；程序actual为空是未识别写法，不能说模型漏掉了全部声音。旧失败保留，323审查原始画面与声音，不重生成、不伪装格式通过。

主助手读完整输出后needs_revision。审核发现一些错误，也仍有误判：火锅提问的顺序理由不成立；音画分组不是信息缺失；不能猜待核声音是某个孩子；旁白承载心理合法；原段行不是本次格式失败原因。

## 结论

独立提示和精简传递可保留，本轮成本基本持平。返回字段没有串用，但声音归属和画面语义仍不可靠，不能将错误全部归因于提示混杂。下一步应精确界定“只有声音才能传达的缺口”，并让输出合同容纳合理分组形式；不得靠格式容错冒充语义验收。
