# 普通动作与表情的快速呈现规范

用户进一步要求压缩信息与时间比例：普通动作/平淡表情直接展示到位状态，不需把每次轻微变化慢慢演一遍。此规范用于后续新版本的编剧、导演、分段与最终请求审核，不覆盖已冻结v10代码、已审正文、SDK请求或旧账本。

1. 普通表情起镜即成立。平静、防备、疑问等状态直接可读；只在新信息触发重要情绪变化时给转变窗口，不机械安排每人从中性脸逐步变化。
2. 取物、收物、转头、抬眼、起身等功能动作随对白推进；允许切镜省略已能理解的过程，保留动作结果和前后物件位置。走路仍须符合空间距离，省略不等于瞬移。
3. 普通动作不拆成独立5–8秒服务段。按完整互动合并，一个段应承载有意义的交锋/判断/关系变化，不为每个动词分配单独时窗。
4. 关键反应仍清楚可见。刺激到达、听懂/做决定的反应及下一回应要承接；可在对方说话时拍听者。避免强求吸气、落泪、擦泪、起笑等整套顺序表演，选择最有效的反应。
5. 静物与收尾服务于理解。票、通知等可随传递短暂清楚呈现；一次挥手与回应即可收束时，不再叠加多段远去、空景和同义动作。
6. 压缩主要靠删重复、合并互动、动作对白并行及普通状态直接呈现。保留的长对白仍需自然说完，不能全稿按比例缩秒、变速播放或塞进更短服务段。
7. 审核同时查看信息密度与局部容量。整片长不代表每段都松；旧稿有普通动作偏长，也有长对白局部过挤，应回收前者给后者留足时间。目标总长不能靠无信息停顿凑齐。

8. 以最后有效内容结束为切点。对白、必要动作和关键反应都完成时立即收段，不另留固定的“看一眼／点一下／保持表情”尾窗。普通回看和轻微意外可随递物、最后一句对白同时完成，或自然接入下段；不能用新增小动作填满原时长。
9. 新任务的总长是参考估算，内容完成可以更短；用户明确冻结的最短、最长、目标加容差仍是硬约束，冲突交回创作删合或重新分段，不由整理员和编译器偷偷改秒数。服务时长选择能自然完成互动的整数档；低于服务最短档时合并相邻内容，不制造空等。
10. 实际请求跟随所选分段时长，不能继承专项试片的10秒或15秒常量。Seedance Mini实际提示词按动作顺序组织，具体小数时间表只留在内部规划；审核核对最后有效内容之后还安排了什么，并给出保留停顿的具体理由。
