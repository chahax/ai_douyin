# 番茄多章剧本自动返修流程 v2

用户纠正“不是让你改的是流程”。此前助手直接修改《我没偷》的稿件保留，但不是自动创作流程的验收结果。本次修改的是当前番茄多章分析与剧本 CLI 的通用审核返修逻辑，不手工修改本次模型正文。

## 接入范围

`scripts/run_fanqie_corpus_workflow.py` 仍使用原专属环境获取全部可读章节，调用 `corpus_screenplay_v1.prepare/execute`。新准备任务的计划版本为 `corpus_screenplay/v2`，默认进入 `screenplay_review_cycle/v2`。

`scripts/run_corpus_screenplay.py` 同样接入新流程。新增 `prepare-rework` 可将已经收到完整终态的旧 v1 失败模型稿交给新流程检验，核对原编剧回执、全文审核请求、来源SHA和累计消耗；旧任务没有解除或重领。此迁移入口只支持明确的旧 v1 终审失败格式，不声称所有历史任务均可迁移。

冻结的 v1 任务保持原语义。旧网页自然导演 v10、其他历史创作入口及媒体派发没有因此全部迁移；番茄账号网页的采集按钮本身也没有变成自动模型调用按钮。本次新 CLI 进程已实际加载代码，未重启账号后台服务。

## 新流程

1. 保留全部已获取章节的分批分析与选段；选段前后章原文一并作为审核范围。
2. MiniMax 负责完整自然文本创作。返修不靠助手手改正文。
3. DeepSeek 全文审查，分开输出硬伤与可选建议，回传准确稿件SHA和全部审核章节。
4. 程序核对稿件、章节范围、原文引用、稿件引用、检查项与结论的一致性。审核自身的证据或结构错误先交回审核，不交给编剧改剧情。
5. DeepSeek 再次阅读全文并复核前审，核对误判及遗漏。该阶段仍是模型判断，不是确定性事实证明。
6. 复核后的硬伤和程序发现的明显局部时长超限进入 MiniMax 的完整返修。可选建议不会被作为强制返修项输入。
7. 每份新稿重新全文审查及复核，不能沿用旧稿通过结果。最终交付绑定稿件SHA与审查/复核记录。

正常新流程最多两轮完整返修。计划提前为分析校订、全文审查、审核错误校订和返修预留内部执行上界；提前通过就结束，达到上界仍失败则停止，不无限调用。传输未知保留请求ID和pending，不重派；已收到的截断或拒绝响应仅在原生ID、终态和用量可核对时结算为已知未通过，不自动重试。

## 修复的通用问题

- 旧 `issues == []` 把可选建议与硬伤混为一谈；新结构分别存放，严格对应fail检查项。
- 审核曾把4—6章候选选段误填成3—7章完整审核范围。审核请求现在明确给出完整范围，并移除容易混淆的候选索引；错误反馈包含expected/actual。
- 审核不能引用不存在的原文、错章引文或其他版本的剧本来指导返修。引用存在不等于其解释必然正确，因此保留模型复核和真实验收边界。
- 明确人物不在场、无过渡换地点、人数矛盾、关键转手缺环的审核责任；原文动作顺序不同本身不自动算错误，须检查实际物理依赖和人物知情。
- 分段统计不再仅提供整片字数。对可识别的秒数标题逐段计算对白单位和自然语速区间；即使按每秒6单位都明显超时也必须返修。6只是宽松的超限筛查线，不是推荐语速；停顿、串行动作和证据可读性仍需语义及音画验证。
- 每轮保存局部约束证据。没有可识别时间标题不会被称为“程序已验证时长”。

最后模型稿仍有“你给我的二十块”的指代/钱款归属问题，以及83—90秒结尾严重超时。最终复核退回，并未将两轮返修完成当成通过。人物在场等问题也仍暴露出模型分类不够稳定，不能宣称通用创作质量已经达标。
