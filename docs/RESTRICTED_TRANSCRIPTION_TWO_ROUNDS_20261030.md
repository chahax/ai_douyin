# 视听转写两轮修改与真实测试（2026-10-30）

## 目标与检查结论

用户要求先检查流程再修改两轮。完整第19章为上下文，完整20/21章为目标，两轮输入逐值相同。沿story-pipeline-debug进行原请求/输出/完整原文核对。原转写调用同时承担背景概括、人物归属、心理转换、场景和演出设计，换名并没有实际限制这些职责。

## 第一轮

新增 restricted_transcription 与 run_restricted_transcription。背景由程序按关键词摘录完整原段并保留id/角色/context；是制作参考原文索引，不是自动理解完成的世界观。内容不直接配音。转写只生成有类型的音画正文：画面、对白、旁白、场景信息；心理用旁白，未知说话人只标待核。模型仍看完整原文，不看自由摘要。

程序回归13项通过；MiniMax-M3.1-Flash medium 两次（转写+独立对照），29,780 reported tokens。26场原生输出，格式通过不代表语义通过。主助手完整检查needs_revision：姐姐夸赞交给叶嫣儿本人；五男孩场次漏叶寻；男孩换衣和袁军疑问顺序改变；新写乐园附近便利店；若干心理因果/孩子摇头缺失。审核捕获部分，但把普通动作及系统字卡过度判错。

## 第二轮

根据第一轮原因增加逐条音画原段锚点、对白原句匹配/实名局部证据、场次必需字段和源段顺序诊断。审核收到程序从原文构建的逐句证据表。引用命中不代表语义证明，不自动放行。

回归14项通过后真实同源两次，47,726 reported tokens。15场，原文背景保持；女孩自称姐姐不再出现，留待核；五男孩漏名、换衣顺序、孩子摇头与袁军疑问顺序改善。仍needs_revision：地点写商场便利店，点菜省略号误演一时语塞；待核备注仍把说话人限为哥哥；个别动作先后改变。

同时发现119个音画/系统锚点抄用了提示格式示例CH2并连续编号，不能简单改成CH20：序号已被模型当镜头计数。程序正确拦截；提示词使用真实风格虚构编号是开发设计缺陷，不能只归咎模型。另7处说话人证据不含姓名/对错段号，不等于7个角色归属都错。2处台词是正常间接问话/感叹加标点，原检查过严。

## 测后修复（无第三轮真实调用）

移除具体虚构ID示例，改为字段占位说明并附本次允许源ID清单，增加发送前检查示例ID是否属于原文。对白引用允许末尾问号/句号差异，仍拒绝内容改变。15项回归通过，原输出离线复核仅清除2个标点误报，保留119个错误锚点和7个证据问题；不覆盖原VALIDATION。新提示未再真实验证，不宣称引用生成已修复通过。

## 结论与限制

两轮开发与完整候选审查已完成，4次调用77,506 reported tokens，累计308/5,786,462已知tokens，pending=null。原304工程边界沿本次两轮授权增至308，无重置账本。没有继续第三轮、手改剧本、媒体生成/发布、后台重启或生产默认迁移。

背景身份乱写可通过取消自由背景重写直接规避；旁白与心声混淆通过明确音轨职责改善。人物对白、地理关系、心理动作仍有语义错误，不能靠格式校验替代原文理解。带出处让问题更可追踪，但也增加生成负担；本轮证据不支持继续无条件增加字段。后续应评估将源段引用交由程序绑定，模型只处理当前源段的音画表达并保留全场上下文，而不是让模型同时重编段号。这是待评估方向，尚未实现。

第20章参与过历史开发，本批不是独立留出，69章整链未验收。背景摘录不等于成片世界观介绍，待核对白也不等于可直接配音。
