# 异常提示人工关闭与再次展示（2026-10-18）

用户补充：异常在前端展示即可，人工判断无异常时可关闭；之后再出现异常重新展示。

本轮在现有账号后台异常待办上增量实现。关闭当前异常是人工处置记录，不是删除历史、永久静音、改写任务结果、确认登录有效或恢复后台运行。原账号暂停、身份核验、未知任务、锁、预算及媒体权限保持。

先文档、子 agent 按后台/前端实施，主 agent 审查、回归并部署。保留当前工作区其他修改，不触碰同时推进的创作任务。

## 后台合同

- 按不可变 issue_id + account_uuid + account_key 精确关闭当前记录；显式操作者及说明（默认人工判断无异常）入处置审计表，原消息与运行回执保留。
- 仅 open 转 closed；重复关闭幂等，跨账号拒绝，不能按错误码批量永久屏蔽。
- 后续同账号同错误码的新异常仍生成新的 open issue。关闭旧条目不能消掉并发到达的新异常。
- snapshot 返回关闭元数据供历史查看；现有库增量建表，正常查询继续走只读 schema 快路径。
- API 约定 `close_account_issue(issue_id, account_uuid, account_key, *, closed_by, note='人工判断无异常，关闭本次提示', path=DB) -> bool`。

## 前端合同

- 默认只展示当前 open 异常，管理员可逐条“人工确认并关闭提示”，不用逐条请求助手批准；其他角色只读。
- 已关闭/已解决记录收进历史，可查看操作者、说明和时间。
- 账号状态仍如实显示 paused；已关闭的旧原因不继续作为待处理 warning 挂着。不以技术状态旧值重新生成待办；新的实际异常事件照常再次展示。
- 关闭提示按钮不调用平台、不触发恢复或模型。请求恢复继续沿原身份探测入口。

## 验证

持久关闭与审计、重复关闭、账号隔离、保留原暂停及 run_id、同错误新事件再次出现、关闭旧条目不覆盖新事件、前端范围/权限/历史折叠/不误报和原相关回归。部署只重启已核实空闲的网页后台，不结束其他制作进程，不真实重探账号。
