# 番茄推广架构开发：第一批实现

依据[架构规范](FANQIE_PROMOTION_ARCHITECTURE_SPEC_20261024.md)，本轮开发可复用的账本、身份合同、发布证据和回填执行基础。**生产调度尚未启用，不能据此称番茄闭环已上线。**

## 已实现

| 文件 | 实现 |
|---|---|
| `src/services/publication_evidence.py` | 统一读取原成功发布和现有独立核实后的成功记录；核对原账号/版本、原未知快照、核实命令、冻结证据文件 SHA 及结果关联；命令更新时间不再改变作品证据身份 |
| `src/services/fanqie_backfill_workflow.py` | 首版准备入口复用统一证据读取；新增实际 XLSX 行/字段/公式检查；明确区分执行前有效性检查与过期任务的只读核实 |
| `src/services/fanqie_promotion_ledger.py` | 在原 P0 数据库内扩展合同和 outbox，不另建生产任务库；任务状态仍在 `fanqie_bindings`，事件追加到 `fanqie_operation_events`；稳定业务键、作品唯一性、授权准备版本、CAS 阶段迁移和幂等命令投递 |
| `src/operations_accounts/platform_bindings.py` | 独立番茄身份与专属环境的持久绑定仓储；要求稳定身份探测及明确身份确认依据；按当前绑定、owner、generation、心跳和实时身份检查执行归属 |
| `src/services/fanqie_backfill_coordinator.py` | 原准备记录执行，上传前占位；区分上传就绪、提交、平台已接收、待核实、确认成功和未知；只读核实可结案原未知，不重传；同作品已存在时持久结案 |
| `src/operations_accounts/fanqie_backfill_control.py` | 可供独立番茄资源注册的 handler 工厂与真实命令 guard；原命令、原绑定、业务键和准备摘要必须匹配；没有注册进现行抖音后台 pump |
| `src/platform_adapter/fanqie_managed_page.py` | 将项目 tab-fenced Page 代理转换为批量表单需要的角色定位、嵌套定位、上传、可见/可用检查及刷新；URL 从原 worker 实时读取，失败不退回缓存 |
| `src/platform_adapter/fanqie_backfill.py` | 上传后等待提交控件就绪；选中文件本身不算上传完成；点击提交仍不冒充平台已接收批次 |
| `scripts/inspect_fanqie_ledger.py` | 只读检查当前账本；可在新的项目内目录制作一致性副本，迁移副本并核对所有原表，不修改生产库 |

身份与授权仓储目前是内部服务接口，尚无前端确认入口。测试中的身份探测、推广路径和平台接收结果均为隔离 fixture，不是当前番茄账号的生产证明。现有平台任务 ID 和 alias_id 分开保存，不假设两者相等。

## 迁移和状态规则

账本构造函数只读，不自动建库或迁移。显式迁移先检查旧表结构并备份，再事务内创建扩展表、校验唯一约束和登记版本；不覆盖旧行。第一次和最终结构版本的副本演练均通过，最终证据：

- `data/qa/fanqie_ledger_migration_20261024_02/REPORT.json`
- 原有 **28 张表**的记录摘要全部保持，SQLite `integrity_check=ok`。
- `production_migrated=false`，原业务库未执行迁移。副本和备份只留在项目内。

一次回填的权威状态在原 `fanqie_bindings`，合同扩展表只保存不可变准备、授权、并发版本及批次关联，不维护第二份业务终态。旧 `BackfillStore` 保留为首版原型与历史测试接口，没有切换成生产调用。

命令投递复用现有 BrowserControlStore 的 `(account_id,idempotency_key)` 唯一性。业务 outbox 写回前崩溃时，重复投递得到原命令，不创建第二个外部动作。外部动作开始后没有自动重试入口；服务重启留下的阶段可只读核实。

当前 `uploaded` 表示页面提交控件已经就绪，其证据明确标记 `submit_control_enabled`；平台受理批次是之后独立的 `accepted`。没有批次接收证据且列表未读到精确作品时保留 `outcome_unknown`。

## 尚未接通的部分

1. **真实番茄身份探测与绑定 UI。** 仓储和 guard 已有，但页面端稳定 ID 的可靠读取器尚未完成；不能把昵称转换成稳定身份。跨平台账号关联及其版本的前端确认/生产准入也待接入。
2. **真实推广元数据和批次核实。** 当前页面适配器尚不返回已证实的 alias_id、推广路径和批次/行结果；协调器遇到缺少这些字段会在上传前阻止执行。需要实际页面契约后开发，不猜内部接口版本。
3. **发布元数据来源和成片接入。** 日期/展示抖音号的来源、已有成片审核、任务申请及发布记录的统一导入仍需应用层接线；内部仓储接收的来源引用不能替代这些校验。
4. **生产资源和后台调度。** handler 工厂不是已启动的番茄 owner。需专属资源、调度注册、状态页面和受控恢复接线后才能开启；现有全局番茄缓存浏览器没有自动迁入新环境。
5. **单条真实验收。** 要选择已审核成片、对应生效的 AIGC 推广任务及明确操作范围。此前已授权的范围按原记录复用，不扩大为无限发布/回填。

本轮尝试只读核对现有番茄页：标签页清单能返回该页面，但两次内容读取超时，没有得到本轮账号/推广任务的新证据。未刷新、关闭、重新登录或提交该页面。此现象是本轮浏览器读取阻塞，不能据此判断项目后台服务故障或账号失效。

## 后续开发入口

先补真实身份、推广任务和批次结果读取，把来源绑定到上述仓储和 guard，再完成前端准备/确认/状态入口；随后在副本完成集成和恢复测试，才部署生产迁移及一次真实验收。现行服务不因这批源码自动重启，旧账号暂停、未知任务及历史审核保持。
