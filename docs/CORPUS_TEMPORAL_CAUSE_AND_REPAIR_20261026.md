# 两处时间标签混淆：原因、修复与真实复验

用户要求“纠察下错误原因，仍有两处时间标签混淆，这个看下”。主要问题是材料命题的时间判定对象没有讲清，以及合并规则与单个时间字段之间存在冲突。没有输入过长、输出截断或原文丢失的证据。

## 原因与影响

旧分类合同每条事实只有 `statement + modality + event_time` 一组字段，但提示词允许“保留相互关联的动作因果”，没有要求合并的命题必须具有相容的时间与语气。`event_time` 只列了当下、此前、未来等枚举，没有说明遇到嵌套表达时究竟标注说话、回忆的行为，还是表达中提到的事件。

| 旧输出 | 问题 | 本次真实新输出 |
| --- | --- | --- |
| 第2章：“林岚告诉阿禾现在收下钥匙，并计划明早开柜子”，整条 plan/later | 当前表达、交付与未来计划合在一起，只能填一个标签 | CH2-F003 当前表达 actual/chapter_present；CH2-F004 明早开柜子的安排 plan/later，并明确尚未执行 |
| 第3章：“阿禾告诉父亲，钥匙是林岚昨天给的”，标 actual/earlier | statement 描述当前告知，标签却取了话中交钥匙的时间 | CH3-F003 当前交信/告知 actual/chapter_present；CH3-F004 昨天交钥匙 actual/earlier；CH3-F005 父亲现在获知 actual/chapter_present |

旧引文和来源都正确，枚举也合法，因此 JSON、引文、覆盖校验会通过。这些检查没有能力证明“标签与命题语义一致”。旧实测也没有进入 Qwen 材料语义审核或 DeepSeek 终审，不能说审核已经看过却放行。

下游确实使用这些标签：只有 actual 且 chapter_present/timeless 才可能作为当前状态候选。把当下告知误标成 earlier，会使该事实被当前状态门拒绝。但原稿另有“父亲这才知道”事实，因此不能据此声称这次父亲知情信息已经完全丢失。

## 通用修复

新增 `corpus_temporal_policy_v1.py`，生成和独立复核共用明确口径：时间与语气跟随 statement 所断言的主体命题；当前表达与过去/未来内容必要时分别登记。人物实际说过不等于所述事件客观成立。前序分类继续保留完整作者章节及完整邻章，不新增实体表、持物/知情状态数组。

抽取 schema 的字段描述同步解释判定对象。材料审核专门检查主体、标签与内层事件是否混淆；后续框架、快照、编剧和终审获得对应的时间解释规则，材料阶段的“不生成状态数组”限制不会错误传到快照或编剧阶段。

首次仅修提示的 v8 实测3次/16107 reported tokens：第1章通过，第2章拆分事实后把句子顺序当成自然段顺序，引用地址错误；一次返修重复地址错误并停止，第3章未调用。旧正文与只有 ID/偏移的目录分离、返修只给笼统来源错误，是这次失败的具体证据。原记录完整保留，不能写成成功。

后续 v9 新增 `corpus_reference_view_v1.py`：完整章节正文不变，来源目录直接展示每个固定原段 ID 对应的原样文字；一个原段含多句话、多条事实也不能重新编号。来源拒绝反馈指出事实 ID、字段位置、声称的原段和所有精确匹配的原段；有多个匹配时全部列出，不替模型选择、不改写输出、不放松原校验器。

## 最终实际结果

- 模型保持 **MiniMax-M3.1-Flash**，相同 adaptive/medium/16384 输出策略。
- 原《两把钥匙》三章：3次真实调用，15255 reported tokens，44.478秒；全部来源与格式通过，无返修。
- 另一份合成测试材料：1次真实调用，5186 reported tokens，16.013秒。覆盖当前表达、未来计划、告知过去内容、回忆、猜测、叙述者确认的往事，以及“声称买票但实际没买”的谎话。
- 最终4次共29项事实、30条精确引文、22个原段，全部 stop、pending=null。主助手逐条读原文与原生输出，确认本次所问的两处混淆已在新输出中纠正。
- 加上保留的前一版失败，本轮总计7次真实调用、36548 reported tokens；没有真实小说外发、Qwen/DeepSeek实际调用、完整剧本、媒体或发布。

这不是所有时间表达的全面验收：测试材料的回忆、猜测项仍以“回忆起/猜测”作句子开头，时间指向内层内容，虽可从 memory/belief 理解，文字范围仍应更明确。临时场景带 world 标签偏宽也未在本次专项修复中处理。记录这些限制，不把引文通过当作语义全部通过。

最终回归 **377 项通过**，包含新规则实际派发、完整章与邻章保持、错误地址反馈、不改写输出、失败与未知不重派、模型路由、旧版本兼容以及全链模拟原生响应。一次测试断言误以为引文只在本章出现，实际邻章有相同原句；修正测试以保留两个匹配地址，未修改生产校验放行。失败 XML 保留。

新 corpus/Fanqie CLI 默认 v9；M3.1 固定使用偏好保持。旧 v3—v8 冻结任务仍走原路线，旧网页入口未迁移，账号后台未重启。49份此前文件及38份首次失败版本文件的 SHA 核对不变。
