# 小说连载剧本生产规范 v1

日期：2026-10-26。状态：需求与实现方案已整理；本文件不是部署或生产验收记录。

## 目标与边界

将已获取小说转为可持续生产的连载长剧本，按剧情分集，再按镜头拆成视频生成片段。不能把全部章节压成一个固定60秒故事，也不能把视频模型的单次时长当作单集剧情上限。

当前来源为《你敢惹我？我有六个反派儿子》第1—69章、150,503字；只代表已获取范围，不代表全书完结。未获取部分不得补写成已知原作事实。总纲可覆盖当前材料，后续新增章节形成新的材料及总纲版本。

用户已确认连载方向。本轮只落地规范，不调模型、不生成媒体、不发布；原真实小说外发拒绝及历史执行记录保留，未将本轮方向确认写为外发授权。

## 层级与产物

| 层级 | 产物 | 必须保留的内容 |
| --- | --- | --- |
| 原文 | source_manifest | 书籍、完整章节、顺序、原文SHA、可读范围与缺章情况 |
| 章节分析 | chapter_materials | 世界、人物、环境、事件材料；原文地址、引文、时间及事实性质；遗漏与歧义 |
| 全局归并 | series_bible | 世界规则、人物身份及别名、关系发展、地点层级、事件因果及时间线、待确认矛盾 |
| 美术设计 | visual_bible | 整体画风、时代与生活条件、人物服饰、场景风格；原作事实与美术补足分列 |
| 连载规划 | serial_outline | 篇章主线、人物成长、核心冲突、事件依赖、已获取范围的结尾边界 |
| 分集规划 | episode_plan | 本集事件、来源、开场状态、冲突推进、阶段结果、悬念、后集承接、预估时长 |
| 分集剧本 | episode_script | 完整剧情、场次、动作神情、对白、音轨、镜头意图、时长与状态变化 |
| 镜头拆分 | shot_plan | 生成片段的内容及长度、关联场次、人物场景资产版本、连续性要求 |
| 后续媒体 | episode_media | 片段、合成、音画检查、分集成片与发布记录；本规范不启动该阶段 |

稳定标识串联书籍、篇章、剧集、场景和镜头。每个产物记录输入版本、证据地址、生成请求及候选SHA，不能只靠文件名或自然语言摘要衔接。

## 分析与容量

1. 按作者完整章节分析，不按固定字数截断原章。自然段仅作证据定位。邻章上下文需要时带入，并明确归属，不计为本章事实。
2. 全部已获取章节必须有分析状态。缺失、失败、歧义不能用总纲掩盖；本轮以全部69章分析完成、归并检查完成为总纲验收前提。
3. 材料分类阶段不要求穷举影视站位、镜头和道具状态；进入某一集后再根据实际演出补齐这些细节。
4. 跨章按实体、地点和事件归并，可分批后统一核对，但每项保留原章地址；不能把摘要当作唯一事实来源。关键关系、转折、误会及证据冲突回查原文。
5. 每次请求检查实际输入和输出余量。完整单章超容量时显式停止并调整方案，不静默裁切；不能靠放宽旧容量门强行发送69章全文。

## 长剧本与分集

先完成连载总纲与分集规划，再逐集扩写，最终可导出按集排序的长剧本。无需一次调用写完所有正文。

分集依据事件和情绪推进，不要求一章一集：一个完整事件可以跨章，同一章也可以拆到不同集。来源范围允许重叠，必须说明回顾、不同视角或承接用途，避免重复灌水。

每集写明“观众新知道什么、人物做出什么选择、关系或局势发生什么变化”。开头尽快建立人物关系、环境与当下矛盾，动作与信息同步推进；不为凑秒数安排空等或无意义特写。悬念须来自已有剧情，不能伪造原作事件。

时长由本集内容和发布需求确定，允许各集不同。先预估，完成对白和动作后再测量。超时优先检查冗余、重复解释和场次拆分；不能任意提高语速、删除必要因果或把全书缩成一分钟。

## 分集内生成与跨集承接

每集先固定剧情和对白，再逐场细化调度。每场注明故事时间、地点、在场人物、起始位置、动作神情、道具转移、人物获知信息、音轨及结束状态。

跨集承接使用上一集已审核版本的结束状态，并记录时间跳跃及其依据。人物、服装、地点和道具资产引用固定版本；新服装、换地点或物品消失必须有剧情解释或明确镜头转换。

历史事件的发生时间、当前人物回忆/获知时间、画面时间、配音时间分别记录。当前旁白不能改变历史画面中人物的知情状态；观众已经知道，也不等于角色已经知道。

可视化设计要能快速传达关系及生活环境：家庭的生活痕迹、空间布置、光线和人物互动应相互支持。近景用于表情、判断和关键信息；推拉与切镜有明确叙事用途，避免无动机跳变。

## 视频片段与发布单元

单集是叙事单元，镜头片段是生成单元，平台发布作品是发布单元，三者分别建模。允许一集包含多个生成片段；若一集需要拆为多条发布内容，应增加明确的子段顺序与承接，不把随机截断当分集。

镜头拆分在剧本通过之后，依当前选定模型能力确定长度。完整对白和关键动作优先保持连续，避免在说话、交接道具或人物进出过程中机械截断。首尾帧仅在镜头需要连续时衔接，正常切镜以场景和状态一致为准。

片段间检查人物数量、服饰、空间方向、持物、口型、音色与声音接缝。补帧只能处理部分运动衔接，不能替代剧情连续性修复；音频另行校验处理。

## 模型职责与审核返修

前序分析、归并、设计、编剧和交叉检查拟固定 MiniMax-M3.1-Flash，Qwen不自动参与；DeepSeek负责每集完整候选的最终内容与时长审核。真实派发仍需具体来源及目的地授权，现有旧调用额度不重新领取。

程序做引用、结构、完整性、状态承接与可测时长校验；模型做语义判断。通过结构校验不能称内容通过。终审绑定同一完整候选SHA；长集超过上下文时必须调整审核设计，不得裁去前后文仍称全文审核。

审核意见绑定候选字段、原文证据、时间线和责任阶段。证据不足的意见进入澄清或核验，不直接驱动编造事实。区分硬错误、风格建议与不确定项。

返修按责任回退：原文理解错误修对应章材料；关系/世界错误修全局资料；主线或分集问题修总纲/分集；对白和因果问题修该集剧本；站位、持物或音轨问题修对应场。记录依赖并使受影响下游失效。上一集结束状态改变，检查后续集依赖，不默认全部重跑，也不继续使用过期状态。

保留全部候选、失败、审查与用量；未知调用不盲重派。不得手改模型正文后当自动化验收通过。

## 接入现有代码与验收顺序

当前 story_first_production_v5 仍是短篇完整原文入口，目标限制10—120秒，不能直接承担此连载规范。当前 corpus 旧路线也没有接通“连载规划→多集→逐场”。此文档不代表上述能力已实现。

后续新增独立连载协调层及版本合同，复用经过验证的原文证据、请求账本与逐场状态机制；不能只调大 target_seconds 或将69章交给旧入口。旧冻结任务按原版保留。

实施顺序：来源和章节覆盖合同 → 全局资料及分集规划 → 可变时长的分集生成 → 跨集状态和局部返修 → 镜头拆分导出。现有时间线语义混用问题须在接入时修复。

验收分开记录：离线程序测试、真实69章分析、总纲与分集语义审核、首集完整剧本审核、至少相邻两集连续性检查。首集通过不能宣称全部连载已通过；文本验收不能宣称视频或发布完成。
