# 账号后台运行、会话复用与异常人工处理（2026-10-18）

## 用户目标与范围

复用已登录账号的独立浏览器环境；标准启动器带起后台任务，前端关闭不停止服务。出现异常时持久暂停受影响账号，在前端自动更新原因、最近运行与人工处理入口；人工处理后先核验原身份，再恢复后台计划。持续运行不能保证平台永不撤销会话，也不能把安全验证误写成登录过期。

本轮是正常代码修复与本地验证，不新增自动点赞、评论、媒体、发布或付费创作任务。不自动重派未知外部任务，不改旧生产冻结、预算及历史回执。先由子 agent 按模块实施，主 agent 审查实际接线与回归。

## 已观察问题

- `scripts/run_streamlit_web.py` 已启动后台调度；同步与智能运营策略分别为 4 小时、24 小时。
- `account01` 最近同步因旧 `blocked` 状态在读取真实页面前停止；该状态不等于 cookie 已过期。
- 通用队列日志提示旧数据库缺少 `task_executions.claim_owner`；需核对迁移并修复启动预检，不能删表重建。
- 当前自动更新失败按时间重试，缺少持久人工待办、暂停/恢复控制与前端周期刷新。

## 实施边界与模块

1. 会话与错误分类：保留每账号 profile 和 storage state；核对保存/恢复，不以旧快照覆盖新 cookie。维护结果增加 `error_code`。旧 blocked/expired 仅在明确恢复探测中读取原会话并核验绑定身份，失败不得恢复业务任务； mismatch 不自动换绑。区分过期、安全验证、身份不可读及普通网络问题。
2. 持久后台控制：在 `account_refresh.db` 新增独立控制/问题记录，不覆盖旧回执。对绑定阻断/人工验证立即暂停受影响账号；普通故障有界退避，连续三次后暂停。同步和智能运营共享账号暂停门，在原子 claim 中复核；一个账号失败不阻断其他账号。恢复请求仅允许一次健康探测，探测通过后释放暂停并进入原计划，探测失败保留问题。不得直接把绑定改 active。
3. 前端：账号范围过滤，展示后台服务心跳、运行、待办原因、暂停/恢复按钮及处理指引。可见页面定期刷新本地状态，不在渲染中调用平台。管理员控制，恢复走后台探测，不直接启动业务或重置历史。
4. 主 agent：审查以上 API 与状态机、启动迁移、回归及真实只读状态；评估安全热更新/重启，不中断在途媒体、模型或未知任务。生产登录验证需要真实用户交互时保留待处理，不伪写通过。

## 预定接口

`src.scheduler.account_refresh` 保留原 API，并增加 `pause_account(account_uuid, account_key, reason, *, path=DB)`、`request_account_recovery(account_uuid, account_key, *, path=DB)`；`snapshot` 增加 `controls`、`issues`、`service`，空列表/字典兼容。control 至少提供 account_uuid/account_key/state/reason/error_code/updated_at；issue 为不含凭据的持久事件。服务状态可以缺失，但必须显示未知或未启动，不能显示健康。

维护结果的 `error_code` 用于后台分类；`AccountRuntimeService` 增加独立恢复探测方法（名称由实施确定，并通知主 agent/后台 agent），必须复用原会话、账号互斥及身份比对。人工请求不增加播放/发布权限。

## 验证与交付

人工修复窗口使用独立 `manual-session` 账户互斥，可通过显式 `allow_manual_verification` 进入业务熔断冷却中的原 profile，供管理员处理验证码或登录。该例外仅跳过业务 circuit 冷却，原未知锁（含过期锁）、日配额与使用累计仍有效；人工窗口退出只释放自身锁，不清零或延长原失败计数/熔断。打开或关闭人工窗口不自动恢复后台业务，自动恢复探测与维护任务没有此例外。

覆盖重启后暂停仍有效、双计划不越过暂停、一次恢复探测、错误分类、原身份不匹配、其他账号继续、连续异常熔断、前端只读定时更新及权限。主 agent 记录相关测试结果和生产接入/未接入范围。真实平台登录是否仍有效以原账号只读探测为准，不由模拟测试证明。
