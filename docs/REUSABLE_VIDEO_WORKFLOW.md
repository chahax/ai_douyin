## 2026-10-01 完整剧本重新生成与复审（v4）

新原创任务的内容返修采用 `full_script_revision_v1`：将创作简报、上一版完整剧本和已经核实的审核问题交回 MiniMax，要求返回完整新剧本，再由 DeepSeek 全文审查，助手核实审核证据。审核定位用于指出问题，不是限制只能改某一拍。模型可调整整篇动作、对白、拍数、拍号、顺序和时长，仍须保留用户主题、人物关系与核心表达要求。程序完整采用本次模型输出，不把新稿中的部分节拍与旧稿拼接。

流程为：**初稿 → 全文审核 → 修改需求 → MiniMax 完整新稿 → 全文复审**。通过即进入后续制作；新任务启动器默认最多5轮内容返修，每轮都须复审。初稿审核不计返修轮次，5轮返修最多对应6次全文审核。这是现有任务的共享内容返修上限，后续导演/联合返修也计入，不是每个阶段另给5轮。第5轮仍有主要问题时保存完整未通过稿及问题，停止交接，不强行通过。

预算版本为 `config/creative_workflow_budget_v5.json`：总调用上限20、reported tokens上限500000、结构修复上限8保持原值。一次内容返修通常至少包含1次完整生成与1次审核，结构恢复和审核补证另计调用；因此5轮不是5次接口调用，也不保证总预算一定能完成全部5轮。恢复旧任务沿用已保存的预算和返修模式，不覆盖历史回执或悄悄增加付费额度。

完整新稿审核通过后才生成分镜。普通分镜路线如果已有旧分镜，重新生成完整分镜，不把旧镜头当新稿补丁；已审核状态计划路线保留其重新规划及审核门禁，不以自由分镜返修绕过。数据结构恢复只允许无损整理模型输出的动作/对白次序，不创作缺失剧情，也不从旧稿回填内容。每次新稿、复审与采用结果均保留来源记录。

本次新任务冻结运行时登记为 `data/creative_governance/20261001_v14_full_script_revision`，状态为离线实现、尚未生产验证。验证覆盖完整新稿采用、跨拍对白保留、完整分镜重建、第三轮提前通过、第五轮失败停止和旧预算继承；本次没有调用付费文本、图片或视频接口。情感、事件、画面仍是文本审核重点，总时长按简报策略浮动；视频由用户人工审查，接口成功仅记录 `awaiting_human_review`。


## 2026-10-01 情感、事件、画面优先；总时长可浮动（v3）

用户最新确认：时间长短不是主要验收目标，主要审查情感表达、事件表达和画面表达。新稿使用 `narrative_expression_v3`，将三项优先级写入现有创作与文本审核请求，不新增审核轮次。

| 审查重点 | 看实际内容中的什么 | 不以什么代替 |
|---|---|---|
| 情感表达 | 刺激如何触动人物，怎样犹豫和选择，对方如何回应，结尾是否完成情绪收束；关键对白前中后的表演空间 | 背景里的心理说明、情绪标签、机械停顿；也不强迫人物口头解释自己的感情 |
| 事件表达 | 前因、信息变化、选择、结果是否在实际动作/对白中成立，修订到最终交接是否丢掉事件 | 摘要声称发生了、字段填完整、接口成功 |
| 画面表达 | 必要事实与关键反应是否有看得清的主体、景别、构图及窗口，分镜到最终提示词是否保留，画风与资产是否一致 | 只写镜头目的或全片固定中景；文本计划不能证明实际视频观感 |

简报新增可选 `duration_policy`：`flexible` 表示 `duration_seconds` 是创作参考，实际全片可长可短，按事件、对白和表演安排；`strict_range` 表示用户明确要求的硬范围。当前真人示例与通用新稿示例均使用 `flexible`。缺该字段的旧简报仍按原严格规则解释，旧任务的完整绑定提示词和回执不修改。

可浮动模式在正式剧本检查中解除简报参考范围及候选估计时长偏离检查，事件结构恢复可按表演调整总秒数；不会按候选数字机械缩放。总秒数仍必须等于真实节拍合计，语速、刺激/反应顺序、必要动作的物理时间、明确的局部时间要求及单次生成服务的能力限制仍需成立。分段属于执行适配，不因参考范围切段增删剧情。

审核针对明确表达要求的缺失提出有原文证据的问题，针对自然程度、张力、强度和美感给出具体内容建议；不把主观感动程度伪写为通过，也不把不超时当作内容好。本轮之前的52/56秒差异是关键回应丢失的证据，失败原因不是单纯变短。

文本阶段审查分镜与最终提示词；实际视频继续由用户人工审查，助手只核对生成接口与文件保存，记录 `awaiting_human_review`。本次仅修改流程及离线验证，未增加付费调用。新任务默认运行时登记目录为 `data/creative_governance/20261001_v13_content_priority_flexible_duration`。


## 2026-10-01 完整接通叙事交接（v2）

新原创任务绑定 `narrative_expression_v2`，将阶段职责表与完整提示词保存在任务状态中。旧v1绑定保持原阶段分配；没有绑定的历史任务不补写新规则。新职责表把全片动作规划也纳入导演表达职责，不增加单独审核阶段。

既有联合文本审核输入新增 `final_video_prompts`，由视频请求的同一编译器生成；普通审核与聚焦审核都收到它，交接核验重建同一输入。聚焦审核requirements、timing、first_frame对照包含最终请求；不把“新增信息”或情绪标签当作实际表演。新增文本会增加输入量，但不增加模型调用轮次，不宣称节省费用。

正常及助手返修交接分别生成 `NARRATIVE_TRANSFER.json`、`ASSISTANT_REVISED_NARRATIVE_TRANSFER.json`：
- 简报要求及源稿哈希；
- 各拍实际播放的动作和对白顺序（背景摘要不当作演出）；
- 每镜构图、表演、切走理由、作者提示词及实际编译请求；
- 请求是否可编译及对应版本。

对照文件的哈希进入媒体交接与输出清单；最终请求与对照不一致会停止导出。文件只证明来源和请求可对照，`semantic_approval=false`；叙事是否成立仍由现有文本审查判断，实际视频由用户人工审查。生成前不伪写内容通过，不把用户反馈替换成自动视频审核。

视频适配器v3明确映射全片计划的“画内对白/画外对白/混合对白”为请求的“画内/画外/画内与画外”语义（混合文本使用画内/画外）；保持说话人、台词与次序，不猜测新模式。v1/v2请求按原版本重建，旧模式失败不被悄悄改成通过。

本次新治理运行时登记目录为 `data/creative_governance/20261001_v7_narrative_transfer`；之前冻结目录不修改。本轮只修改代码、示例和文档，未调用文本、图片或视频付费接口。手工自由写视频提示词不属于新原创交接流程；新制作应沿用锁定剧本、分镜与编译请求，不再为每段单独改写剧情。


## 2026-10-01 叙事表达优先与真人风格

《今晚不算你的》用户反馈“习惯替同事加班”没有被看懂，成片情绪不足；这是用户反馈，不是助手播放后得出的媒体结论。文本核对发现：B01在请求前就重新打开本子，没有明确外部触发；B05才用“上次熬到两点”回述历史；正式稿B05的反应近景在最终提示词中变为固定中近景。不能把单次开本子/伸手自动解释成长期牺牲，也不能把文字里的情绪标签当作表演。

新原创任务自动绑定 `narrative_expression_v1`（`state.narrative_focus_binding`），直接进入现有编剧、导演、普通文本审核和聚焦文本审核请求，不新增模型调用或输出字段。检查分工：
- 编剧用实际动作/对白建立核心关系、当前欲望、选择代价和改变判断的依据；背景说明和摘要不算演出。
- 导演在最终prompt中落实新增信息、关键反应构图与时间窗口；连续尾帧不支持的换机位须明确适配需求，不能静默删除叙事。
- 审核在现有requirements项核对核心前提及剧本到最终prompt的信息保留。违反明确简报的表达缺失归writer/director；强度、美感与感动程度等主观建议不扩大为机械禁令。
- 动作、道具、布局、计时仍负责可执行性；这些检查通过不证明内容有感染力。

叙事判断不由关键词或程序伪造；当前改动仅完成离线验证，须新稿真实文本生产及用户观感验证才可宣称创作改善。旧run缺此绑定时沿用旧提示词；已有绑定保存完整文本，恢复不读取新规则覆盖历史。既有源稿、审核和付费回执不改。

真人版可使用 `config/creative_brief.live_action.example.json`：每次可替换主题、关系、感受、转折和结尾，示例不代表已批准重制。真人指AI写实实拍质感；人物、背景与首帧必须采用同一媒介并重建或选择兼容资产，不将动画尾帧用于真人续段。

**当前视频审核政策：**依据AGENTS.md中2026-09-30更新，视频由用户人工审查；助手仅核对任务成功及文件保存，记录 `awaiting_human_review`。下方旧版“助手抽帧/听看”默认已被替代。逐段续生一般等待用户反馈；明确授权完整审片版可延后人工审查，均不得自动写内容passed。

## 每次换什么

复制 `config/creative_brief.example.json`，修改本次内容。`theme` 必填；其余创作文本字段可留空，留空代表委托编剧导演提出方案，记录在 `delegated_fields`，不冒充用户已确认。时长为秒数区间，默认 60–100 秒。标题由启动参数提供，模板中的 title 仅供阅读。

示例是可编辑的写法，不是已选定的新作品。本次代码更新未启动文本模型、图片或视频付费生成。

网页“新版创作流程”的故事来源新增“原创创作简报”，填入 JSON 路径即可启动。小说与参考视频仍可附加简报来约束风格和表达；小说情节、对白的来源要求继续生效。

命令行示例（启动会使用现有文本模型预算）：

```powershell
.venv/Scripts/python.exe scripts/run_creative_workflow.py --source-driver original --title "新作品" --brief config/my_brief.json --run-dir data/creative_workflows/my_new_story
```

原有编剧—导演—编剧回核继续使用同一任务预算。新增一轮导演资产设计，计入总调用、token 和契约修复预算；返修设计也计入原任务，不能换目录重置同稿额度。

## 实际推进顺序

验收以真实作品推进为准：从可替换简报生成一份完整剧本，实审其因果、情绪和可执行性，再检查对应分镜、资产及首帧计划。审核器识错率和本地测试只能验证部分机制，不能替代这条实际生产链。助手可委派独立创作审查代理守住这些目标，主助手负责核实意见并推进结果；媒体未生成时不得报告成片质量已通过。

新原创任务绑定简报优先级：硬约束高于候选中的具体道具与操作，候选是可修正的方案；小说来源锁不受影响。原创返修可显式授权同步更新故事摘要，未授权节拍保持不变，旧回执按原请求重放。制作审查应区分必须修改的事实矛盾、导演可落实的表演时间和可选审美建议，避免把本次题材限制变成所有故事的禁令。

新原创任务的分镜使用独立绑定的 `original_director_v1`，以当前剧本实际动作/对白为锁，避免继承小说改编的来源还原规则。导演退回的非空剧情问题与完整分镜使用不同校验；空问题但缺分镜按欠交分镜处理，不得当作完成，也不得要求模型捏造问题填满数组。旧请求保留其原提示词版本。

1. **简报和故事**：编剧提出完整因果及情绪推进，导演编排镜头。每镜写清新增信息、反应主体、切走理由、反应窗口。无叙事作用的操作返回上游处理。
2. **少量样板**：选一项人物、一项背景作为样板；兼容的历史素材可作为样板。实审风格与可读性后再补齐资产。
3. **人物和场景**：按 `reuse_key` 或准确名称/别名及兼容标签匹配，校验原图、实际图像审核和生成回执。历史 `scene` 类型兼容背景。多个候选保留选择任务，失效素材明确记录原因。导演可以显式指定历史人物的 `reuse_key` 来复用外观，剧情关系仍以本次简报为准。
4. **依据实际素材检查分镜**：任务包列出每镜实际图片、首帧构图、信息和反应窗口；助手看图检查空间动线、表演位置、切镜理由。文字计划本身不能充当图像审核。
5. **关键表演试验**：按身份、对白、交互和机位风险选择能覆盖风险的代表镜，避免默认每镜重做一遍测试。
6. **逐段制作**：继续现有生成、失败预算和未决任务处理规则。每段首尾与镜内动作抽帧，并同步听看声音、语速、说话人和口型。通过后才使用该段原始尾帧推进下一段。需要切换机位却无法按当前续段规则执行时，任务明确停在衔接适配，不能把新机位图片当作原始尾帧。
7. **整片检查**：全部片段实审通过后才能进入合成；合成版还要检查所有切点、声音、情绪重心和结尾。整片通过才得到 `full_workflow_pass: true`。

声音未审保持 null，不能当作完整通过；《玄关一步》的旧单片授权不会扩展到新作品。

## 自动生成的文件

- `PRODUCTION_DESIGN.json`：角色/场景需求、镜头意图和资产引用。
- `REUSABLE_PREPRODUCTION.json`：匹配结果、拒绝原因、每镜实际参考素材和视频请求模板。
- `PRODUCTION_QUEUE.json`：依据当前文件与真实审核重新计算的下一步。
- `prepared_work/<版本摘要>/work.json`：当前可执行任务包，包含对应素材清单、镜头模板或审核模板。
- `asset_manifest.json`：需要出样或补齐资产时生成，兼容 `scripts/generate_ark_asset_pack.py` 的已有入口。
- `review.pending.json`：待实际检查的表单，所有检查项初始为 null；不会覆盖已经登记的审核。

重复执行准备命令是幂等的，不能因重跑自动重生成或重复付费：

```powershell
.venv/Scripts/python.exe scripts/prepare_reusable_production.py data/creative_workflows/my_new_story
```

网页也提供“更新素材复用与下一步任务”按钮。准备命令负责本地编排与检查，不调用生成 API。当前远程生成仍走原有执行器和 campaign 登记；任务包中的 `prepare_existing_executor` 要求原执行器的预算预留、生成范围授权与已审首帧，不能直接把模板当作已批准请求。助手完成实际检查并登记证据后，重跑准备命令即可推进到下一个阶段。

## 历史素材与审核凭据

默认库为 `data/visual_asset_library/reusable_assets.json`；可以用 `--asset-library` 指定另一个库。新故事生成的已审素材可以登记在该 run 的 `RUN_ASSET_LIBRARY.json`，不覆盖全局库：

```powershell

```

登记描述使用现有素材库格式：`reuse_key/kind/canonical_name/aliases/tags/decision`，以及 `image/review/receipt` 三份 `{path, sha256}` 绑定。审核必须已实际通过，回执必须绑定同一张原图。多个候选应在新的导演设计中明确 reuse_key，保持版本链，不能就地篡改已交接的设计。

阶段审核放在 run 根目录的 `STYLE_REVIEW.json`、`STORYBOARD_MEDIA_REVIEW.json`、`CAPABILITY_REVIEW.json`。任务包给出对应版本绑定和目的路径。实际记录至少包括各项 checks、具体观察 observations 和证据文件 evidence；保存证据不等于检查完成。

`ASSEMBLY_RECEIPT.json` 绑定 `segments_sha256` 和成片 video；`FULL_FILM_REVIEW.json` 绑定成片与合成回执。任一上游文件或证据改变，旧审核失效。

返修沿用现有助手反馈与文本复核入口。修订设计写入已审返修工作稿，交接时输出 `ASSISTANT_REVISED_PRODUCTION_DESIGN.json`。准备入口自动选择已交接的修订版本；初稿和旧审核完整保留。

## 2026-09-27 试生产失败修复

新简报任务在导演分镜和分镜返修请求中携带当前配置的模型时长范围与本地能力依据；校验不接受超长单镜。长节拍应由导演拆镜，保留对白顺序、刺激与反应窗口，不能机械缩短对白或把切镜冒充原始尾帧连续。旧请求回执保持原请求绑定；最终执行能力审计仍不可跳过。

首帧状态、画内/画外说话人、道具支撑与真实场景布局的语义一致性仍须实际审核。上述代码修复和离线测试不等于旧试生产已通过，也不等于完成声音或口型检查。

再次实测发现单镜超限若采用数值补丁，会与节拍总时长还原形成循环。超限错误现归入完整节拍镜头组修复，修复请求带模型范围并同时锁定节拍总时长；必须真正拆镜、合并或重分配，不仅修改总秒数。此规则仍需真实新响应验证，离线拆镜通过不等于影片通过。

### 2026-09-27 分镜前预审与证据核实闭环

新流程为：MiniMax剧本 → DeepSeek剧本预审 → 助手阅读全文并核实 → 必要时MiniMax定点返修 → DeepSeek重新预审 → 助手核实 → 分镜和资产方案 → DeepSeek联合审核 → 助手核实。联合审核需要修改剧本时，修改稿也必须重新经过剧本预审后才修改分镜。仍保留原有最终文本复核与逐段真实声画审核。

`issues`仅容纳必须修复的blocking/major问题，必须给出唯一ID、规则、具体事实、冲突说明、影响、修复目标和逐字字段引用。`suggestions`只存可选润色，不能自动触发返修。对白证据必须定位到具体text叶子；简报和数字时长引用可验证，数组或对象不能冒充台词。格式错误消耗原有契约修复预算，仍失败就停止。

审核包保存当前剧本、简报等上下文与DeepSeek原始意见；即使模型issues为空，也需要助手实际阅读全文。助手逐条confirm/dismiss并写原因，可用additional_issues补录漏检。核实回执绑定完整审核包，已使用后不可改写，稿件或审核变化后旧回执失效。这里只验证回执、路径及原文，不把程序校验当作语义正确性。

```powershell
.venv/Scripts/python.exe scripts/record_creative_text_review.py --run-dir <原任务目录> --decision <助手实际核实后填写的JSON>
# 随后按原参数恢复 run_creative_workflow.py，或在页面点击“继续已核实的任务”。
```

这是助手的审稿操作，不要求用户逐条确认。`reviewed_by=assistant`属于留痕声明，不是独立身份认证；必须实际看完才能填写。导入工具不会替助手填结论，也不会自动发媒体请求。

确认的问题才消耗共享返修轮次；返修前预留再次审核所需调用，不扩大原调用/token/契约修复预算。未受影响节拍保持原文。导演仅返回误报而未给分镜时，最多允许一次保持剧本不变的分镜重拟，再次无有效分镜则停止。审核包、核实回执、有效问题单及汇总进入最终输出清单。

本次真实API冒烟复用两个已见案例，三版提示共6次DeepSeek调用，0次视频调用。当前版格式检查通过，但正常稿仍有误报；核实层实际驳回该误报、保留错误稿的真实问题并去除同根因重复项。不能据此宣称审核模型已经稳定，详见 `data/model_evaluations/review_gate_smoke_v3_20260927/REPORT.md`。
