# 同照片表演首图 v36

本轮修复背景重造和合影式视线。`visual_scene_performance_stills_v36.py` 是独立生产器，旧 v24/v34 图像计划和源代码保持冻结。

每段均从同一张已经真实保存的 S01 照片编辑，引用该照片原生任务 `239ab58e-994b-42b6-acca-492a2faa7f82` 的 RESULT，核对实际 PNG 的路径与 SHA。照片的裂墙、木床、灰床面、窗框和桌子是房间参考；另外三张正面人物图只负责苏墨、叶南、叶西决身份和服装。母图不是 3D 替身，也不通过另一个房间的图冒充同场景。

四个独立原生图任务各有相同顺序的四张输入：同照片母图、苏墨、叶南、叶西决。工作流逐张 `LoadImage → VAEEncode → ReferenceLatent`，并验证四条链实际位于正向 CFGGuider 的祖先路径。母图只在负向链或孤立节点出现会被拒绝。这证明照片确实进入了模型，不证明输出像素被锁住；此路线没有像素掩膜锁定，实际效果由用户审核成片。

## 生命周期接口

`prepare(spec_path, run, authorization=None)` 纯 CPU：核四图输入、真实母图收存证据、当前授权和源材料；冻结源照片快照、四个单图 graph/PLAN。`SCENE_IMAGE_SPEC.json` 绑定同一新 run 的 USER_AUTHORIZATION。此生产器最多派发四次，不自动返拍；总授权的八次图片工程上限由上级协调器管理。

`submit_next(run)` 只处理首个尚未保存的任务；每次最多一次新 POST。已有原生 ID、未知结果、已知失败或中断均不会自动重发或跳过。协调器持全局 `GPU.lock`，原 `image_jobs_v3` 持共享 input 的 `VISUAL_GPU.lock`。

`collect_known(run)` 优先按原 ID poll/collect，消费冻结本地照片快照，不重新依赖可变的外部 SPEC、授权或母照片。新派发前仍会复核外部原文件，变化则停新派发。未知 POST 不重放。

`status(run)` 返回四段 `id/status/job_dir/prompt_id/result_path/image`；`result_path` 是 v36 回执的绝对路径字符串；`image` 是 `path/sha256/dimensions`。`result(run, sid)` 回执包含原 `image_jobs_v3 RESULT` 的 `native_result` 绑定、原 ID、PNG、房间照片出处、起点状态及技术图链证据。`complete(run)` 只表示四张原生 PNG 技术收存；`budget(run)` 统计包含未知和失败在内的 claim 次数。

回执始终 `user_review_pending=true`、`production_approved=false`。没有 VLM、ASR、OCR、正脸或 root 语义审核门，不创建假通过记录。协调器先串行生成四张首图，冷切模型后再生成四段原生音视频，最终交用户看完整分钟。

## 验证范围

CPU 测试含：母图确实进入正向祖先链、错误或孤立参考拒绝、人物与面包起点状态、真实保存母图来源、源变化停止新派发而不妨碍原 ID 收存、未知不重放、原 PNG 变更拒绝，以及独立 Python 进程对本地 HTTP 测试服务的四图串行生命周期黑盒。黑盒的纯色 PNG 明确是测试夹具，没有运行模型，也不作为生产效果。

实际输入的 CPU prepare 是真实文件/图接线验证，0 媒体调用。测试通过不代表生成结果保持了背景或正确表演；该结论需要本轮真实模型输出，按用户要求直接交其审核。
