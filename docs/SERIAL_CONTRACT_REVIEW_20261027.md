## 设计审查与修正

| 层面 | 原问题或职责 | 新设计/验收边界 |
| --- | --- | --- |
| 材料覆盖结构 | 同一行要求omission_reason必填，已覆盖又要求空，提示没讲清 | covered与omitted是两种互斥结构。covered只含原段ID、status、非空claim_ids；omitted只含原段ID、status、非空reason。禁止同时填写 |
| 规则来源 | schema、提示、校验各自隐含不同约束 | COVERAGE_RULES写入schema说明、系统提示、请求规则。结构由同一schema检查，跨引用关系单独校验 |
| 引用定位 | 语义有关不代表claim已绑定该原段 | 每条coverage边核对对应claim.evidence，精确返回行/claim/source及已有证据ID；不放宽来源门 |
| 错误反馈 | 仅第一处错误且截取2500字符，缺期望值 | 材料校验同时报告结构、重复、缺段、引文和覆盖边错误；完整结构化反馈通过容量门，不静默截掉错误 |
| 数值类型 | v3把chapter_index设为const时没有保留显式integer，模型连续返回字符串 | v4同时声明type与const；反馈包含expected和actual。注意const=1本身已拒绝字符串，这一项是模型类型错误及反馈不足，不是schema允许字符串 |
| 全局资料与分集 | 身份别名、可读范围、事件依赖、来源归属仍须核对 | 保留既有实体去重、未读结局拒绝、章节处置、前集依赖等校验；内容充分性不能由结构证明 |
| 剧情与调度 | 下游不能私改固定对白；位置持物知情需要动作支持 | 沿用固定brief比对、时间线分离、跨集前态、动作绑定和计时校验；真实语义仍由交叉审和终审判断 |
| 审核返修 | 不支持的审核意见不得直接改稿 | 保留候选及审核SHA绑定、字段地址核验、独立裁决和两轮责任返修；不确定/全驳回保留停止 |
| 执行与预算 | 失败任务不可盲重派，剩余额度不能重复领取 | 新版本通过父任务已知终态及AUTHORIZATION校验；BUDGET_TRANSFER一次性绑定唯一子任务；未知状态拒绝转移 |

## v5追加审查与最终结果

v4真实4次/81361 reported tokens，材料经一次来源边修正后进入内容审核及裁决。又发现材料审核的owner使用全局枚举，允许写episode，直到返修路由才被拒绝。独立裁决还会部分同意一条混合意见，而旧传播机制仍把整条原意见传回生成器。

v5按审核阶段限制owner，候选路径与阶段各自校验；独立裁决须输出validated_issue，只有经确认的问题被传播，原意见只作历史证据。新测试重放v4错误责任阶段，模拟混合意见只传有效部分、驳回意见不可夹带修订。最终182项不同回归通过，见final.xml。

v5真实11次/205258 reported tokens，第1章首稿一次通过结构、覆盖与引用检查；随后内容审核、独立裁决和两轮自动语义返修均实际运行。最终仍未通过：原生材料继续误解“哥哥”自称及条件句，第二次返修又加入“哥哥指老大叶东”和“最终未上交”的无据判断。第10次裁决在rejected项漏validated_issue=null，第11次协议返修提交两份submit_result，严格原生门拒绝，不随意拼接或取其中一份。

这说明字段合同缺陷已有针对修复，但模型生成、审核和裁决仍有共同语义偏差，自动返修不能保证纠错。不能将纯粹的无工具/多工具协议修正当成已经解决内容问题。尚需处理裁决可选分支表达及多提交行为，并重新设计歧义/否定/条件与人物自称的校验策略；本轮未冒称完成这些剩余项。

本轮真实共17次/332404 reported tokens，含此前v2总19次/373430，原400次边界算术剩余381，非新预算。所有任务pending=null，旧任务不重跑；第2—69章、全局归并、分集、完整剧本、DeepSeek、媒体、发布均未执行。没有手改模型稿。独立审查见v5目录PRIMARY_PRODUCTION_REVIEW.json，汇总见data/qa/serial_story_v3_20261027/ACCEPTANCE.json。
