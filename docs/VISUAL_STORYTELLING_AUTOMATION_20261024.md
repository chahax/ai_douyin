# 视觉叙事规范接入自动剧本流程

日期：2026-10-24。依据用户确认的七条规则实施。本次是流程开发与离线验收，没有新增付费文本、图片或视频调用，没有修改旧成片或进行发布。

## 新任务行为

小说改编、原创剧情的主网页入口，以及 `scripts/run_natural_director_v10.py source-prepare` 的新来源入口，统一冻结 `brief.visual_storytelling`。规则包含版本、完整内容和 SHA256；继续保留原排时 v2 与内容结束规范。

| 规则 | 创作与审核重点 |
| --- | --- |
| 开场信息 | 通过首个有效动作与对白，让人物关系、地点、当下目标尽早可理解；悬念允许有目的地暂隐信息 |
| 可见情绪 | 情绪有刺激、可见动作/神情/视线或声音变化，普通状态可以开镜成立 |
| 动作对白并行 | 合理并行、保留物理依赖，内容完成即收，不强加走路或纠结过场 |
| 关系互动 | 称呼、距离、习惯与说听反应体现关系；独处、镜外声、避视和沉默允许成立 |
| 来源环境 | 场景用途、时代、生活条件、陈设和空间清楚；地点改换有明确 brief 依据，并核对剧情后果 |
| 光影动机 | 根据时间、天气、实际光源与剧情设计，并维持段间连续；不套用暖黄/旧客厅模板 |
| 镜头连续 | 景别、机位、运动、切换有信息作用；跨段核对轴线、构图、位置、道具、动作与光线 |

## 实际接线

`visual_storytelling_v1.prepare_source → performance_timing_reference_v2.prepare_source → 原 writer-only / natural director 流程`

现有五个真实请求构造器均传递完整冻结 brief：MiniMax 编剧、DeepSeek 全文审查、MiniMax 自然导演、DeepSeek 忠实整理审核、DeepSeek 全部实际 SDK 请求审核。规则按阶段说明职责，并映射到原生九维检查，不新加一套强制创作 JSON。

整理后的每段 prompt 保留本段正向环境、光线、表演和摄影安排；规则清单、内部证据和后续剧情不由编译器自动拼入视频提示词。最终审核仍读取完整规则及所有实际请求，不能仅检查导演稿。

责任层写入原有审核意见：正文与来源问题属 writer，表演与分段属 director，忠实整理属 extractor，实际请求编译丢失属 compiler。本次没有替换旧执行状态机，也没有实现自动修改程序代码的修复器：沿原有机制处理全文返修、导演重写、故障停止及证据保存。审核规则规定的责任归属不等于四种责任层各有一个独立自动修复执行器。

## 旧运行与范围

- 不修改原核心角色、审核合同、运行器或它们已冻结的代码哈希，旧运行证据保持。
- 新规范适配器拒绝向旧 BINDING 补写规范；原 CLI 对已冻结旧来源保留原准备语义，execute/recover 路由保持。新规范运行必须匹配已冻结 brief，不能借重复准备换规则。
- 没有取消来源身份、用户授权、历史停止、预算、未知结果及媒体人工验收门。
- 没有自动把《渡口》改成家庭环境，没有对当前小说推广视频补绑书籍。
- 本次覆盖主网页的小说改编/原创剧情路线和主 CLI 新来源入口。历史版本 CLI、账号选题旧专线和人工编辑后单独提交视频的入口未宣称迁移。
- 源码与独立测试进程已经生效；本次未重启正在运行的账号后台，未证明其已缓存的网页模块被重新加载。网页如仍显示旧提示，需要重载应用模块后创建新任务；CLI 新进程直接使用新默认。
