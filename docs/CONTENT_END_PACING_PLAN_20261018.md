# 按有效内容结束的剧本与请求设置

用户对10秒渡口首段反馈：“7秒票推完后续其实没什么动作了这些内容可以再剧本或者设置中处理不需要有多余的时间短”。这是用户对原视频的观察，助手不通过播放、抽帧或音频识别重新判断视频。

根因有两层：原试片提示词为普通回看单独排到10秒，专项入口又把SDK请求、计划及技术时长校验固定为10秒。通用自然导演v10的SDK编译实际上按每段原定秒数传递，并未额外加尾巴；其当前规则仍缺少“最后有效内容完成即收段”的明确要求，网页把参考总长写成目标，也容易诱导补时间。

本轮先完成可复用的上游设置和当前首段的新执行候选，不增加模型或媒体调用：

1. 独立`content_end_pacing/v1`把规则写入新任务冻结brief；MiniMax编剧/自然导演与DeepSeek全文审核/忠实整理/最终实际请求复审都收到同一个brief。普通神情直接成立，普通动作和反应随对白并行；最后必要对白、动作、关键反应完成即结束，不另留固定尾窗，不靠补动作凑参考总长。
2. 新任务默认以内容决定时长，参考总长只供估算；显式最短、最长或硬目标范围保持原约束。有冲突时交回上游重写、删合或重新分段，审核员与SDK编译器不私自改秒数。重要反应可以独立保留，但必须有具体信息或情绪作用。
3. 新准备入口与网页新任务接入该设置；旧运行恢复不补写brief、不改原生稿、代码冻结、预算、失败或已耗尽十轮授权。源身份与有效授权仍由原运行器核对，开发不新增真实派发。
4. 当前另存7秒S01候选：对白、取票和推票并行，女儿的意外在推票时呈现，票到位、最后一句结束即收段。按最终候选的7秒编译无参考图SDK预览；不只修改旧10秒请求的duration字段，不修改或剪裁旧片，不生成新片。
5. 离线核对规则进入各实际请求材料、参考与硬范围不混淆、新候选SDK秒数一致，以及旧稿/回执保持。字段与测试通过仅证明接线，不能声称已解决模型成片质量。

新设置由子agent实现，主agent审查实际调用材料与预览并复验。用户进一步要求重生成时再登记独立一次提交；已生成首段继续保留原生10.08秒及`awaiting_human_review`回执，当前反馈独立绑定原ID和文件SHA，不冒充用户通过或自动续段。
