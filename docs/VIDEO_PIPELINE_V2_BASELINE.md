# 视频流程 V2 历史设计基线

## 当前使用范围

本页保留 2026-09-04/05 的视频生产线重置设计，用于追溯退役路线和当时的候选合同。
2026-10-02 的完整剧本、导演、请求预览、显式镜段生成与用户审核实现见
[当前实现](CREATIVE_WORKFLOW_IMPLEMENTATION.md)及[系统架构](SYSTEM_ARCHITECTURE.md)。

下文“待实现”“自动质量检测”“逐帧/转写”等属于历史设计，不是当前助手执行要求。
依据[AGENTS.md](../AGENTS.md)的 2026-09-30 更新，视频内容仅由用户人工审查，技术成功进入
`awaiting_human_review`。旧组合仍退役，当前独立显式创作入口已接线；真实质量验收仍待完成。

## 重置时的决定

当前没有通过质量验收的生产视频生成管线。

以下实现已退役：

- `presenter_anime`
- `dual_framepack_active`
- `single_template`

与这些主流程绑定的旧背景、人物驱动、镜头生成、插帧和合成节点也已从当前工作流
候选列表撤下。它们可以作为未来的镜头级技术候选重新评估，但不得直接恢复旧组合。

退役原因包括固定角色与模板感明显、画面表现不足、分析脚本与实际生成稿不一致、
生成与发布耦合、候选视频缺少统一人工验收等。旧代码和文档保留，但不能从管理页、
命令行、Agent Skill、工作流或自动发布服务调用。

## V2 只定义流程，不预设生成技术

```text
账号策略
→ 有时效且与账号相关的内容样本
→ 时间校正后的高展示指标样本组
→ 跨视频、跨作者重合特征
→ 从重合特征原创扩张人物、场景、动作、语言和情绪
→ 人工确认详细剧本
→ 锁定脚本版本
→ 锁定逐镜头设计
→ 为每个镜头选择生成实现
→ 生成多个候选
→ 自动质量检测
→ 人工逐镜头审核
→ 合成候选成片
→ 人工终审
→ 独立发布
→ 发布数据回流
```

LTX、WAN、FramePack、Seedance/即梦、LivePortrait、SadTalker、Sonic、静态动效或
其他实现都只能作为镜头级候选 Provider，不能天然成为默认生产流程。

## 生成前分析 V2

`视频类型` 只是输入筛选条件，不是分析结论。以 `mixed` 为例，正式顺序是：

```text
近期采集数据
→ mixed 类型筛选
→ 明确发布时间 + 账号相关度筛选
→ 页面展示指标、发布时间新鲜度和相关度联合排序
→ 取相对高展示指标样本组
→ 至少两条视频、优先跨作者计算共同钩子、叙事装置、题材和媒体表现
→ 账号领域策略选择可用切口
→ 原创扩张人物定妆、场景、站位、动作、情绪、对白、镜头、声音和连续性
→ `DetailedVideoScript/v2`
```

页面只显示最终详细剧本；高流量阈值、来源视频、重合支持数、作者覆盖和证据等级写入
独立审计文件。页面展示数字只能称为页面展示指标，不能冒充官方播放量。

元数据分析只允许支持题材、标题钩子和抽象叙事结构。只有取得授权本地视频并完成逐帧
分析和语音转写，才能把场景、人物、动作、语言与情绪标记为 `observed_media`。缺失的
媒体维度可以由领域策略原创扩张，但必须在审计中标记为 `creative_expansion`，不能伪装
成对热门样本的观察结论。

## 必须统一的数据契约

### `VideoProject/v2`

- 运营账号 UUID、策略版本、领域。
- 分析批次、选题 ID、证据时间范围。
- 锁定脚本 ID 和内容哈希。
- 目标时长、画幅、语言、发布目的。
- 目标样片或视觉参考及其授权说明。

### `ShotSpec/v2`

- 镜头 ID、起止时间、画面目的、主体、动作、镜头运动。
- 旁白/对白、字幕、安全区、声音要求。
- 角色与场景连续性约束。
- 允许的 Provider、随机种子和模型版本。
- 禁止元素与领域合规要求。

### `ShotCandidate/v2`

- 输入清单哈希、Provider、模型、工作流、seed。
- 原始输出路径，不允许用后期剪辑掩盖生成失败。
- 实际时长、帧率、尺寸、音频和字幕信息。
- 自动检测报告、人工审核状态和问题列表。

### `FinalVideo/v2`

- 只引用已经批准的镜头候选。
- 保存实际时间线、混音、字幕、颜色和编码参数。
- 保存最终质量报告和人工批准人。
- 发布记录必须引用最终成片哈希，不能只引用选题或脚本 ID。

## 开发前必须先确定

1. 法律号和小说号各自的目标样片与不可接受样片。
2. 首个 V2 流程做口播、案例演绎、剧情短片还是图文信息流。
3. 15 秒目标是严格 15.0 秒，还是允许明确的误差范围。
4. 角色、真人、动漫、3D、摄影和字幕的视觉规范。
5. 首批允许测试的 Provider 以及单次成本、时长和显存预算。

## 最低验收门槛

- 分析、批准脚本、实际配音和字幕内容完全一致。
- 每个镜头来源、版本和生成参数可追溯。
- 不允许静态占位背景、固定狐狸角色或模板循环作为无提示降级。
- 角色身份、服装、场景、光照、动作方向和镜头连接通过连续性检查。
- 无黑帧、冻结、闪烁、肢体畸形、乱码、字幕越界或音画缺失。
- 法律内容完成权威来源与逐句事实核验；小说内容绑定授权作品和章节。
- 自动检查通过后仍必须人工逐镜头审核和最终成片审核。
- 生成和发布必须是两个独立动作，生成测试不访问或操作抖音账号。

## 恢复生产入口的条件

只有满足以下全部条件，才能新增一个可切换的 `video_pipeline` 实现：

1. 接口契约测试通过。
2. 同一输入可重复生成并完整记录参数。
3. 法律号和小说号各完成一组人工批准样片。
4. 质量门禁、人工审核和发布前账号确认均为强制步骤。
5. 管理页可以看到分析证据、锁定脚本、镜头候选和审核状态。
