## 问题清单

### Bug #1：`st.session_state.clear_confirm` 写入时机错

**报错**：
```
StreamlitAPIException: `st.session_state.clear_confirm` cannot be modified after the
widget with key `clear_confirm` is instantiated.
```

**位置**：`src/web/app.py:832` (page_fanqie_batch_queue，清空清单按钮)

**原因**：streamlit 限制 `session_state[key]` **只能在 widget 实例化之前**赋值；按钮 click → code 路径上 widget 已经存在 → 写入失败 → 整个 page rerun 崩。

**修复**：用以下任一方式：
- A. 用 `st.session_state[key] = value` **只在页面顶层**，把逻辑放在按钮 click handler 之前
- B. 用 callback `on_click=` 配合 `st.session_state`
- C. 改用 `st.form` submit 模式，key 不重复

**优先级**：**High**——清空清单按钮彻底失效

---

### Bug #2：dataframe PyArrow 序列化错

**报错**：
```
pyarrow.lib.ArrowTypeError: ("Expected bytes, got a 'int' object", 'Conversion failed for column 耗时(秒) with type object')
```

**位置**：`src/web/app.py` 的某一处 `st.dataframe(rows, use_container_width=True)`，列名是 "耗时(秒)"

**原因**：dataframe 的 "耗时(秒)" 列里既有数字（int）又有 None / 空字符串，类型推断不稳。

**修复**：构造 rows 时给该列强制转 str：
```python
"耗时(秒)": str(b.get("duration_ms") / 1000) if b.get("duration_ms") else "-"
```

**优先级**：**High**——整页 dataframe 渲染崩，掩盖了下面所有数据

### Bug #3：`batch-run FAIL #85..93: DB 中找不到该清单条目` × 10

**报错**：
```
[batch-run] [1/10] FAIL #85: 我的6个超级奶爸 (DB 中找不到该清单条目)
... (9 条类似)
```

**实际原因**：用户通过 UI 一键清空把 DB 清空后，又跑 `batch_run`。`batch_run` 在 #pending=0 时本来应该跳过，但实际触发了 task——可能因为之前已经 enqueue 但 DB row 被删了。

**修复**：
- 在 `batch_run` 入口检查 `len(targets) == 0` → 立即 return "清单为空，请先加书"
- 友好提示文案

**优先级**：**Medium**——之前已修过，没预期清空后会残留 task
