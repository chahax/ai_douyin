# 批量来源优先的剧本试跑

入口：`scripts/run_cohort_expression_trial.py`。先20条原片核心/画面/转写证据，补全原声音画窗口及本地声学数据，再重新计算类型与点赞对照，经实际总结审核后生成短/长试稿。用户指定单片不替代这批研究，不写创作贡献百分比。

本轮目录：`data/qa/cohort_expression_trial_20260912`。全片共129个最长30秒窗口，短片单窗，窗口边界不是原剪辑点。完整原片图像/ASR沿用已经绑定审核的结果；新增Omni与emotion2vec均为模型观察，不冒称人类听看通过。反复输出、问题复述和截断结果标为不可用，矛盾或含糊结果保留未知。声学RMS是混合音轨幅度；分类器分数不是角色动机或观众情绪。

`--stage summary` 强制核对全20条成员、同批点赞、原媒体SHA、所有新窗口、声学证据。完整主张及其**全部支持证据行**保留在 `cohort_cards.json`。综合阶段使用显式 `reviewed_expression_digest/v1`：20条已审核心、视觉、语言、冲突、未知项原文和所有所引证据ID/时间均保留，删除重复的底层转写正文与声学原始分数；不让模型重新撰写20条事实记录。逐条报告由已绑定原分析确定性渲染，模型只做类型比较和选题。类型可重叠，样本一视频一票，近似模板注明，不按窗口数、时长或点赞份额计算创作权重。

`--stage short|long --summary-run <总结目录> --review <实际审核.json>` 只接受通过实际复核、绑定总结正文的记录；选定主参考必须属于本批20条。模型接收全批总结、实际审核意见和类型比较，再接收主参考的全部支持证据正文展开剧本。保留请求、原始模型正文、响应元数据、所有来源绑定和北京时间；不生成视频，不自动批准成稿。当前为显式CLI试跑入口。

阅读输出时分别检查：核心为何来自此批、类型为何被选、画面具体如何借鉴、音频情绪证据有哪些限制、短/长稿如何兑现真实结局。原始法律主张不自动正确，必要的法律示范先查原始权威文本。

审核可选择 `entire_summary` 或 `selected_direction_only`。后者不是整份总结通过：必须逐字摘录实际模型输出中可试写的方向、列出未采用的问题和编剧约束。入口验证摘录确实来自原模型正文，只有被批准摘录进入选题字段，完整20条已审核心/视觉/语言分析仍送入编剧；不得由审核者替写故事后伪装模型输出。试稿仍需逐镜实际审核。

本轮发现并修复：长上下文重写事实导致串来源/统计漂移，改为保留逐条工件、模型专做综合；问题复述含换行时漏检，补充检测；来源门禁元组序列化为列表引发误判，改为比较两个已保存JSON工件，不放宽来源一致性要求。

编剧反馈入口 `scripts/revise_cohort_screenplay.py` 绑定实际父稿与反馈，再由项目模型修订，保留每版正文和响应。`scripts/audit_cohort_pacing.py` 仅检查声明对白排时，不能代替实际声音审核。

结构化试跑入口 `scripts/compile_cohort_screenplay.py --parent-run <已完成候选目录> --feedback-file <实际反馈> --output-dir <新目录>`：模型编写JSON中的人物、物件、场景动作和对白，程序按字符数与明确独立动作时间分配45/180秒；角色、退款方向/金额、物件末态、语速范围不符合则拦截。严格解析拒绝重复键及损坏JSON，不自动修掉歧义后冒称成功。该入口的本轮实际模型输出仍未达标，不能把单元测试通过当成候选通过。

## 2026-09-13 升级：事件状态先行，失败按阶段修复

`run_cohort_expression_trial.py --stage short|long` 现在默认进入 `run_cohort_scene_flow.create_plan`。上文整稿编写、旧编译方式仅用于历史复现；整稿入口必须显式传 `--legacy-author`。网页生产入口尚未切换，不把 CLI 接通描述成全产品上线。

流程为：20条来源与总结绑定复验 → 模型事件规划 → 状态重放 → 实际事件审核 → 模型逐段对白 → 不可变版本组装 → 实际逐段终审。所有阶段均停在视频调用之前。规划器获得全20条核心及表达方式、类型比较、已审选题与主参考证据摘选；完整证据仍存档，不把模型摘选描述为全部原声复看。

状态由动作计算，不能由模型填写结局代替：每只手只能持一个道具；转移必须从实际位置出发；证据必须现场展示再确认；付款人、收款人及各自设备一致；提交不等于到账；终态必须真的完成。每段先保留实际操作最低时间，再按段分配对白及反应时间。声明排时不是实拍速度证明，实际动作若更慢必须重新排时。

失败分别回到格式、事件规划、对白或实际审核阶段。事件修订只允许实际审核指定的 JSON 指针，冻结其他内容；明确零基数组下标与镜头编号对应，拒绝越界、遗漏、重复修改。对白按输入与反馈指纹限定尝试次数，仅重写指定失败段，已通过段复用；实际审核否决的旧选择不能自动复用。每次原始请求、模型输出、错误和父版本保留，不以文件修改时间标记完成。

分段入口：

```text
scripts/run_cohort_scene_flow.py --stage repair-plan --workflow <父规划目录> --feedback-file <绑定父候选与允许路径的审核JSON> --output-dir <新目录>
scripts/run_cohort_scene_flow.py --stage write --workflow <规划目录> --review <实际规划审核JSON>
scripts/run_cohort_scene_flow.py --stage write --workflow <规划目录> --review <实际规划审核JSON> --beat-id <失败段ID> --feedback-file <本段实际反馈>
scripts/run_cohort_scene_flow.py --stage accept --workflow <规划目录> --review <实际逐段终审JSON>
```

事件审核须覆盖因果、动作、情绪、法律边界、来源匹配和本稿价值；终审还须逐段绑定真实对白、动作与实际终态。结构检查通过仅为 `structurally_valid_pending_actual_review`；最终 `ready_for_user_review` 表示可交用户看剧本，不能当成实际声画审核通过。

## 本轮闭环验证完成（2026-09-13）

真实通过稿：`data/qa/cohort_flow_upgrade_20260913/short_trial_r8/assemblies/007/screenplay.md`，终审记录为同一运行目录的 `screenplay_actual_review.json`，状态 `ready_for_user_review`。此前失败版本和审核记录保留。

进一步升级了以下环节：

- 对白生成只读取已经在场景中展示的证据；初始知道不等于已向观众揭示。给模型当前手持状态、既定道具及终点，避免初始位置误导当前动作。
- 角色对白中的金额不得擅自增加。实际反馈可使用JSON的 `forbidden_phrases` 指定已明确否决的措辞；机器拦截重复，人物立场与含义仍需实际复核。
- 每段的原始秒数现在是编写预算，不再强迫自然对白凑成固定长度。按实际发音文字排除标点，先保留动作及反应时间，再在各段目标语速上下限内分配完整45/180秒；无法容纳时退回对白，禁止放慢动作或填空白。保存独立 `scheduled_trace.json`，原事件轨迹不覆盖。
- `select_reviewed_scene` 支持重新选用因旧排时规则被否决、但内容经过实际复核的真实模型候选。必须绑定同一段输入与候选哈希，保留旧选择，不可手改台词冒充模型修订。
- 新增 `--stage direction --workflow <目录> --feedback-file <绑定最终对白的导演审核JSON>`。仅模型修订审核指定的意图、触发、表演或构图字段，不能改变对白、动作与道具状态。后续对白变动会使旧导演提示失效；局部修订保留其他提示。
- 最后核对导演提示是否引用未实际说出的对白，逐段核对人物立场、动作先后、承诺与兑现、情绪及核心表达，再执行 `accept`。规则检查不替代这种实审。
