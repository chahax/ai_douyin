# 人工处理完成后继续后台流程（2026-10-18）

用户明确要求按“默认后台运行 → 异常前端显示 → 人工处理 → 点击完成继续”开发。本轮按[实施方案](ACCOUNT_MANUAL_HANDLING_CONTINUATION_PLAN_20261018.md)由三个子agent分别完成后台、前端和处理目标，主agent审查实际派发门并做组合及独立流程验证。

## 实际行为

- 默认后台按已保存设置运行，正常任务不要求聊天确认；原账号暂停、互斥、额度及未决原运行门继续生效。
- 所有已登录页面顶部的异常卡有“前往处理此账号”“处理完成，继续运行”“仅关闭此提示”。前往处理会选中异常所属账号，再进入账号页面，避免在其他账号的浏览器中处理。
- 原账号登录页与自动更新日志统一“处理完成，继续运行”。点击后仅登记一次持久恢复请求，显示等待/正在核验并禁重复；查看者只读，片段刷新再次鉴权，不靠刷新触发平台操作。
- 后台持久记录操作者、请求ID、控制版本、原失败任务与策略快照。原身份核验通过后，符合条件且已明确结束的失败/受阻运营计划进入下次扫描；旧失败ID、回执和消耗保持，新运行仍走原配额、策略和互斥。已完成任务及正常未来周期不强制重跑。
- 未知、未结束的任务或核验、其他身份、后续暂停及相关设置变更均阻止旧完成请求越过。即使旧任务误标failed/completed，结构码明确outcome_unknown/recovery_outcome_unknown也不能作为已知失败重派。
- “仅关闭提示”继续只处理当前异常，不恢复账号、不确认登录有效；新异常重新展示。关闭后的账号仍可在账号页点击完成。

## 原环境处理入口

独立helper只接受同账号当前暂停、原调度运行与完整维护回执匹配的上下文。按已记录的数字视频ID生成官方视频页，或用原回执首个调研关键词打开相关搜索页；不声称后者就是精确失败查询。后台同步则使用固定创作者管理页，无可靠上下文返回原账号主页。忽略回执任意URL及路径，不跳到其他账号或外站。

打开窗口不再覆盖已有human_required原因。已绑定账号关闭人工窗口后保存会话，等待用户点击完成并交给后台核验，不再在前台要求重新确认绑定。未绑定新账号保持原完整绑定流程。
