# 热门选题与运营反馈闭环

## 1. 目标

在 `ai_douyin` 内形成一条不依赖 Anything Analyzer 的原生运营链路：

```text
授权页面热门样本采集
  -> 去重与话题聚类
  -> 样本/趋势评分
  -> TrendBrief 选题卡
  -> 人工批准
  -> 原创脚本与视频生产
  -> 发布与作品同步
  -> 多时点指标快照
  -> 表现归因与下一期策略
```

第一版只采集页面明确展示的数据，不下载第三方视频，不调用或重放网页内部接口，
不绕过登录、验证码、频率限制或权限控制。Anything Analyzer 的实现仅作为交互和解析参考，
不成为生产运行依赖。

## 2. 产品原则

1. **一次快照不是趋势。** 单次采集只输出 `sample_score`；至少两个不同时间的观察值才计算 `trend_score`。
2. **热点不是事实来源。** 热门样本用于发现用户关注点；法律事实、法规时效和个案信息必须另行核验。
3. **生成使用话题摘要。** LLM 接收话题簇摘要和短证据，不直接复制单条视频完整文案。
4. **发布必须可追溯。** 每个成片保留 `brief_id`、`cluster_id`、脚本版本、工作流方案和发布时间。
5. **复盘使用相对表现。** 不比较不同生命周期视频的累计绝对值，优先比较相同观察窗口和账号基线。
6. **默认人工触发。** 网页采集和 TrendBrief 批准默认由编辑人工操作；遇登录或安全验证立即停止。

## 3. 采集范围

原生 `DouyinWebTrendProvider` 负责：

- 输入最多 10 个关键词；
- 切换综合排序、最多点赞、最新发布；
- 每个排序最多保留 20 条页面可见记录；
- 记录视频 ID、URL、标题、作者、排序、排名、展示指标、查询词和采集时间；
- 通过同一 `AccountRuntimeContext` 使用与运营账号唯一绑定的浏览器环境；
- 通过 `SourcePolicyGate` 校验授权范围后才启动浏览器。

第一版不负责：

- 下载第三方 MP4；
- 批量 ASR 或人脸识别；
- 评论用户、粉丝关系和私信采集；
- 代理池、Cookie 池、指纹伪装、验证码识别；
- 将网页样本描述为抖音官方全量热榜。

## 4. 分析流程

### 4.1 去重

同一视频在多个关键词或排序中出现时，保留一个内容实体和多个观察记录。
跨排序、跨关键词重复出现本身是一项热度信号。

### 4.2 话题聚类

第一版使用可解释的规则聚类：

- 提取标题中的话题标签；
- 使用中文字符 bigram 和英文/数字词元计算 Jaccard 相似度；
- 查询词相同且标题相似的样本归入同一簇；
- 保留样本标题和来源，允许编辑人工调整。

后续可替换为 embedding 聚类，但不得改变上层 `TrendAnalysisService` 合约。

### 4.3 评分

单个样本分由以下信号构成：

```text
sample_score =
  35% 排名
  + 25% 页面展示指标（对数归一）
  + 20% 跨排序覆盖
  + 10% 跨关键词覆盖
  + 10% 样本新鲜度/数据质量
```

重复采集后增加趋势信号：

```text
trend_score =
  60% 展示指标增长速度
  + 40% 排名上升速度
```

最终选题分：

```text
selection_score =
  40% 样本/趋势分
  + 25% 账号定位匹配
  + 15% 用户需求强度
  + 10% 原创空间
  + 10% 制作可行性
  - 合规风险扣分
```

所有分数必须展示组成，不允许只输出不可解释的总分。

## 5. TrendBrief

每个候选选题至少包含：

- `brief_id`、`cluster_id` 和生成时间；
- 话题标题、查询词、样本量和覆盖范围；
- 样本分或趋势分及其证据；
- 代表样本摘要；
- 用户可能关心的问题；
- 普法解释、生活场景、行动清单三类原创角度；
- 推荐开头和脚本结构；
- 未核验事实、敏感表达和法规时效风险；
- `draft / approved / rejected / used` 状态。

只有 `approved` 的选题卡可以带入视频生产页面。

## 6. 发布效果快照

发布视频在 1 小时、6 小时、24 小时、72 小时和 7 天保存快照：

- 播放、点赞、评论、分享、收藏；
- 快照时间和视频发布时间；
- `brief_id`、话题簇、开头类型、内容形式、工作流方案和脚本版本。

第一版先在每次 `douyin-sync` 时自动落一条快照。调度器后续按上述窗口触发同步。

## 7. 复盘与下一期策略

单条视频至少有两个快照后计算：

```text
view_velocity = 播放增量 / 小时
engagement_per_1k = (点赞 + 2*评论 + 3*分享 + 2*收藏) / 播放 * 1000
relative_performance = 当前观察窗播放 / 同观察窗账号中位数
```

按以下维度聚合：

- 话题簇；
- 开头类型；
- 视频形式；
- 工作流方案；
- 发布时间段；
- 视频时长区间。

下一批选题采用 `70 / 20 / 10`：

- 70% 已验证表现好的题材和表达；
- 20% 相邻题材；
- 10% 新实验。

少于 3 个有效样本时只给出“观察中”，不做确定性结论。

## 8. 数据模型

趋势域使用独立 SQLite 文件 `data/trend_intelligence.db`：

- `trend_collection_runs`
- `trend_items`
- `trend_observations`
- `trend_clusters`
- `trend_briefs`
- `published_content_context`
- `video_metric_snapshots`

独立数据库避免破坏已有 `douyin.db`，跨域关联使用稳定的 `local_id`、`video_id`、
`brief_id` 和 `cluster_id`，不建立跨库外键。

## 9. MVP 验收

- 无授权确认时不会启动网页采集；
- 原生 Provider 不依赖 Anything Analyzer；
- 多排序重复视频只形成一个内容实体；
- 单次观察不产生伪趋势；
- TrendBrief 显示样本范围、代表样本和风险；
- 批准的 TrendBrief 可带入视频制作表单；
- `douyin-sync` 自动保存自身视频指标快照；
- 至少两个快照可生成增速和互动率；
- 少量数据不会被解释为稳定策略；
- 核心分析、存储、Provider 和网页页面有自动化测试。
