# 功能展示与交互流程改版验收

## 本次目标

技能先展示中文名称与用途，设置集中展示；工作流突出节点和流向；模型用点线关系呈现，点击节点和连线后展示详细介绍。检查其他功能，按适合的展示方式更新，最后自评与测试。

## 交互与数据约束

- 交互图是本地静态组件，不引入第三方脚本或图形服务。所有动态文本以 textContent 渲染。
- 节点与边均支持鼠标、Enter、空格，保留键盘焦点；连线有扩大后的点击范围。
- 组件返回值只能是图内已存在的节点或边。点击不执行能力、不保存方案、不调用模型。
- 工作流注册表不是可执行依赖图。图展示职责衔接，并在边详情中展示真实输入输出契约；不声称接口已直接接通。
- 停用阶段保留停用标签、虚线和停用说明。缺少审核结论不会被显示为通过。
- 模型配置不显示在线状态；模型请求图包含缓存和限流记录，不将记录数冒充实际外部请求数。
- 技能设置为原注册规则的只读展示；原权限、确认与重试策略未调整。
- 角色菜单继续过滤：技能中心从编辑角色可见；工作流编排从管理员可见；模型与系统设置仅超级管理员可见。
- 桌面显示画布与详细说明；390px 小屏可横向滚动图内内容，详情自动换行。技能小屏先显示当前能力简介。

## 自评

主观评分 **8.5 / 10**。用途说明优先、参数分层和点线详情比原先的表格堆叠更直观，图与项目真实的选题、制作、审核、运营环节相对应。

自评中发现并修正：连线文字附近难以点击；较长模型名挤出节点；技能筛选区域过高；移动端技能介绍排在目录之后。复杂图在手机上仍需滚动，这是当前空间与可读性的取舍。图形负责解释关系，实际执行和审核仍使用原来的业务入口。

## 验证范围

- 自动化：中文目录覆盖、筛选和空结果、未知调用结果分类、节点状态与真实注册表一致、连线返回值校验、真实文本模型选择、服务地址去敏感信息、请求缓存和限流区分、制作页面全部阶段切换、模型设置只读、不同角色菜单、已有工作流/选题/审核/登录回归。
- 额外渲染检查：模型用量、批量清单、任务调度页面可正常生成，未点击业务执行按钮。
- 浏览器：实际点击模型节点；点击采集→媒体连线；Enter 选择停用背景节点；切换技能卡片并查看配音设置；制作审核节点返回 Python 并切换下方标题；390px 画布横向滚动、审核详情与技能简介布局。
- 浏览器交互使用隔离的合成数据预览，避免更改账号或触发任务；真实制作产物的页面渲染和阶段切换由 AppTest 覆盖。未声称完成真实登录后的所有业务端到端操作。
