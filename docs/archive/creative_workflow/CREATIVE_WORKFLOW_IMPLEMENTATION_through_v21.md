## 已接通的入口

- 新命令行：`scripts/run_creative_workflow.py`，显式 `--source-driver novel` 或 `reference_video`。原有小说分析命令和旧 `reference_video` 参数没有改义。新 CLI 以来源正文、原视频哈希、表达参考正文和创作焦点计算逻辑任务 ID，并原子绑定唯一输出目录；同一创作意图不能靠换目录、改标题或复制材料重置调用及返修预算。独立新故事须明确改变创作焦点；旧试跑不追补目录锁。
- 管理页面“创作空间 → 双角色剧本”：选择故事来源、原文/原视频分析、可选表达参考与对照焦点；后台任务使用同一新版命令。运行状态和产物在页面读回。
- 页面显示阶段性助手复核的实际进度与停止条件。配置清单只含 MiniMax 编剧和 DeepSeek 导演，不存在第三审核模型角色、Token 或预留接入位；三类连续首稿校准已于 2026-09-25 达标并自动退出逐稿复核，重大回归或指纹、输入形式、画风类别变化时临时恢复，问题关闭后再次退出。
- 配置：`config/creative_agent_models.json` 与 `.env` 的角色专用项；编剧 MiniMax-M3，导演 DeepSeek 的 `deepseek-flash`。Token 仅由本机设置加载，不写入运行产物。
- 小说材料要求已获取正文，记录文件哈希、章节标记和未知后续范围。原视频驱动要求视频和对应分析，分析须写出视频文件名或 SHA256；仅文件名匹配会如实标为弱绑定。

## 文本链路与失败规则

完整可容纳时同份材料整体送给编剧、导演；超过配置阈值时分块、保存每块哈希与摘要，不能静默截断。阶段为编剧全局候选 → 导演画风与空间前期意见 → 编剧可读剧本 → 导演先核对剧本可拍性再拆镜 → 编剧意图核对 → 媒体交接待适配。导演分镜这一现有调用若发现必须回上游修的主要故事问题，只能先提交带证据的 `story_issues`，程序扣同一个返修轮次，编剧修稿后再调用导演；正常稿仍在原调用直接返回分镜，不增加常规审核模型或调用。两轮用尽仍有问题就导出未通过工作稿，不能交接媒体。新任务采用 `config/creative_workflow_budget_v4.json`：编剧与导演共用最多两轮实质返修，JSON 格式和字段契约修复另共用最多八次；所有调用仍共用 20 次请求和 50 万报告 token 的总上限。v1—v3 旧任务恢复时必须显式指定原预算版本与额度，不能靠换版本重置已有任务预算。v4 是根据真实试跑中技术修复先于实质返修耗尽的证据发布，只对新任务生效。实际请求、原始响应、角色、模型、父稿哈希、用量和错误分别留档。已收到但未校验的响应可本地恢复解析；未确认调用不能当成功。一次 JSON 语法修复或契约修复都单独记账。无 request ID 的连接失败或已留档的空正文修复响应，均只允许同一预算下一次有界重试，保留前一次记录。

导演拆镜前的 `story_issues` 分流已用假模型完整串联验证，并在后续真实 DeepSeek/MiniMax 试跑中实际触发：问题单只能指向编剧并包含证据、影响、建议和主要/阻断级别；不得与镜头结果混交。编剧返修、导演复审和后续编剧回核共用调用预留及同一两轮实质返修上限。预算不足、两轮后仍有问题时不产生媒体交接。正常分镜路径调用数不变。真实触发只证明路由工作，不能据此宣称质量改善。

编剧创作调用先锁定情绪节拍、原文对白和时长，再由程序把 `before/during/after` 动作与锁定对白编排为可读剧本。早期的独立动作稿调用先后出现额外对白、错误占位、动作段数量不符与返修附加字段，故不再让模型重复改写同一故事；失败原始记录保留。程序编排不能自动证明戏剧质量，仍须核对情绪窗口和候选结尾有没有真正兑现。小说选段附逐字引文及邻近上下文清单；原著版式换行不算改词，繁简字变化仍会拦截。小幅总时长算术错误可按节拍合计更正，但保留原填值和警告，不能计为首稿无异常。JSON 语法修复还会比较修复前后内容流与字段顺序，改变正文即拒绝。

MiniMax-M3 官方验证仓库标注 `response_format=json_object` 暂不支持，但工具调用有结构用例；本地小探针和真实试跑确认工具参数可以返回合法 JSON。编剧分析和节拍稿现用强制工具调用提交，再由程序独立校验。实跑也证实工具调用并不保证遵守所给 schema：试跑 11 只返回 `summary`，并把其余字段混入摘要文字，仍被程序拦截。工具调用不是质量通过凭据。参见 [MiniMax 官方 M3 格式用例](https://github.com/MiniMax-AI/MiniMax-Provider-Verifier/blob/main/m3_format_check/docs/m3_text_cases.md)。

程序校验候选起止引文、已获取原文对白、画风选择、节拍时长、镜头顺序、逐镜事件与对白锁，以及原始尾帧续段状态。它们不能判断表演或构图的主观质量；前期由助手对完整首稿进行人物归属、动机和情绪高光的实际复核，`scripts/record_creative_review.py` 将证据绑定到当前产物版本。登记主要问题后，任务主状态改为 `needs_revision` 并绑定复核文件哈希；恢复原命令只读回此状态，不能用模型先前的空问题单重新放行。当前七份绑定首稿复核均按原始证据同步了主状态，没有改动原稿、媒体交接包或调用计数。只有校园小说、另一题材小说与视频原创三个独立任务连续首稿均无主要异常，才停止逐稿额外助手复核。达标里程碑由三份有效绑定记录持续证明，之后不再因例行任务没有额外复核而失效；后续若登记主要问题，则恢复针对性复核。新任务创建时保存当时的校准依据及是否需要助手复核，交接包按该决策如实标注。视频通过数独立且不会被文本事件增加。MiniMax 编剧现于原有交叉回核阶段收到锁定候选的 aftermath，并被要求逐项核对最后节拍与收束镜中的可见兑现；这没有增设第三审核模型或额外模型调用，也不能替代前期助手实审。

媒体交接包始终写 `automatic_submit: false`。已对当前选定的火山方舟 Seedance 2.0 Mini 做只读本地参数探针：客户端能够构造 4–15 秒文本与首帧请求、要求返回尾帧；无远程任务提交，不能证明实际切镜、换场、表演或声画效果。初始证据见 `data/creative_workflows/capability_checks/selected_executor_20260922.json`，加入分段适配器后的当前快照为 `selected_executor_20260923.json`。成功文本任务除 `MEDIA_CAPABILITY_AUDIT.json` 外，现在另存 `SEEDANCE_SEGMENT_PLAN.json`：逐镜生成绑定版本的 Seedance 请求模板，首镜要求已审开场帧，连续镜要求前段画面通过后的原始尾帧，新机位要求独立已审首帧与离线切镜装配；超出模型单段时长的镜头不猜测动作拆分，明确阻断。模板仍全部 `submission_ready:false`、`automatic_submit:false`。真实首帧绑定、切镜装配和实际媒体能力仍未完成，不能从新版文本流程自动启动付费视频生成。真实视频仍须按 `docs/SCRIPT_VIDEO_RUN.md` 逐段抽帧、听看和整片复核。

文本通过时还输出 `EXECUTION_DRAFT.json`，逐镜绑定有效剧本的事件、对白、构图、表演、首尾状态和提示词；`generation_segments` 保持空列表，待实际执行器能力核验后才做片段映射。`EDITORIAL_REVIEW_PACKET.json/.md` 汇集人物来源、选段理由、刺激—前中后反应及对应镜头，明确显示“待助手实际复核”。两份文件均受交接包哈希约束，篡改或换父稿不能沿用旧复核。
