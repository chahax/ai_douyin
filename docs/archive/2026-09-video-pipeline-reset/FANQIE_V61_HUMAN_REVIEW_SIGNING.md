# 番茄 V6.1 人工审核操作说明

> 历史文件名保留用于兼容旧链接。当前流程已经取消 Ed25519 密钥、`allowed_signers`、审核人就绪证明和 `.sig` 文件。

## 当前审核方式

候选视频生成后，审核草稿保存在 `data/qa/`，状态为 `pending_review`，管理后台会把它显示为“待审核”。空模板或缺少真实视频/哈希的记录不会进入待审核队列。

启动后台：

```powershell
D:\IT\ai_douyin\.venv\Scripts\python.exe D:\IT\ai_douyin\scripts\run_streamlit_web.py
```

登录后进入侧边栏 **视频审核**：

1. 查看联系表。
2. 点击“开始完整播放计时”，从头到尾播放候选视频；7 镜头样片逐个播放，整片完整播放。
3. 播放时长满足要求后记录完成，并逐项勾选页面列出的镜头/整片审核项。
4. 填写审核备注。
5. 点击“通过”或“驳回”；驳回必须填写原因。

审核页面将当前登录用户名、决定、备注、播放时间、逐项确认和候选/机器包哈希写回审核 JSON，并在显式闭环数据库写入唯一操作事件。数据库事件失败时不能形成有效批准。无需生成、保管或输入任何人工审核密钥。

前端审核发生时通常还没有选定最终番茄推广任务，因此 `review_approved` 决定事件的 `task_id` 有意保持为 `NULL`，但事件仍严格绑定审核文件、候选视频、机器包、审核人和全部哈希。后续登记到匹配的推广任务时，P0 服务要求这条唯一事件存在，再在同一事务中创建脚本、视频任务和审核记录，并写入带目标 `task_id` 的登记事件。不要只按 `task_id` 查询前端决定事件。

前端与 P0 登记必须使用同一个权威数据库绝对路径：

```text
FANQIE_CLOSED_LOOP_DB_PATH=D:\IT\ai_douyin\data\fanqie_closed_loop_p0.db
register_fanqie_story_v61_candidate.py --db D:\IT\ai_douyin\data\fanqie_closed_loop_p0.db ...
```

部署或执行登记前必须核对两个绝对路径完全相同；不得使用主工作区或 P0 worktree 中的 `data\wisdom_ai.db`。路径分裂时登记会因找不到前端事件而失败关闭，不会形成误批准，但会造成流程不可用。

## 状态流转

```text
pending_review
        ↓ 前端展示
pending_review
   ├─ 通过 → approved → 允许进入下一段本地生成流程
   └─ 驳回 → rejected → 按备注重新生成新候选
```

7 镜头样片通过后，只开放 19 镜头本地生成；整片通过后，也不会自动上传抖音或回填番茄。发布和回填仍需各自的平台任务门禁。

## 仍然保留的校验

简化的是“审核人身份签名”，不是产物质量检查。执行链继续校验：

- 计划文件和源代码契约；
- 精确镜头边界和镜头顺序；
- 视频、音频、字幕和联系表 SHA-256；
- 时长、帧率、音轨和口型阶段证据；
- 7 镜头复用到 19 镜头时的路径与哈希一致性；
- 19 镜头成功后自动独占写入的渲染审计回执，绑定最终进度、计划、镜头数和渲染者标识；
- 抖音发布和番茄回填默认关闭。

渲染审计回执是程序生成的不可变哈希凭据，不是人工审核签名，也不需要用户持有私钥。最终抖音上传边界仍可使用独立、短时效的发布授权；该授权不参与视频内容审核。
