# 单段声音流程真实执行

## 新增入口

`audio_quality_execution_v1.py`及公开CLI `scripts/run_audio_quality_execution_v1.py`补齐了原规划入口后的执行接线。输入为分段候选、原剧本、资产绑定、既有整轨检测、问题确认、已验证处理能力及一次试验授权，不写死S03或异常秒数。

调用顺序为prepare、execute、status：

1. 重验原媒体已有的完整ASR输入和台词证据，自动选择处理方式。
2. 用父授权生成独立执行grant，原规划请求的execute_allowed=false保持不变。
3. 调用CPU处理器并核对视频帧、PTS、时长及波形保护区。
4. 给派生文件分配新的local-edit身份、结果和时钟记录，不冒充H3新生成。
5. `local_audio_inspector_v1.py`只执行一次本地CPU整轨识别，保存新媒体自己的WAV、原始ASR及进程回执。
6. 对新媒体重新做整轨证据、台词和路由检查，不继承旧问题确认，不使用旧ASR给新音轨放行。
7. status只读重验缓存；同父授权和同媒体双重一次性记录防止重复调用。未知结果保留，不盲目重派。

当前执行桥限audio_only_test和cleanup_gap，后台全量生产路线未迁移。音频重生成、降噪和音画重生成不会被伪装成已接通的后端。
