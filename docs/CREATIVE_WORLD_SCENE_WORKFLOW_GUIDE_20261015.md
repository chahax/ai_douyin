# 通用剧本的世界、场次与表演合同

本会话负责通用流程代码与离线验证；当前样片的实际重写、视频提交由另一会话“你可以生成视频吗”推进。适用任意主题、人物数和场景，不固定超市、角色姓名、时长或分段数。

## 输出顺序

1. **世界框架**：先介绍时代与现实基调、社会环境、开场前史、人物关系及空间衔接。角色档案、目标、场景和道具仍引用原规划中的稳定ID，不再维护另一套互相矛盾的设定。世界框架是剧本前置说明，不自动变成旁白、字幕或必须让角色说出的台词。
2. **逐场情境**：标明故事时间及与前场的连续/跳时关系、地点、环境变化、参与人物和前场引用。同一地点可以出现多个不同情境。正文每拍都有可查的情境绑定，阅读版逐拍显示紧凑时空与在场人物信息。
3. **全体人物的表演**：每个参与者都明确动作来源和当前神情；不说话的听者也覆盖。保持原动作、安静聆听均允许，不为凑字段增加揭纸、压角、转笔、系围裙等无叙事作用的操作。实际动作仍以原生steps为唯一正文来源，神情引用对应动作，避免抄写两套不同动作。
4. **对白与动作并行**：可声明某动作与对白适合并行。正文顺序用于定位文字，不直接等于动作完成时间；并行安排不证明某个动作已经完成。导演/局部表演阶段再安排具体秒数、情绪重心和反应窗口，不能因固定开场空等或收尾空等把一次交流拆碎。
5. **交接给下游**：发送共享世界、角色/场景/道具档案、当前情境与表演、前一拍剧本背景、下一锁定剧情及合格当前状态。前一拍“写过”的事件不能冒充已验证完成；当前状态必须来自同源有效setup、已接受表演终态或符合人工批准要求的服务原始尾帧。

## 生成与审查

世界框架放在同一次完整规划输出中，不增加单独的世界生成阶段。保持MiniMax创作、DeepSeek少量必要审查。原规划四审与同源全文语义/物理两部分仍各负原职责，新字段进入这批请求，不另叠加世界审查模型。

G/C目录定位完整规划及claim原文；E定位正文实际步骤；H定位场次时间与环境说明；P定位人物神情。背景说明不是已经演出的事件证据，神情也不能证明纸已交出、已签字或法律条件已经成立。只有精确外键字段可按元数据处理，相同字符串出现在设定正文中仍需审查。

涉及动作前提和严格先后的检查需要有原文依据的完成先后关系，不能仅看E编号较小就认定发生在前。顺序缺失、相互矛盾或状态不足必须暴露，不靠编译器发明取放或过渡。

## 返修及版本

内容返修由创作模型提交完整新稿，再按同一新稿全文审查；编译和渲染不手填世界、神情、入场或动作。已确认要求与原始状态不能为迁就正文而被审查建议改写。世界/规划改变后，相关审查与下游绑定须重建；正文改变后，原全文审查和导演/表演缓存不能继续冒用。合格静态素材可按原资格复用，旧账本、回执和媒体保留。

旧627/634等正文不含新合同字段，应明确拒收，不能由显示层补齐后算新版本通过。离线样例、请求预览和Mock闭环只证明代码接线；实际接口、有效完整文本、创作质量与用户视频批准分别记录。新视频仍为awaiting_human_review，助手不主动抽帧、听看或ASR。
