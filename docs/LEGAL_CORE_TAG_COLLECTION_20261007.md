# 法律核心标签的获取与分析

用户已确认法律为核心定位：一个核心标签可以带多个相关标签。本轮完善了现有采集器和分析入口，并做了真实元数据测试。108项离线回归及2项新增回执验证通过；真实测试在登录/安全验证处停止，新增有效视频为0。当前热点、创作质量和运营收益均未验证。

## 固定定位与标签分工

法律服务是账号的固定领域，本轮核心检索词为“法律”。后续可在法律领域内以“劳动争议”等具体议题作为一轮采集核心；相关标签必须有来源证据，不能向任意全站热词扩散。

1. **核心标签**限定本轮问题范围。广义“法律”可用于探索；具体“劳动争议”需要标题/原话题中的本议题或检索词族证据。
2. **相关议题标签**提供多个法律问题入口，例如拖欠工资、加班费、离职补偿。保留实际视频ID、原话题、可见作者名及关联依据。
3. **账号/地域宣传标签**作为账号线索保留，不自动成为故事议题。实际旧样本中的“南京劳动法律师”说明：法律相关不等于适合选题。
4. **发布标签**在完整作品形成后按实际正文整理；采集词、原话题和推断主题仍分别记录。

实际链路为：法律定位 → 核心词及有证据的相关词 → 全新同批采集 → 去重与明确指标 → 法律相关度及议题筛选 → 时效/样本核对 → 完整创作简报 → 原有编剧、导演、表演和编译。

本轮接通的是元数据采集与计划验证。通用创作桥接仍处于离线准备状态，页面按钮和模型派发没有切换；没有自动生成剧本或发布作品。

## 新核心计划的最小合同

新增[核心计划模块](../src/trend_intelligence/collection/legal_core.py)与[离线准备入口](../scripts/prepare_legal_core_collection.py)。每个计划保存完整账号策略、原观察、边界、源批次、来源摘要和派生请求。执行前按真实账号重新计算并验证；改账号、策略、关键词或支持记录会拒绝该计划。

- 只消费一个有身份的源批次，不混旧批次凑当前样本。缺ID、混批次、未来采集时间和冲突身份停止准备。
- 核心相关性来自可见标题及原话题。检索输入本身不能制造法律相关度。
- 默认选择最多4个相关议题，至多6个；根据支持覆盖、作者名多样性、共现和可用排序计算**关系分**。它不是热度分或法律结论。
- 多样性选择参考MMR思想，用支持视频集合的Jaccard相似度惩罚重复证据；没有使用KeyBERT向量或运行语义模型。
- 核心词与关联词作为同一新批次的独立查询，分别搜综合/最多点赞/最新，默认每页至多20个可见结果。关闭该计划内的递归关联扩展，防止超出计划。
- 默认单次最多30页；本次5个关键词×3个排序=15页。达到页面上限时拒绝准备，不静默拆成多个批次。保留既有每日90页、最小1秒间隔及来源策略约束。
- 旧关联可以提供新检索种子，即使旧样本过期也可准备搜索；旧数据不能证明今天热门。每份计划均标记需要全新同批采集与分析。
- 既有创作样本门槛保持：同一run_id至少20个去重video_id、至少2个主标签，已确认点赞总量或已确认播放总量分别至少100万。两类指标不能相加，未知指标不计入。
- 本入口只执行metadata_heuristic，不允许混入旧批次、额外关键词、递归扩展、原片下载、本地音画分析或旧A/B编剧；没有自动重试、模型或媒体调用。

检索词族是工程启发式，不是权威法律分类。生僻同义词可能漏选；含法律词也可能误选。作者名只能说明可见名字多样，不能保证真实账号不同。广义核心下的共现不证明因果，单次排序不证明增长或全站热度。
