# 难点排查与验收

## 1. 请求太大与输出截断分开处理

- 请求超容量：核查完整原文、结构产物、证据字段值、渲染稿是否重复。可以把证据改为稳定编号及可逆地址，完整值保留一份。压缩后验证所有地址能还原同一值、空值和候选 SHA，没有静默丢内容。
- finish_reason=length：这是已知截断，不能把部分 JSON 当成功。查输入、输出及思考用量，判断是不是整稿调度/返修过长。不要把输入压缩当成已解决输出截断。
- 没有可靠原生终态或用量：保持未知，不自动重放。

## 2. 逐场调度的实现目标

先固定基础设定、剧情、场次 ID、对白 ID、地点和时长，再逐场或按有界小批次生成调度。每次包含全局身份/地点规则、当前场、前场结束状态、后场所需承接信息及必要原文。前序场修改后按依赖关系重新检查下游，不把旧状态继续当事实。

每场输出只保留必要动作、神情、镜头、音轨区间与状态。用 Schema 同步限制集合大小和文本长度，避免剧情/表演/动作三处重述同一内容。限制应来自成片需求与模型容量，不能机械删掉关键动作。

场次顺序、覆盖及对白保持由程序核对；语义改动必须回到相应责任阶段。断点只能复用输入、版本、候选 SHA 一致且已确认成功的场次。不能把未实现的场级断点功能写成现有能力。

## 3. 跨场连续性

人物：稳定身份 ID、所在地点、是否在画面/画外、进出动作。背景中看得见的人也必须登记；画外声不代表人物在屋里。

道具：持有人、位置、状态及变更动作。区分“保持”和“变化”。例如：腰间→右手→口袋→柜锁；开柜后去向未交代就是待确认，不自动补回口袋。承接必须核查父状态，不能只检查前后字符串不相同。

知情：谁在什么动作后获知什么、信息来源是什么。计划、回忆、说话行为与话中事件分开。模型美术补足不能改写原文事实，未知不能当否定。

空间：结构化地点 ID 与站位/摄影文字一致。若允许跨地点镜头，应显式表示镜头及转换，不能厨房场里悄悄出现院外画面。检查相邻场的入场来源与出口。

## 4. 审核意见有效性

每条硬伤需要：候选 SHA、具体字段/证据 ID、明确断言、冲突的原文或合同、真实责任阶段和必要修改。

将合理差异、偏好与硬伤区分：

- 继母被孩子称为“妈”，单凭继母身份不能判错；若原文明确禁止该称呼才有直接冲突证据。
- 音轨前半句早于开柜，不证明后半句也早于看见信。涉及知情时序时，需要关键短语或发言节点的时间，不能只凭整句 start 判错。
- 台词与动作可以合理并行；“给你”可以在递出动作之前开始。不能要求所有对白与动作起点完全重合。
- 院外明确写成院中、原文傍晚写成下午、没有动作却改变持物，是可以核查的矛盾。
- 空字段只说明未填写，不能推导“明确不存在”。

代码核对地址、SHA、必要字段和结论一致性；语义依据不足时另做核验或保留未决，不把错误审核意见直接变成创作指令。若实现裁决步骤，须有原问题绑定和有界次数，不能无限裁决到通过。

## 5. 有效验收样例

至少覆盖本次修复涉及的实际机制，而非固定凑测试数量：

- 多场产物完整且按顺序合并；缺场、重复场、错候选 SHA 拒绝。
- 修改某场后只失效有依赖的后场，未受影响对白不漂移。
- 道具留在锁中却无动作回口袋被检出；明确取回后的承接通过。
- 合理的“继母叫妈”、动作对白并行可以通过；明确身份冲突、提前获知应被检出。
- 失败原生响应保留；length 不采纳部分产物，unknown 不重复派发。
- Schema 时长上限与程序一致，完整时长与每场动作/对白均可执行。
- 真实新小样完成生成和审核，主助手复核通过，才能称该小样内容验收通过；不能外推到长篇或视频。
