# 第一轮独立内容审核

审阅范围：完整 SCREENPLAY.json、static_visual_manifest.json 原响应、director_state_plan__00.json 原响应及两次 contract_repair 原响应。此次未产生 DeepSeek 审核，不能归因于 DeepSeek 漏报。没有图片/视频审核，没有媒体通过。

结论：本轮不通过。有真实动作/因果问题，同时过细的自由文本状态契约让修复耗在形式错误上。最后响应不仅 JSON 损坏，还主动改坏 B2 因果。单独强制 JSON 不会解决内容问题。

## 真实内容问题

1. 陈禾的初始 posture 为 sitting，位置为 E02 椅上，全片没有起身，B4 却要求“坐下接手工作”。原响应 sitting→sitting 被无变化规则拦截，首次修复仅删掉该变化，没有解决人一直坐着却再次坐下。需要从全片后续动作反推初态站立，而不是加无叙事作用的起立。
2. 文件夹初始 location 在桌面，holder 却为 C02；B1 拿起仍写 C02→C02，B3 放桌仅改 location，不清持有人。混淆资产 owner_id（永久所有权）和 holder（当前实际持有者）。首态桌面应无持有人，拿取、放回必须改变实际持有状态。
3. B2 changes.affect 写“目光从P01移回C02陈禾面部”，但 gaze 仍指文件夹；B3 又安排从文件夹抬眼。自由文本表情字段藏入视线变化，typed 状态无法覆盖。应在 B2 保持看文件夹，B3 才抬眼，对照已审剧本。
4. 原响应 B4 道白窗口 2–5 秒，转身走路 2–7 秒，陈禾坐下 4–9 秒。与剧本 before→对白→during→after 的顺序不同；这不是“固定机位禁止人走路”，而是动作发生顺序改变。可在10秒内安排先松肩点头、道别、走两步、陈禾坐下，无须增加镜内硬切。
5. 最后修复在 B2 写“C02陈禾口头接受的对白已结束”，把 B3 的接受搬到 B2。B2 锁定对白实际是林遥“今天不行，我赶时间。”这是新引入的明显因果错误，不能把格式修复当成只动格式。
6. B4 composition 说固定机位，camera 却“跟随C01…保持其在画面内”，应明确究竟固定且预留纵深，还是连续跟拍；不是硬切问题，但提示词执行选择仍不唯一。

## 上游与实现的负担

- 剧本 B1“脚步放缓”、B2“停下脚步”可以是减速→停稳，不必视为上游矛盾。导演擅自把 B1 写成“停在桌前”后，B2再次停步才产生重复。不能为此反复重写已审剧本。
- holder from==to 是冗余数据本身，但此例掩盖了所有权/实际持有权混淆。直接删除可减少格式负担，却不能证明物理状态正确。
- 禁止一切 event 重叠会把不同人物合法并行动作也作为结构问题。应允许互不冲突字段并行，或让程序明确编排，不能仅靠不断合并长句。当前 B4 的并行动作仍有原剧本顺序问题，要分别判断。
- 逐字复制自然语言 from 字符串容易制造无关格式失败；关键姿态、持物和位置采用稳定 ID/枚举更适合程序检查。自由文本 action 的情绪/动作合理性仍需审核。
- 原响应及首次修复 B3 留4秒沉默，接受对白给2秒。该台词9个汉字，4.5字/秒，低于项目5单位/秒上限，不能仅凭“可能太快”报必修；真实语速与表演留视频审核。
- B1 已背包的初态省略“背起包”的具体动作：可能是合理镜头省略，也可能改变要求，需要明确是否关键，不能机械要求每个剧本动词都成为新道具操作。此处不是本轮主要阻断。
