- cross_checks必须且只能含dialogue_action、voice_performance、spatial，值分别为passed或failed。三项分别判断对白动作关系、声音与实际对白和表演要求、座位/相机/构图/对视空间关系。任何一项失败均否决整稿，不因其他检查通过而抵消。未读完或不能确定时不能填passed。

result_audit必须对每版分别列出target=resolution及target=ending两项，共四项。resolution指该版resolution，ending指expression_plan.ending及closing_line承诺的结果。每项写decision、至少一处同版实际action原文依据及非空explanation，说明已完成事实究竟由哪个动作支持，以及元数据/台词是否夸大。需要的动作缺失或只写计划、首尾物件名称时应failed；仍引用最相关的实际action并说明缺的过程，不能伪造引文补齐。真正执行了停签等当前决定可以成立，不强迫全交易签完；突然让步或未执行却声称完成必须指出。
character_audit逐版覆盖每个已定义角色，每个script/character_name恰好一条，字段必须且只能为script、character_name、decision、spoken_shot_ids、performance_arc_quote、dialogue_quotes、voice_quote、performance_quotes、assessment。spoken_shot_ids按实际顺序列该角色全部非空对白镜号，dialogue_quotes是镜号到该镜完整dialogue原文的对象，不能漏镜或借用其他人的对白；完全不发声者分别填[]与{}。performance_arc_quote完整复制该角色performance_arc；voice_quote完整复制其首次发声镜audio，不发声者填空串。performance_quotes是该角色首、末入画镜号到该镜emotion_and_performance非空原文片段的对象（首末相同只写一次；始终不入画者填{}）。assessment用一句具体判断把角色设定与其全部实际对白、首末表演相对照，不能以逐字复制代替判断；decision只可passed或failed。

conflict_audit每版一条，字段必须且只能为script、decision、conflict_object、disputed_property、positions、turn、closure_scope、evidence。五项文字依次说明本场争议针对的具体对象、争的具体属性或事实、双方立场或实物演示中目标与阻碍、实际发生的选择改变、最终完成的是哪一范围的结果；不得把数量/金额/文本版本等不同争议偷换为同一问题。每项一句具体判断，不能只抄goal/obstacle。evidence对象固定有opening、dispute、turn、ending四个键，各为真实稿件引用数组，字段只可action或dialogue，必须来自同版对应story_beats：opening=setup，dispute=conflict或escalation，turn=turn，ending=resolution或closure。每组至少一处实际action；该组有非空对白时还须至少一处实际dialogue。没有完成动作时引用最相关的现有动作并指出缺失，不能编造。decision只可passed或failed。

完整审读后简洁记录：每镜三种note各一句，角色assessment与冲突五项文字各一句。仅协议要求的dialogue/audio/camera_angle和角色台词/设定引用使用全文；其他引用保留足以支持判断的连续原文，不复制整份首尾库存。全部镜头、四项结果、全部角色和两版冲突均须覆盖，不因精简漏审。action_evidence保持真实action原文；概括后的库存只能写在说明中，不能冒充quote。需要否决跨字段关系时，在issues.evidence引用真正互相冲突的至少两处原文。只输出一个标准JSON对象，不加Markdown围栏。
判断动作目的须结合后续：放下笔可以是暂停签字并提出另一核对办法，不自动等于本场所有交涉已经结束；提出电话核价被对方拒绝可以不实际拨号。停签成立不要求手机关屏、所有道具收纳、双方认可某个正确金额或完成整笔交易。角色已通过“没有这份记录/没见过报价”等对白回应，就不能声称展示后无人回应。对于位置，桌面“偏左”与“偏上”可同时成立；只有实际不相容的位置/持有/纸页改变且无动作依据才判矛盾，不能把不同坐标维度或范围包含关系机械地判为瞬移。

输出字段清单（只返回九个顶层键；每个数组展开到全部实际对象）：
- candidate_sha256、evidence_sha256：复制输入。
- shot_audit：每项 {script,shot_id,decision,action_evidence,continuity_note,voice_note,dialogue_action_note,cross_field_evidence,cross_checks}，严格按上文字段和原文要求。
- result_audit：每项 {script,target,decision,action_evidence,explanation}；两版各resolution、ending，共四项。
- character_audit：每项 {script,character_name,decision,spoken_shot_ids,performance_arc_quote,dialogue_quotes,voice_quote,performance_quotes,assessment}。
- conflict_audit：每项 {script,decision,conflict_object,disputed_property,positions,turn,closure_scope,evidence}；两版各一项。
- checks：本文15项名称全部出现，值为JSON布尔值。
- issues：问题对象数组；无实质问题才可为空。
- summary：基于实际证据的一句非空结论。
所有字段名都要使用双引号形成合法JSON；上述清单不是可直接返回的JSON模板。不要输出schema或passed顶层字段，这两项由程序校验完整协议后写入。

passed/true不是预设答案。发现实质问题要在对应audit中failed、相关check设false，并在issues中给出具体问题和可执行修订要求及真实引文，格式仍为{"script":"short或long或both","shot_id":"具体镜号或overall","problem":"明确问题","evidence":[{"script":"short","shot_id":"S01","field":"action","quote":"实际原文"}],"rewrite_instruction":"可执行修改"}。跨字段矛盾引用两处原文。15项checks全部true、所有audit和逐镜cross_checks全部passed且issues为空才可能通过；任意一项失败、漏审、未知判断、SHA不符或不实引文都会拒绝。不存在总分或其他优点抵消严重问题。不能改写剧本替代审核。


法律类专项否决项（优先于一般完整性判断）：
- 只检查观众能听到的 dialogue 是否包含关键适用条件。premise、resolution、legal_review_note 和纯动作里的条件不算已向观众交代。短版和长版必须分别检查；任何一版遗漏 editor_feedback 指出的必要边界，reasoning_coherent 必须 false。
- 限定情境下成立的判断，若收尾被说成无条件结论，同样不通过。不能因为 legal_review_note 写了边界就放行。
- 不能把截图、照片、聊天记录的证明作用说满，不得仅凭单一材料承诺可以证明整个事实，或笼统把全部举证责任分给某个人。存在这类表述时 evidence_honest 或 reasoning_coherent 必须 false。
- 单方手机电子档不当然真或假，也不当然是双方确认的版本；若仅因它与一份纸件相同就认定另一份错误或归责打印店，evidence_honest 或 reasoning_coherent 必须 false。手写涂改不一概无效，单方删改数字不代表双方已对既有合同变更形成清楚合意；混淆未签文本核对与既有合同变更，或从本场未签推断此前没有合同关系，同样应定位原文提出修订。
- source_evidence 提供原视频音画表达证据，原作者口述的法律判断本身不自动成为已核验规则。编辑意见中明确已核对的法律资料才可作为已核对的规则边界；引用的条号须与输入完全一致，不得在审稿摘要自行生成条号。无法确认的法律细节要求删除或修改，不得以“仅供参考、待专业审核”替代这次编辑修改。
- 有一个具体问题就应列入 issues。不得因为整稿总体可读而把全部检查设为 true。

输出前最后自检：JSON 字符串中的中文说明（包括所有note、assessment、summary）使用中文引号“”，不得直接嵌入未转义的 ASCII 双引号；引用原文若本身含 ASCII 双引号，必须按 JSON 规范用反斜杠转义，不得改动引文字词。每层对象字段名都不得重复，尤其不能覆盖先前failed/false判断。shot_audit 和四条 result_audit 的每个 action_evidence 均引用 field="action"，不能只引用 dialogue 或 closing_line 作为结局的动作依据。结果解释无需再次整段引用结局元数据，用一句话说明动作与结果是否一致即可。保留全部检查与真实判断，完整覆盖两版所有镜头、四项结果、全部角色及两版冲突；确认整个对象可以被标准 JSON 解析器直接读取。


戏剧强度专项审核（2026-09-11）：
在现有conflict_audit、逐镜审查与summary中报告开场、实际施压/抵抗/转折、收场的秒数。45秒冲突剧情预算为开场≤5秒、核心冲突段≥30秒、收场≤10秒；180秒对应20/117/36秒。以实际动作与对白核对，不把beat标签当证据。长停顿须指出具体镜号、动作和时间依据；未生成视频不能声称测得实际语速。
检查冲突点的情绪触发、语速、语气、台词原词重音、停顿和末尾余波是否可执行，且与voice、action、末态一致。只有“自然、平稳、克制”的重复模板不能证明情绪弧成立。结尾须完成选择且体现其情绪后果；两镜重复结论或没有原因地突然轻松和解，引用对应对白/表演原文，按现有冲突转折或节奏检查项失败并要求回到故事阶段，不新增JSON审核字段。自然平静本身不是否决理由，必须说明它如何与本稿仍存在的压力矛盾。
结构预算和七项字段完整都不等于表演合格，须审读真实内容。短促或低声也可有冲突，不以喊叫、反问数量、关键词数量评判。尊重已冻结事实、法律边界和连续性，不能以增加戏剧性为由跳过状态核对。


来源情绪与结尾选择（2026-09-11，优先于预设平静收场）：
事件完成与情绪平复是两回事。结尾可以仍然愤怒、委屈、不甘、讽刺、得意、释然或冷静；应由人物目标、刚发生的选择和真实参考表达决定。不能把“明确结局”机械解释为双方平静和解，也不能机械规定必须负面紧绷。不同角色可处于不同情绪。
读取各source的emotion_analysis：区分人物间对抗、讲解者情绪表达、角色扮演，以及音乐/剪辑诱导的情绪。比较开场、触发点、中段变化与末尾，关注原声相对语速、句式、语气、重音、停顿，结合已观察到的面部与动作；用原片时间窗口说明实际借鉴。参考情绪是可借鉴的表达方式，不是必须照搬的事件或法律结论。
status=not_analyzed/unavailable不能支持实际语气判断；ASR只能支持语言结构。model_observed_unverified属于本地模型观察，可能误认角色和情绪，不能冒充独立确认；需与已有视觉/ASR证据核对，矛盾则保留未知，不将其升格为法律事实或精确测量。sampled_begin_middle_end仅覆盖列出的windows，不能推断全片情绪峰值、冲突占比或中间转折；样本拼接点不是真实剪辑点。无情绪证据时表演只能标为本稿原创设计，不能声称来自原片。
比较同批高点赞与其他视频的情绪表达时，用实际metric_kind/value及样本覆盖说明，不把点赞当播放量，不生成“情绪贡献百分比”，不推断高点赞由某种情绪造成。不要仅挑最大点赞一条抄情绪；结合账号需求选择可迁移的表达，保留实物示范、直接讲解等不同形式。
在现有reference_usage的borrowed_expression/adaptation与角色performance_arc（该阶段有此字段时）说明采用哪一种情绪推进、借鉴什么、哪些为原创；不增加未定义JSON字段，不伪造evidence_ids。最后一句和最后动作应完成本场结果并体现所选情绪，不能连续两镜重复结论来凑收场。
